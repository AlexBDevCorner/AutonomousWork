# MB-007 — Remove the “Повелитель дифференциалов” FPL achievement

## Goal

Remove the FPL achievement currently displayed as **💎 Повелитель дифференциалов**
(`differential-merchant`) from MandarinBotNet.

The achievement is too noisy in practice: it is awarded to most/all league
players in many gameweeks, so users do not understand what is special about it
and it adds little value to recap/profile/achievement output.

This task removes the achievement rather than trying to retune or rename it.

## Context

- Project: `mandarinbotnet`.
- Target repository: `AlexBDevCorner/MandarinBotNet`.
- Default target branch: `main`.
- The achievement key is currently
  `FplAchievementKeys.DifferentialMerchant` with persisted key
  `differential-merchant`.
- The Russian display name is currently **💎 Повелитель дифференциалов**.
- `FplAchievementCalculationService` currently defines the achievement as
  “Was the only manager in the league to captain that player.”
- Its rule is effectively:
  `captainCounts[captainData.Captain.PlayerId] == 1`.
- In a small league, where many managers choose different captains, that rule
  naturally matches many players at once and can therefore award the
  achievement to nearly everyone in the same gameweek.
- The achievement is also included in profile/season-summary aggregation and in
  recap/message tests.
- Historical `differential-merchant` awards may already exist in the
  recognition store. Removing only the calculation rule would therefore be
  insufficient because old awards could still appear in profiles or affect
  achievement totals.

## Requirements

1. Stop generating new `differential-merchant` awards.

2. Remove the Differential Merchant achievement definition and rule from
   `FplAchievementCalculationService`.

3. Remove `FplAchievementKeys.DifferentialMerchant` from active achievement
   code where it is no longer required.

4. Remove the **💎 Повелитель дифференциалов** display mapping from
   `FplAchievementDisplay`.

5. Remove Differential Merchant from the achievement categories used for
   per-achievement season rankings.

6. Existing persisted `differential-merchant` awards must no longer be exposed
   to users or affect current recognition statistics. In particular, legacy
   awards must not:
   - appear in `/profile` achievement counts;
   - appear in `/achievements` / season-summary category output;
   - contribute to total achievement counts/rankings;
   - appear in gameweek recap achievement sections.

7. Prefer filtering/ignoring the retired persisted key at the recognition query
   / composition boundary rather than introducing a risky destructive database
   migration solely for this cleanup. Existing rows may remain stored as legacy
   data as long as they are invisible and do not affect current totals.

8. Keep all other achievements unchanged:
   - First Blood;
   - Bench Warmer;
   - Captain Disaster;
   - -8 Enjoyer.

9. Do not replace Differential Merchant with a new achievement in this task.

10. Update all affected automated tests so they no longer expect or create
    Differential Merchant as an active achievement.

11. Add regression coverage proving that legacy persisted
    `differential-merchant` rows are ignored by user-facing profile and season
    summary calculations.

12. Keep the change focused on achievement removal. Do not redesign the
    recognition framework, persistence model, FPL snapshot collection, recap
    scheduling, or Discord command architecture.

## Architectural direction

Treat `differential-merchant` as a retired achievement key.

New recognition calculation must never create it. User-facing query/composition
code must ignore already-persisted rows with that key so historical data cannot
continue to show the removed achievement or inflate totals.

A small explicit legacy-key filter is preferable to a database migration unless
the existing persistence design already has a safe, established migration path
that makes removal trivial.

Do not weaken or change behavior for the remaining achievements.

## Acceptance criteria

- [ ] No new `differential-merchant` award is produced by
      `FplAchievementCalculationService`.
- [ ] **💎 Повелитель дифференциалов** is no longer emitted in any Discord
      message.
- [ ] Differential Merchant is no longer listed in active achievement
      definitions or season-summary categories.
- [ ] A manager profile does not display historical Differential Merchant
      awards.
- [ ] Historical Differential Merchant awards do not contribute to total
      achievement ranking counts.
- [ ] Historical Differential Merchant awards do not produce
      per-achievement leaders.
- [ ] Gameweek recap output does not show the retired achievement.
- [ ] All other achievements continue to calculate and render as before.
- [ ] Tests include a stored legacy `differential-merchant` award and verify it
      is ignored by profile and season-summary output.
- [ ] Existing tests that referenced **Повелитель дифференциалов** are updated
      or removed as appropriate.
- [ ] `dotnet build MandarinBotNet.sln` succeeds.
- [ ] `dotnet test MandarinBotNet.sln` succeeds.

- the literal persisted key may remain only where intentionally required to
  recognize and ignore legacy stored rows;
- tests may contain the persisted key only for regression coverage proving the
  retired achievement stays hidden.

## Out of scope

- Designing a replacement achievement.
- Retuning the captain uniqueness rule.
- Renaming Differential Merchant.
- Reworking unrelated recognition rules.
- Recalculating the whole current season.
- Destructive cleanup of historical recognition data unless strictly necessary.
- Changing FPL data sources, gameweek snapshot collection, scheduling, or
  Discord channel configuration.
