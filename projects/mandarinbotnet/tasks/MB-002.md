# MB-002 — Trigger AutonomousWork dispatcher from MandarinBotNet every 10 minutes

## Goal

Use MandarinBotNet's existing Quartz scheduler as the reliable clock for
AutonomousWork by triggering the control repository's dispatcher workflow every
10 minutes.

MandarinBotNet must only trigger the existing dispatcher. Task selection,
claiming, reconciliation, retries, review handling, and target-repository
dispatch remain owned by AutonomousWork.

## Context

GitHub Actions scheduled workflow execution has proven unreliable for this
repository: manual and push-triggered runs work, but scheduled runs have not
been created reliably.

The control workflow already supports `workflow_dispatch`:

`AlexBDevCorner/AutonomousWork/.github/workflows/dispatch.yml`

MandarinBotNet already uses Quartz through
`AddMandarinBotScheduling()`, so it can provide a small external scheduler
without introducing a second scheduling framework.

The desired steady state is:

1. MandarinBotNet Quartz trigger fires every 10 minutes.
2. A small job sends a GitHub workflow-dispatch request for
   `AutonomousWork/.github/workflows/dispatch.yml` on `master`.
3. AutonomousWork performs all existing validation, reconciliation, task
   selection and target-repository dispatch.
4. If no work is eligible, the dispatcher exits normally.

## Requirements

1. Add a dedicated configuration model for the AutonomousWork dispatcher
   trigger. It must support at least:
   - `Enabled`
   - `Cron`
   - target owner/repository
   - workflow file name or workflow ID
   - target ref
   - GitHub token

2. The default configuration must be safe:
   - scheduler disabled by default;
   - cron configured for every 10 minutes using Quartz syntax
     (`0 0/10 * * * ?`);
   - target repository defaults to `AlexBDevCorner/AutonomousWork`;
   - workflow defaults to `dispatch.yml`;
   - ref defaults to `master`;
   - no token is committed to source control or appsettings.

3. Runtime secret configuration must support supplying the token through the
   normal .NET configuration hierarchy, for example an environment variable
   such as `Bot__AutonomousWorkDispatcher__Token`.

4. Extend startup validation so that:
   - the cron expression is valid;
   - owner, repository, workflow and ref are non-empty when enabled;
   - a token is required when enabled;
   - disabled configuration does not require a token.

5. Implement a small GitHub client/service that triggers the existing workflow
   through GitHub's workflow-dispatch REST endpoint:

   `POST /repos/{owner}/{repo}/actions/workflows/{workflow_id}/dispatches`

   with a request body containing the configured ref.

6. GitHub requests must:
   - use bearer-token authentication;
   - send GitHub's JSON media type;
   - send a supported GitHub REST API version header;
   - treat any successful 2xx response as success;
   - include enough response/error information in logs for diagnosis without
     ever logging the token.

7. Implement the scheduler as a Quartz `IJob` integrated with the existing
   `AddMandarinBotScheduling()` registration rather than introducing another
   timer, background loop, hosted service scheduler, or scheduling package.

8. Prevent overlapping executions of this job within the MandarinBotNet
   process, using the normal Quartz mechanism for non-concurrent job execution.

9. Register the job only when the scheduler feature is enabled.

10. A failed GitHub request must:
    - be logged clearly;
    - fail that Quartz execution;
    - not disable future scheduled executions;
    - not introduce a fast retry loop. The next normal Quartz occurrence is
      sufficient.

11. Keep the implementation isolated from Discord/FPL/UCL business logic.
    The scheduling job must not depend on Discord connectivity.

12. Add automated tests covering at least:
    - configuration defaults;
    - validation when enabled/disabled;
    - the 10-minute cron registration;
    - correct GitHub endpoint;
    - correct ref payload;
    - required authentication/API headers;
    - successful 2xx handling;
    - non-success response handling;
    - token not appearing in exception/logging paths where practical.

13. Update project documentation/configuration examples so an operator can see
    exactly which non-secret values and which runtime secret must be configured.

## Architectural direction

Keep this feature deliberately small.

Prefer a typed `HttpClient` or equivalent thin HTTP abstraction and the
existing Microsoft.Extensions dependency-injection/configuration patterns.
Do not add Octokit or another GitHub SDK unless the existing implementation
cannot reasonably express this one endpoint with `HttpClient`.

Keep the external scheduler dumb: it sends one workflow-dispatch request and
stops. It must not inspect tasks, determine whether work exists, select a
project, update task status, call target repositories directly, or duplicate
any logic from AutonomousWork.

The GitHub credential is an operator-provided runtime secret. The expected
credential is a fine-grained token scoped only to the private
`AlexBDevCorner/AutonomousWork` repository with the minimum permission
required to create a workflow dispatch event.

## Acceptance criteria

- [ ] MandarinBotNet can be configured to trigger
      `AlexBDevCorner/AutonomousWork/.github/workflows/dispatch.yml` on
      `master`.
- [ ] When enabled, the Quartz trigger runs every 10 minutes.
- [ ] When disabled, no AutonomousWork trigger is registered.
- [ ] The GitHub token is never committed to the repository.
- [ ] A successful scheduled execution creates a new
      `workflow_dispatch` run in AutonomousWork.
- [ ] Failure to call GitHub is observable in MandarinBotNet logs and does not
      prevent later scheduled executions.
- [ ] Existing MandarinBotNet scheduled jobs continue to behave unchanged.
- [ ] All tests pass.
- [ ] No AutonomousWork task-selection/reconciliation logic is copied into
      MandarinBotNet.

## Verification

Run:

```sh
dotnet build MandarinBotNet.sln
dotnet test MandarinBotNet.sln
```

Then perform one real integration check with production-like configuration:

1. Enable the new scheduler.
2. Configure the GitHub token through the runtime secret provider.
3. Temporarily invoke the job or wait for the next 10-minute occurrence.
4. Confirm a new run appears for
   `AutonomousWork/.github/workflows/dispatch.yml` with event
   `workflow_dispatch`.
5. Confirm the MandarinBotNet log records success without exposing credentials.
6. Confirm a subsequent 10-minute occurrence triggers another dispatcher run.

## Out of scope

- Reimplementing task selection, reconciliation or retry rules in MandarinBotNet.
- Reintroducing GitHub Actions `schedule` as the primary clock.
- Changing AutonomousWork's existing dispatcher/reconciler behavior.
- Changing the autonomous PR review/merge protocol.
- Adding automatic retries faster than the normal 10-minute schedule.
- Supporting multiple GitHub repositories/workflows from one scheduler job.
- Distributed/multi-instance Quartz coordination.
- Replacing the existing GitHub App used by AutonomousWork for cross-repository
  orchestration.
