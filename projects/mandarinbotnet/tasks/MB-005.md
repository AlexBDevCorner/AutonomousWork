# MB-005 — Run MandarinBotNet autonomous worker on Linux

## Goal

Move MandarinBotNet's autonomous OpenCode worker from a Windows GitHub-hosted
runner to Linux so its autonomous development workflow uses the same
Linux-oriented environment as the repository's existing CI, deployment, and
infrastructure workflows.

## Context

- Project: `mandarinbotnet`.
- Target repository: `AlexBDevCorner/MandarinBotNet`.
- `.github/workflows/autonomous-worker.yml` currently uses
  `runs-on: windows-latest`.
- MandarinBotNet's normal `.github/workflows/ci.yml` jobs already run on
  `ubuntu-latest`.
- Its OCI deployment/provisioning workflows are already Linux-oriented as well.
- The autonomous worker contains several `pwsh` steps and a prompt instruction
  saying `Use PowerShell for Windows environment variables.`.
  Linux runners may still provide PowerShell, but the autonomous workflow must
  no longer depend on Windows-specific environment syntax, paths, tools, or
  assumptions.
- The existing autonomous workflow behavior is working and must be preserved;
  this task changes the execution platform, not the control model.

## Requirements

1. Change the MandarinBotNet autonomous worker job in
   `.github/workflows/autonomous-worker.yml` from `windows-latest` to
   `ubuntu-latest`.
2. Audit every script and shell fragment in the autonomous-worker workflow and
   make it Linux-safe. It is acceptable to keep `pwsh` where PowerShell is
   genuinely cross-platform, but no step may depend on Windows-only paths,
   executables, environment-variable syntax, or runner behavior.
3. Remove or replace worker prompt/comments that tell the model it is running on
   Windows, including `Use PowerShell for Windows environment variables.`.
   The prompt must accurately describe the Linux runner and should prefer
   platform-appropriate shell/environment syntax.
4. Preserve all existing autonomous-worker safety and control behavior:
   - MB task/path validation;
   - pinned AutonomousWork checkout;
   - validator build and control SHA recording;
   - authorization guard;
   - GitHub App token minting;
   - explicit `gh` authentication validation;
   - Git credential wiring without exposing credentials;
   - OpenCode permission restrictions;
   - autonomous branch/PR/checkpoint behavior;
   - implementation/correction modes.
5. Preserve the current toolchain requirements: .NET 8 plus the pinned .NET 10
   SDK used by MandarinBotNet, Node 22, GitHub CLI, Git, and the pinned OpenCode
   action.
6. Do not weaken credential protections or external-directory restrictions when
   adapting the workflow for Linux.
7. Keep MandarinBotNet's existing CI, deployment, and infrastructure workflows
   on Linux. They already use Ubuntu/Linux runners and should not be moved back
   to Windows.
8. Keep the change focused on autonomous-worker runner/shell portability. Do not
   change bot features, deployment behavior, infrastructure semantics, or
   AutonomousWork task-control behavior.

## Architectural direction

- Align the autonomous worker with the repository's existing Linux-first GitHub
  Actions environment.
- Prefer Linux-native workflow behavior rather than emulating a Windows runner.
- Cross-platform PowerShell is allowed where it remains clear and robust; Bash
  is preferred where a step is naturally POSIX-oriented.
- Preserve the GitHub App authentication design and exact OpenCode action pin.
- Keep using GitHub-hosted runners; no self-hosted worker is introduced.

## Acceptance criteria

- [ ] MandarinBotNet `autonomous-worker.yml` uses `ubuntu-latest`.
- [ ] No active autonomous-worker instruction assumes a Windows runner.
- [ ] Dispatch validation, control checkout, guard, App-token auth, Git auth,
      OpenCode restrictions, and PR/checkpoint behavior remain intact.
- [ ] The worker can build the AutonomousWork validator and execute the guard on
      Ubuntu.
- [ ] The worker reaches and runs the OpenCode GitHub action on Ubuntu without a
      Windows-specific shell/path failure.
- [ ] Existing MandarinBotNet CI remains Linux-based and passing.
- [ ] Existing deployment/provisioning workflows remain Linux-based.
- [ ] No bot or infrastructure behavior is changed.

## Verification

Run the repository's normal build/test commands on Linux:

```bash
dotnet build MandarinBotNet.sln
dotnet test MandarinBotNet.sln
```

Expected: build and tests succeed.

Inspect the autonomous workflow and confirm:

```text
.github/workflows/autonomous-worker.yml -> runs-on: ubuntu-latest
```

Confirm the existing CI/deployment/provision workflows still use their existing
Ubuntu/Linux runners.

After merge, the next autonomous MandarinBotNet task dispatch must start its
worker job on an Ubuntu GitHub-hosted runner and reach the OpenCode action
without a Windows-specific shell/path failure.

## Out of scope

- No MandarinBotNet feature changes.
- No deployment or OCI infrastructure redesign.
- No AutonomousWork protocol changes.
- No self-hosted runner setup.
- No changes to existing Linux CI semantics beyond what is strictly required
  for compatibility with this runner migration.
