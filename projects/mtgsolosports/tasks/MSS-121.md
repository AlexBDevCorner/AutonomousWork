# MSS-121 — Display and export Color Cup qualification cutoff and final

## Goal

Make the confirmed 32-to-16, full-score-carryover individual Color Cup easy to follow in UI, history and downloadable reports without changing historical editions.

## Context

- Project `mtgsolosports`; target repository `AlexBDevCorner/MtgSoloSports` (`main`).
- MSS-119 stores/distinguishes format and preserves old editions; MSS-120 implements the deterministic two-phase backend.
- New Color Cup: 32 athletes for rounds 1–16; the top 16 qualify, positions 17–32 are locked; rounds 17–32 are played only by finalists **without resetting points**. Final podium and places 1–16 come from the combined points.
- Current user experience includes live rounds, Cup edition history, athlete records and textual/Drive export workflows; preserve these.

## Requirements

1. Update individual Color Cup progress displays to show rounds 1–32 for new editions and 1–16 for historical ones.
2. Make the round-16 cutoff legible: provisional qualification standings and an explicit top-16 advancing boundary, including qualified/eliminated athlete state.
3. Display the final phase with exactly 16 active athletes and retained cumulative points; show the continuity from round 16 to 17, not a score reset.
4. Show final 1–16 rankings and medals plus eliminated 17–32 by qualifying finish. Preserve navigation to replay for every recorded round.
5. Include format, qualifying ranks/cutoff, advancing status, points/carryover and final placements in relevant Color Cup report/export formats where appropriate; make the same information usable by Drive synchronization if the existing report is its input.
6. Historical 16-round individual Cups must continue displaying and exporting accurately with no fabricated qualification or final rounds.
7. Add focused API contract, frontend and export regression tests. Do not make UI changes to unrelated tournaments.

## Architectural direction

- Prefer existing Cup edition/history/live components and report projections. New projections should be format-aware, backed by persisted data and never reconstructed from unrelated league standings.
- Make any new metadata additive so existing clients/saves are not broken.
- Keep scope to Color Cup presentation and reports; no new simulation logic.

## Acceptance criteria

- [ ] New Cups show a clear 16-round qualifying cutoff, 16-person second phase and cumulative scores across both phases.
- [ ] Eliminated positions 17–32 and final ranks 1–16 are presented distinctly; historical medals/records remain correct.
- [ ] Existing 16-round editions remain accurate in UI and textual exports.
- [ ] Round replay, reports and, where applicable, Drive-compatible exports correctly reflect the mixed 32/16 round format.
- [ ] Relevant frontend/backend tests and required repository checks pass.

## Verification

Run Cup UI tests, API/report compatibility tests, typecheck/build and repository-standard .NET checks from target `AGENTS.md`. Compare a legacy 16-round edition and a new two-phase edition in live, history and export views.

## Out of scope

- Changes to rules, simulation or persistence beyond small additive read-model data needed for presentation.
- Changes to Type Cup, team Color Cup, Chaos Cup, league standings, or selection weights.
- Recomputing/replacing historical results.
