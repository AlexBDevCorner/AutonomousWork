# MSS-119 — Differentiate individual Color Cup with a longer format

## Goal

Give the individual Color Cup a distinct sporting identity instead of reusing an ordinary 16-round league stage. **Draft proposal, not approved for implementation.**

## Context

- Project: `mtgsolosports`; target: `AlexBDevCorner/MtgSoloSports` (`main`).
- User proposal: increase the individual Color Cup to 32 rounds; 32 selected athletes (4 per each of 8 colors) still compete.
- Current code: `RulesV1.ColorCupIndividualRounds` defaults to 16, and `RulesV1.Validate()` enforces `ColorCupIndividualRounds == RoundsPerStage` (16). `RunColorCupIndividualHandler`, `ColorCupIndividualInvariants`, API/read models and tests assume that duration.
- The existing Cup uses active career bonus but awards neither league championship points nor additional career bonus; Cup medals and honours are separate.
- The user is currently considering alternatives; this draft MUST NOT be moved to `ready` before format selection is confirmed.

## Proposed requirements (subject to product decision)

1. Preferred minimal change: 32 rounds, the same 32 athletes in every round, cumulative points across all 32 rounds, podium decided only after the final round.
2. Optionally display a midpoint at round 16 with provisional leaders and changes during rounds 17–32. This is a presentational split only; no score reset or elimination in the minimal proposal.
3. Preserve the existing deterministic seeded simulation, replay checksums, round-by-round play and complete-cup simulation.
4. Preserve the current isolation from league points, career active bonus earning, and team Color Cup scoring.
5. Keep already-completed historical 16-round individual Cups readable, verifiable and exportable. Do not retroactively re-simulate them or interpret their records using the new 32-round invariant.
6. Add focused tests for new Cups and backward compatibility with old Cup editions. Update hardcoded 16-round assertions and any round counters/progress indicators only where applicable.

## Open product decisions

- Choose 32 continuous rounds (recommended for simplicity), 16+16 with a purely visual midpoint, 24 rounds, or an actual two-phase event with score carryover/elimination.
- Decide whether a half-time visual recap should be part of this PR or a separate small follow-up.
- Confirm that the change applies to **new** Color Cup editions only and that existing editions retain their original format.

## Architectural direction

- Reuse the existing sporting kernel and direct Endpoint → Handler architecture; do not introduce MediatR.
- Avoid changing `RoundsPerStage` globally: normal league stage duration must remain 16.
- Do not assume changing one default suffices. Consider persisted effective format/rule version for historical reads and guard validation of both durations.
- Keep PR scope small; split optional UI enhancements into a separate task rather than pulling unrelated features into this change.

## Acceptance criteria (provisional)

- [ ] An approved new Cup format runs deterministically round-by-round and via complete simulation.
- [ ] A new Cup completes with the selected round count and exactly 32 standings entries.
- [ ] Existing 16-round Cups remain unchanged and are still served accurately by history/read/report/export paths.
- [ ] Bonus, league points, medals and history behave as before except for the explicitly approved format change.
- [ ] The existing tests and focused backward-compatibility tests pass.

## Verification

Run targeted Color Cup tests, then repository-required .NET and web validation from `AGENTS.md`. Confirm both an existing 16-round saved Cup and a newly generated Cup can be queried without migration errors.

## Out of scope

- No changes to normal 16-round league stages.
- No changes to Color Cup team competition, Type Cup, or Chaos Cup format.
- No global rebalancing of active bonuses or scoring tables.
- No elimination brackets, score resets or half-points carryover without a separate product decision.
- No retroactive alteration of historical Cup results.
