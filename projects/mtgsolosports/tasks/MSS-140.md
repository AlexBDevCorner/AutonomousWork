# MSS-140 - Rework the Records page into full-width views that fit their data

## Goal

Make every record on the Records page readable without cramped columns, cut-off holders or horizontal scrolling. Split the page into full-width views and give each kind of record a layout suited to its shape.

## Context

- Project `mtgsolosports`, target `AlexBDevCorner/MtgSoloSports` on `main`.
- Reproduced at `/saves/:saveId/records` on a Season 19 save at a wide desktop width. `src/MtgSoloSports.Web/src/features/records/RecordsPage.tsx` puts seven cards (Career leaders, Career records, League scoring, Individual Cups, Team Cups, Record breaks, Official honours) into the auto-fit `.page-grid` from `shared/ui/base.css`. Each card is about 440px wide, which causes these problems:
  - **Career leaders:** the Titles column wraps `3 (0F · 3S)` across two lines, and the table needs a horizontal scrollbar.
  - **Career records:** a tied record lists every holder inline. **Superleague appearances** (18) is shared by hundreds of athletes, which makes one cell taller than the rest of the page. Other holder lists are cut off at the card edge.
  - **League scoring** has 27 rows. Each record label wraps to three or four lines, and holder names plus their season and league details are cut off behind a horizontal scrollbar.
  - **Individual Cups and Team Cups** have the same wrapping and cut-off holder details.
  - Record breaks and Official honours sit below these cards, out of view.
- League scoring is a fixed grid: 9 league scopes (`ScoreRecordKey.LeagueScopes`: 8 colors plus Superleague) × 3 metrics (single round, single stage, season league points). The records come from `GET /api/saves/:saveId/records` (`Features/Records/GetRecords`). Each `ScoringRecordEntry` has `RecordKey`, `Label`, `Category`, `Scope`, the value and `Holders`. There is no explicit field for which metric a record measures.
- Other pages already have URL-backed view switchers: Standings `?view=season|matrix` uses the `.segmented` control. `routes.ts` currently parses `/records` without a query string.
- MSS-139 adds links on this page (honours league, color sub-labels, team holders). Whichever task merges first, the other must keep the existing athlete links and any entity links already present.

## Requirements

1. Split Records into views with a URL-backed switcher: **Hall of Fame** (career leaders), **Career records**, **Scoring records**, and **Honours** (official honours plus recent record breaks). `/records` opens Hall of Fame. `?view=<key>` opens that view. An unknown key falls back to Hall of Fame. Refresh, Back/Forward and copied URLs restore the view, and switching views pushes a history entry.
2. Each view uses the full content width. At 1280px and wider, no Records table needs horizontal scrolling and no holder name or context is cut off. Narrow screens may still scroll tables horizontally.
3. **Hall of Fame:** the Titles breakdown and other compact values stay on one line. The window selector and the **Where points came from** breakdown keep working as today.
4. **Career records:** show the first holders of a tied record (about 10) followed by an accessible "+N more" control that expands the full list in place. Show the total number of holders next to the value.
5. **League scoring:** show a grid with one row per league scope (8 colors, then Superleague) and one column per metric (single round, single stage, season points). Each cell shows the value, the holder(s) and the season, stage or round context. Vacant cells show **Vacant**.
6. **Individual Cups and Team Cups:** group records by event (Color Cup individual, Qualifier, Color Cup team, Type Cup team). Record labels must not wrap beyond two lines at desktop width. Holder context stays fully visible.
7. Keep every existing athlete link and info text. Keep loading, empty and error states for each view. Load only the data the current view needs where the existing endpoints allow it. All values come from persisted data, as today.
8. The view switcher works with the keyboard and announces the current view (for example `aria-current` or `aria-pressed`). Layout respects reduced motion and the existing dark theme.

## Architectural direction

- Frontend change in the Records slice, plus the `records` route parse/build in `features/routing/routes.ts` and its tests. Document `?view=` in `docs/frontend-routing.md`.
- Build the League scoring grid from structured fields (`Category`, `Scope`, and a metric identity). If no explicit metric field exists, add one additively to `ScoringRecordEntry` in `Features/Records/GetRecords`, for example `Metric` = `round | stage | season`. MUST NOT derive the grid from display labels.
- Reuse existing CSS tokens, `.segmented`, `Card` and `data-table` styles. Add Records-specific CSS in the feature folder, not a new component library. Native `<details>` or a small local toggle is enough for "+N more".
- No backend calculation, ranking or record-rule changes. Only additive read-only response fields are allowed.

## Acceptance criteria

- [ ] `/saves/:saveId/records` opens Hall of Fame, and each `?view=` key opens its view. A refresh keeps the view, and an invalid key falls back to Hall of Fame.
- [ ] On a Season 19 tiered save at 1920px and 1280px wide, no Records table shows a horizontal scrollbar and no holder text is cut off.
- [ ] Superleague appearances with hundreds of tied holders shows about 10 names, the total count and a "+N more" control. Expanding it shows every holder, and the row stays readable.
- [ ] League scoring shows a 9 × 3 grid with the correct value, holders and context in every cell, matching the current records data.
- [ ] Individual Cups and Team Cups records are grouped by event with readable labels and full holder context.
- [ ] Route parse/build tests cover each view key and the fallback. Frontend tests cover the League grid mapping, the "+N more" threshold and empty/vacant states. Any new backend field has an API test.

## Verification

- Run `npm test --prefix src/MtgSoloSports.Web`, `npm run typecheck --prefix src/MtgSoloSports.Web`, and `npm run build --prefix src/MtgSoloSports.Web`.
- If the backend changes, run `dotnet test tests/MtgSoloSports.Tests --configuration Release --filter FullyQualifiedName~Records` plus the repository-required backend checks in `AGENTS.md`.
- In a test save of 10 or more seasons, open each view at 1920px, 1280px and phone width. Check scroll, wrapping, keyboard switching, Back/Forward and refresh.

## Out of scope

- New records, changes to record or tie rules, Hall of Fame weights, or how records are computed or stored.
- Entity links for league, color and team names, which MSS-139 covers.
- Redesigning other pages, the app shell or shared page-grid behavior outside Records.
- Search, filtering or pagination of records beyond the "+N more" holder expansion.
