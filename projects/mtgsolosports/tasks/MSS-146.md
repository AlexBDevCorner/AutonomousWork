# MSS-146 - Stop the Live screen from swallowing load failures

## Goal

The Live screen must show an actionable error with retry when required data fails to load, instead of rendering "no rounds played" plus dead controls; aborted requests from navigation must not clobber the state of the request that replaced them.

## Context

- A repository review (2026-11-19) verified the following; re-verify on the live checkout.
- `src/MtgSoloSports.Web/src/features/live/LiveEventView.tsx:183-216`: the primary loads (`fetchSeasonEvents`, `fetchEventRounds`, standings) are wrapped in `.catch(() => [])`/null, and the outer `.catch(() => setLoading(false))` swallows everything; the `error` state is never set on load failure. A network error renders "no rounds played" + dead controls on the app's main Live screen.
- `src/MtgSoloSports.Web/src/features/live/LiveQualifierView.tsx:105-110` (and `LiveEventView.tsx:216`): `setLoading(false)` runs even on `AbortError`, so a request aborted by a save/round switch prematurely clears the *new* request's spinner. The correct pattern exists in `features/saves/useSaves.ts:32-34`.
- `src/MtgSoloSports.Web/src/features/movement/MovementReveal.tsx:316,336`: `boundaries.map()` returns an unkeyed `<>` fragment as the array element (inner elements keyed, fragment not), causing React missing-key warnings and positional reconciliation on reorder.
- Genuinely optional payloads (tournament/draw/individual progress) may keep degrading silently; the fix targets required data.
- Colocated mounted-component tests exist (`features/live/liveEventViewMounted.test.ts`, `qualifierLiveMounted.test.ts`) with mocked fetch, but no error-path coverage exists.

## Requirements

1. Required load failures (season events, event rounds, standings summary) set the error state and render the existing error styling with a retry action; loading and empty states remain correct.
2. Abort handling follows the `useSaves.ts` pattern: an aborted request never touches loading/error state of its successor.
3. Only optional payloads may fall back silently, each with a code comment naming the payload as optional.
4. Key the fragment in `MovementReveal` with the boundary key (`<Fragment key={...}>`).
5. No redesign; reuse existing error/empty styling and the reduced-motion-aware reveal behavior.

## Architectural direction

- Changes stay inside `features/live` and `features/movement`; presentation-only state stays in React; reveal/replay still consumes persisted immutable results and never resimulates (AGENTS.md). No new dependencies.

## Acceptance criteria

- [ ] A mocked failing required fetch renders an error with retry; retry refetches and recovers.
- [ ] A save/round switch during a pending load never ends with the new request's spinner cleared early or stale error shown.
- [ ] No React key warnings from MovementReveal under test.
- [ ] Existing live/reveal mounted tests keep passing.

## Verification

Standard AGENTS.md web sequence: `npm ci`, `npm run test`, `npm run typecheck`, `npm run build` (plus the backend build/test sequence unchanged). Add colocated error-path tests for the acceptance criteria above.

## Out of scope

- Backend changes, data reshaping, redesign of the Live layout, reveal animation changes, and any sporting behavior.
