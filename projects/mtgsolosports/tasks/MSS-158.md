# MSS-158 - Move the save-mutation lock to Shared and stop leaking per-save entries

## Goal

The de-facto global save-mutation lock moves out of `Features/Simulation/AdvanceRound` into `Shared/` where its ownership belongs, and per-save lock/gate entries no longer accumulate forever after saves are deleted.

## Context

- A repository review (2026-11-19) verified the following; re-verify on the live checkout.
- `src/MtgSoloSports/Features/Simulation/AdvanceRound/AdvanceRoundSaveLock.cs:9-17` holds a static per-save-id `SemaphoreSlim` dictionary used by 25+ handlers across all features and by `Persistence/Saves/SaveStore.cs:774,1001,1567` - a genuinely global concept living inside one feature, contradicting AGENTS.md section 5 (shared code only for genuinely global concepts - and this is one, so it belongs in `Shared/`).
- The dictionary never evicts: every save id (including deleted saves) leaks one semaphore forever; the same applies to `SaveStore.cs:70,85` (`MigrationGates`, `SnapshotGates`). On localhost the leak is negligible, which is why this task is the lowest priority of the review batch - it is hygiene, not an active bug.
- Concurrency behavior must not change: the lock is the mutation serializer that makes RNG-commit-with-results safe under concurrent requests.

## Requirements

1. Move the lock type to `Shared/` (mechanical move + namespace updates across all users; no behavioral change). Name it for what it is (per-save mutation lock), not for the feature that happened to create it.
2. Evict entries when a save is deleted: remove the lock/gate entry only when it is uncontended (no current holders/waiters); if contended, leave it and retry on the next delete. Document the weak-eviction rationale in one comment (bounded by distinct save ids, localhost single-user).
3. Apply the same safe eviction to `MigrationGates`/`SnapshotGates` in `SaveStore` where the same rule holds.
4. No lock-scope changes, no new locking levels, no async-serialization redesign; the existing concurrency tests must pass unchanged.

## Architectural direction

- One small mechanical move plus a bounded eviction helper. Do not introduce a cache/registry abstraction; keep the dictionary + guard style the file already uses. AGENTS.md sections 3/5 apply: no generic services, shared only for global concepts.

## Acceptance criteria

- [ ] No feature references the lock type inside `Features/Simulation/AdvanceRound` as its home; all 25+ call sites compile against the `Shared/` location.
- [ ] Deleting a save releases its uncontended entries; a focused test creates/deletes N saves and asserts the entry count does not grow with N; a contended entry is retained (test with a held semaphore).
- [ ] Existing concurrency/round-advance/qualifier tests pass unchanged (full suite green).

## Verification

Standard AGENTS.md backend sequence: locked restore, Release build, full test suite, `dotnet format --verify-no-changes`. Add the focused eviction test; run the simulation concurrency test classes alone from a fresh process.

## Out of scope

- Redesigning locking granularity, WAL/file-replacement ordering (MSS-148), corruption failure classes (MSS-144), and any sporting behavior.
