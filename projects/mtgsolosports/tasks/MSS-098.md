# MSS-098 — Define pure Chaos format and eight-color quota rules

## Goal

Centralize versioned tournament size, stage/advancement invariants and per-color Pool invitation quotas.

## Context

- Project `mtgsolosports`, target `AlexBDevCorner/MtgSoloSports` (`main`). .NET + React, direct vertical-slice Endpoint → Handler, no MediatR; follow `AGENTS.md`. Approved Chaos Cup: 8 sporting colors, 1024 entrants (all source-season league athletes plus random Pool invitations), six 32-athlete group stages [32,16,8,4,2,1], top 16 from each nonfinal group; 16 game rounds per group, active bonus used but not earned; no league points/promotion, group scores reset; first draw exactly 4/color/group, later draws pure random. Runs after 32 league stages and before promotion qualifiers, only for a new season after deployment; odd/even Color/Type Cups keep alternating. Existing sporting history must remain unchanged.
- Scope: **Define pure Chaos format and eight-color quota rules**. This is a single small PR, target roughly 200–600 changed lines where practical; if work expands materially, propose follow-up rather than bundling unrelated features.
- Dependencies: none; tasks with incomplete dependencies must wait.

## Requirements

1. Define 1024 field, 32-member groups, stage group counts 32/16/8/4/2/1, 16 game rounds per group, top-16 advancement and official 32-place Final.
2. Implement per-color entrants = 128, Pool invitations = 128 minus active source-season athletes of that color; cover normal 800 active/224 Pool, Season 1 768/256 Pool and compatible legacy compositions.
3. Validate 8 known SportingColor values, no duplicate entrants and enough Pool; first groups need 4 each color, subsequent groups have no color/tier seeding.
4. Define exit-stage categories for eliminated athletes with no fabricated global numeric ranks.

## Architectural direction

- Reuse existing feature/simulation/report patterns; keep deterministic integer calculations, save-scoped state and clear compatibility boundaries. Do not introduce MediatR or unrelated refactors.

## Acceptance criteria

- [ ] Invalid rosters/format rejected; existing rule snapshots load.
