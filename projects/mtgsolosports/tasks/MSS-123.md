# MSS-123 — Make Chaos Cup full-tournament completion deliberate

## Goal

Prevent accidental full Chaos Cup fast-forward from either Dashboard or Live, while keeping one-click group/stage progress available.

## Context

- Target repository: `AlexBDevCorner/MtgSoloSports` (ASP.NET Core + React; local single-user app).
- The DeepSeek Flash review of [MtgSoloSports PR #115](https://github.com/AlexBDevCorner/MtgSoloSports/pull/115) identified two non-blocking but user-visible UX issues after MSS-110.
- In `SeasonFlow.tsx`, Dashboard advertises a generic **Run all rounds** action when `RunChaosCup` is next, yet `advance-next-event` completes all remaining six Chaos stages (up to 1008 total group rounds), with no confirmation.
- In `ChaosCupLiveView.tsx`, the first **Finish entire Cup** click opens a confirmation, but the original button stays enabled. Another click on it invokes the completion directly, bypassing the explicit **Yes, finish entire Cup** control.
- These are local UX/intent problems, not remote security issues. Keep this a small, focused PR.

## Requirements

1. When the next legal Dashboard event is `RunChaosCup`, distinguish full-tournament completion from the currently selected group or stage. Use an explicit label and require a clear confirmation before calling the full fast-forward action. Keep current labels/behaviors for unrelated events.
2. In Chaos Live, the first **Finish entire Cup** activation must only show confirmation. While confirmation is open, disable or hide the original trigger; only the dedicated affirmative action may execute the full-Cup mutation. Cancellation must leave the tournament unchanged.
3. Guard against repeated activation while a mutation is in flight, without breaking existing per-group/per-stage controls, replay and selection.
4. Add focused frontend tests exercising the Dashboard and Live confirmation paths. Cover initial trigger, repeated trigger/double-click, cancel, confirm, and the correct mutation endpoint being invoked no more than once.
5. Preserve persisted sporting data, RNG semantics, API contracts and backend lifecycle; this is a frontend UX fix.

## Architectural direction

Reuse existing `Notice`, buttons and React state patterns in the current dashboard/Live features. Avoid a new generic confirmation framework or unrelated refactors.

## Acceptance criteria

- [ ] No Dashboard control can silently finish the entire Chaos Cup behind an ambiguous **Run all rounds** label.
- [ ] A rapid double-click on the original Live full-Cup trigger cannot finish the tournament without the explicit affirmative confirmation.
- [ ] The explicit confirmation succeeds exactly once; cancelling makes no mutation.
- [ ] Group/stage finish, replay and non-Chaos Dashboard actions behave as before.
- [ ] Frontend tests cover the failure paths and pass.

## Verification

Run `npm run typecheck --prefix src/MtgSoloSports.Web`, `npm run build --prefix src/MtgSoloSports.Web` and the focused frontend test suite; run the repository-required checks per `AGENTS.md`.

## Out of scope

- No changes to Chaos selection, ranking, medals, sporting simulation, endpoint authorization or persistence.
- No rework of unrelated Dashboard actions, generic confirmation infrastructure or backend endpoints.
- No automatic scheduling or changes to the reviewer model/prompt.
