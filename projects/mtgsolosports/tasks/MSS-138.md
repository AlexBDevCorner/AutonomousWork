# MSS-138 - Link leagues, colors, nationality and Cup teams from the athlete profile

## Goal

Make every league, color team, Type Cup team and Cup edition named on the athlete profile a link to its page. A player reading a career should be able to jump from any row to the league, team or event it mentions.

## Context

- Project `mtgsolosports`, target `AlexBDevCorner/MtgSoloSports` on `main`.
- Reproduced on `/saves/:saveId/athletes/:athleteId` (Tendril of the Mycotyrant, Season 19). **Current league** "Green League F2", **Color** "Green" and the 19 league names in the season-by-season history are all plain text.
- `src/MtgSoloSports.Web/src/features/athletes/AthleteProfilePage.tsx` renders these as text today:
  - identity block: `card.sportingColorName` (Color), `nationalityText` (Type Cup nationality), `currentLeagueText` (Current league);
  - **Card** detail: Sporting color, Type Cup nationality;
  - season-by-season history: `season.leagueName`;
  - honours: `honour.leagueName`;
  - postseason movements: `fromLeagueName` → `toLeagueName`;
  - Cup selections: `selection.team`;
  - Cup history: `entry.teamName` and the season number.
- These pages and builders already exist in `src/MtgSoloSports.Web/src/features/routing/routes.ts`:
  - `leaguePath(saveId, leagueKey)` opens the cross-season league profile. `leagueKey` is the stable key (`superleague`, `feeder-2-green`, legacy `feeder-green`). The backend `Features/Leagues/Profiles/LeagueKey.cs` builds it; the frontend mirror is `leagueKeyFor` in `features/leagues/leagueKeys.ts`.
  - `standingsLeaguePath(saveId, leagueId, { season })` opens one season's table for a per-season league id.
  - `cupTeamPath(saveId, 'color' | 'type', teamKey)` opens a team history. A Color team key is the lower-case color name. A Type team key is the creature type exactly as stored. A Type team that never fielded a squad returns 404.
  - `cupEditionPath(saveId, cup, season)` opens one Cup edition. The Chaos Cup table on the profile already links its editions this way.
- `TeamBadge` in `features/cups/TeamBadge.tsx` is the existing team link (swatch plus name).
- The profile API (`features/athletes/athleteApi.ts`, backend `Features/Athletes/GetProfile`) exposes `currentLeagueId`, `currentLeagueKind` and per-season `leagueId`, `leagueLevel` and `feederDivision`. Honours, movements and Cup selections carry names only.

## Requirements

1. **Color** in the identity block and **Sporting color** in the Card detail link to that color's Color Cup team page.
2. A non-empty **Type Cup nationality** links to that creature type's Type Cup team page in both places. **Uncapped** stays plain text.
3. **Current league** links to that league's profile page. A retired or pool athlete shows plain text, as today.
4. Each league row in the season-by-season history links its league name to the league profile. Pool rows stay plain text. The row also offers a link to that league's table for that season.
5. Honour rows link league honours to the league profile. Cup honours link to the Cup edition for that season.
6. Postseason movement rows link both the source and destination leagues to their profiles. The common pool stays plain text.
7. Cup selection rows link the team to its Color or Type team page and the season to the Cup edition.
8. Cup history rows link the team to its team page and the season to the Cup edition.
9. Links use real anchors from the existing router, so Ctrl/Cmd-click and middle-click open a new tab. They keep the current table styling and stay keyboard-focusable with a visible focus state. Text that has no reliable identity stays plain text. Never build a guessed URL.

## Architectural direction

- Any missing identity should come from the backend as additive response fields, such as a `leagueKey` (from `LeagueKey`) on the current league, season rows, honours and movements, and a cup kind and team key on Cup selections. MUST NOT parse league names or display strings to build URLs.
- Keep API changes additive and read-only. Older saves still return valid profiles, and absent fields render as plain text.
- Reuse `TeamBadge` for team links and the existing route builders. A small league-link component may live in `features/leagues` if the next task (MSS-139) can reuse it. Do not add a generic link framework.
- Keep the change inside the athlete profile slice plus the minimal backend DTO/query fields it needs.

## Acceptance criteria

- [ ] On a tiered save, the profile of a feeder athlete with Cup appearances shows links for Color, Current league, every non-pool season league, honours, movements, Cup selections and Cup history. Each opens the correct page.
- [ ] Clicking **Green** opens `/saves/:saveId/cups/color/teams/green`. Clicking a non-empty nationality opens that type's team page. An Uncapped athlete shows no nationality link.
- [ ] Clicking the current league opens its league profile, such as `/saves/:saveId/leagues/feeder-2-green`. A season row's table link opens that league's standings for that season.
- [ ] Pool seasons, the pool side of movements, retired or pool athletes and missing identity fields render as plain text with no broken links.
- [ ] Backend tests cover the new profile fields on a tiered save. Frontend tests cover link targets and plain-text fallbacks.

## Verification

- Run `dotnet test tests/MtgSoloSports.Tests --configuration Release --filter FullyQualifiedName~Athletes` plus the repository-required backend checks in `AGENTS.md`.
- Run `npm test --prefix src/MtgSoloSports.Web`, `npm run typecheck --prefix src/MtgSoloSports.Web`, and `npm run build --prefix src/MtgSoloSports.Web`.
- In a test save, open a feeder athlete's profile and click each new link. Check that Ctrl-click opens a new tab and that Back returns to the profile.

## Out of scope

- Links on other pages (Dashboard, Records, Standings, Live, History, Qualifiers, reveals, athlete search). Those belong to MSS-139.
- Linking each creature type in the **Type** line. Types without a Type Cup team would open a 404 page.
- New pages, route shapes, or changes to league, Cup or team page content.
- Simulation, persistence schema, sporting rules or profile layout redesign.
