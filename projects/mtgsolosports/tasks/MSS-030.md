# MSS-030 — Add save export/import and technical recovery safeguards

## Goal

Make a universe portable and recoverable without turning rewind into a normal gameplay mechanic.

## Context

- Project: `mtgsolosports`.
- Target repository: `AlexBDevCorner/MtgSoloSports`.
- Default branch: `main`.
- Product rules: `docs/game-rules.md` in the target repository.
- Technical constraints: `docs/technical-design.md` and `AGENTS.md`.
- Architecture is vertical-slice modular monolith. **MediatR is forbidden.**
- Keep sporting simulation deterministic and use fixed-point integer arithmetic.

## Requirements

1. Export a complete save as a portable artifact containing the SQLite save database plus any required manifest/version metadata.
2. Import validates schema/rules compatibility and never silently overwrites another save.
3. Add a technical recovery/checkpoint mechanism for migrations or large operations sufficient to restore the last known valid boundary after a software bug/failure.
4. Normal UI must not expose arbitrary rewind/resimulate-as-gameplay behavior.
5. Separate database schema migrations from game-rule version migrations.
6. Before destructive schema migration create/verify a recoverable backup/checkpoint.
7. Add integration tests for export/import round trip and failed migration/import safety.

## Architectural direction

- Treat the SQLite save as the authoritative universe; external artwork cache need not be embedded if references/fallback remain valid.
