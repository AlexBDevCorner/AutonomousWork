# MSS-155 - Decompose the Reports page god component

## Goal

`ReportsPage.tsx` (1,532 lines, ~45 useState hooks) is decomposed into per-section feature components with one reusable picker control, preserving all behavior and styling.

## Context

- A repository review (2026-11-19) verified the following; re-verify on the live checkout.
- `src/MtgSoloSports.Web/src/features/reports/ReportsPage.tsx` is a single 1,532-line component owning seasons, downloads, Google Drive connect, folder/file adoption (x12), publish, verify, and library sync state - roughly 45 `useState` hooks.
- Around `ReportsPage.tsx:663-830+` sit ~10 near-identical inline picker handlers differing only in which state setter they write (`.then/.catch/.finally` chains).
- Reports feature tests exist colocated (`features/reports/*.test.ts`); the page currently works but every new report capability compounds the component.
- AGENTS.md frontend rules: feature-local components preferred, shared UI only after real reuse, dark presentation default, no new component libraries.

## Requirements

1. Extract a single picker helper (control + handler factory) used by all ~10 picker instances; each picker's selection state remains feature-local.
2. Split `ReportsPage` into per-section components within `features/reports` (e.g. downloads, Drive publishing, library), with the page as a thin composition. State lives with the section that owns it; cross-section interactions stay explicit.
3. No visual or behavioral redesign: same layout, styling, labels, error/empty states, reduced-motion behavior. This is a structure-only refactor; DOM output for given data should be equivalent.
4. No shared/ abstractions are created unless at least two features genuinely reuse them (the picker stays in `features/reports` unless reused elsewhere).
5. Keep all existing behavior verifiable: every existing reports test passes unmodified except where a pure rename/move of internals requires import updates.

## Architectural direction

- React 19, no external state/router libraries, plain CSS per feature - preserve the existing architecture exactly. No new dependencies.

## Acceptance criteria

- [ ] `ReportsPage.tsx` drops to a thin composition (target: well under ~300 lines; each section component under ~400).
- [ ] Exactly one picker implementation exists; no near-identical `.then/.catch/.finally` picker handlers remain.
- [ ] All reports tests pass; a before/after DOM-equivalence spot check (existing mounted tests) documents unchanged output.
- [ ] `typecheck` and `build` pass.

## Verification

Standard AGENTS.md web sequence: `npm ci`, `npm run test`, `npm run typecheck`, `npm run build`. Run the reports feature tests alone first, then the full web suite.

## Out of scope

- Hook/fetch consolidation outside `features/reports` (MSS-154), UX redesign, new features, backend changes, and Google Drive publishing behavior changes.
