# MSS-153 - Derive postseason invariant counts from the versioned rules

## Goal

Hardcoded postseason counts that the rules snapshot already owns are derived from the rules, so a future rules version cannot desynchronize invariant gates from actual rule data. Two trivial dead-code items in the same handlers are removed.

## Context

- A repository review (2026-11-19) verified the following; re-verify on the live checkout.
- `src/MtgSoloSports/Features/Seasons/StartNextSeason/StartNextSeasonHandler.cs:359-360`, `Features/Seasons/SeasonLifecycle/PostseasonEvents.cs:113-114`, and `Features/Superleague/GetFeederMovements/GetFeederMovementsHandler.cs:163,179-182` use literal `8`s (colors x boundaries x challengers) in invariant gates, while `SimulationKernel/Rules/RulesV1` already exposes `SportingColorCount` and `OrdinaryQualifierEventCount`.
- The gates currently match the default rules; a future rules version changing color/qualifier counts would break these checks inconsistently - some gates would validate against stale numbers.
- Trivial dead code in the same area: `StartNextSeasonHandler.cs:530` discards a tracked read (`_ = metadata;`); `Features/Simulation/AdvanceRound/AdvanceRoundHandler.cs:705` has a redundant second `SaveChangesAsync` inside `VerifyCommittedAsync` (a no-op noise).

## Requirements

1. Replace the literal `8`s in the listed invariant gates with the rules-derived counts (`SportingColorCount`, `OrdinaryQualifierEventCount`) so gates and rule data come from one source. Audit the two features for any other postseason count literals and derive those too.
2. Keep the gates strict: if a save's persisted rules disagree with what the invariant expects, the mutation still aborts loudly (never silently tolerates).
3. Remove the dead store and the redundant `SaveChangesAsync`.
4. No behavior change for current default rules: the same saves validate identically before and after.

## Architectural direction

- Rules affecting sporting outcomes are stored/versioned with each save (AGENTS.md); gates must read the save's own rules snapshot, not module constants. Vertical slices stay; changes are confined to the named handlers/evaluators.

## Acceptance criteria

- [ ] No postseason count literal remains in the listed gates; all derive from the save's rules snapshot.
- [ ] Handler tests prove the gates still abort on mismatched/missing rows exactly as today.
- [ ] Dead store and redundant save are gone; grep proves no other `_ = metadata;`-style discards in these handlers.
- [ ] Full suite green with unchanged expectations.

## Verification

Standard AGENTS.md backend sequence: locked restore, Release build, full test suite, `dotnet format --verify-no-changes`. Run `StartNextSeason`, `SeasonLifecycle`, and `GetFeederMovements` focused classes alone from a fresh process.

## Out of scope

- Changing any rule defaults or versions, qualifier engine consolidation (MSS-150), corruption failure-class work (MSS-144), and any sporting outcome difference.
