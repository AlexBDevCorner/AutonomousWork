# MSS-060 — Integrate the multi-division pyramid into season flow, standings, history, and Live UX

## Goal

Make the three-division feeder pyramid feel like a first-class part of MtgSoloSports rather than a backend expansion.

Preserve the current quality and interaction model: the season still advances through the same major concepts, existing standings/history/reveal components should be reused where practical, and the larger number of leagues/qualifiers must remain understandable, responsive, and visually clean.

## Context

- Depends on MSS-059.
- Current frontend already has:
  - Dashboard / `SeasonFlow`;
  - global-stage completion and fast-forward controls;
  - league standings/history;
  - promotion/relegation `MovementReveal`;
  - feeder `RebalanceReveal`;
  - Live event presentation;
  - historical qualifier and transition views.
- MSS-053 integrated movement/rebalance reveals into the actual postseason flow.
- The backend will now expose:
  - 24 feeder leagues instead of 8;
  - F1/F2/F3 identity;
  - one Superleague qualifier plus 8 F1↔F2 qualifiers and 8 F2↔F3 qualifiers;
  - tiered movement and structural rebalance cascade.
- The user explicitly wants the **same season steps**, just more leagues and multiple qualifiers.
- Avoid turning the UI into a giant flat list of 24 leagues or 17 qualifiers with no grouping.

## Required player flow

Keep the existing high-level lifecycle recognizable:

1. Stages 1-32 across all active leagues.
2. Final league standings.
3. Resolve automatic promotion/relegation.
4. Resolve/play the required qualifiers.
5. Show the resulting next-tier rosters / movement reveal.
6. Rebalance feeder pyramid / pool if structurally necessary.
7. Color Cup or Type Cup.
8. Finalize/start next season.

The backend may internally persist more granular events, but the Dashboard should not become a confusing 25-step workflow.

## Requirements

1. Update league navigation/standings to present the pyramid clearly.
   - Superleague as its own top level.
   - Feeder 1, Feeder 2, Feeder 3 as explicit sections/tabs/groups.
   - Within each feeder division, group the eight sporting-color leagues consistently.
   - Preserve direct URLs/deep links to a specific league/history view.
   - Do not rely on league-name parsing.

2. Preserve global stage progression UX.
   - One global stage still means every active league must complete that stage before Stage N+1.
   - "Run/complete stage for all leagues" must work across 24 feeders (+ Superleague from Season 2) without forcing the user to click every league.
   - Individual league inspection/simulation remains possible.
   - Loading/progress text should communicate progress without rendering an unwieldy wall of cards.

3. Make bonus level visible where useful but not noisy.
   - League-level explanatory UI/history can state the tier bonus scale (Super 2×, F1 1×, F2 1/2×, F3 1/4×).
   - Do not clutter every score cell with multiplier labels.
   - Existing bonus/effective-bonus displays must remain numerically correct.

4. Generalize promotion/relegation reveal.
   - Reuse `MovementReveal` patterns.
   - Group movement by boundary:
     - F3↔F2;
     - F2↔F1;
     - F1↔Superleague.
   - Within feeder boundaries, group by sporting color.
   - Clearly distinguish automatic movement from qualifier outcomes.
   - Clearly distinguish competitive movement from later structural rebalance.
   - No spaghetti-style connection visualization is required; readable grouped cards/boards are preferred.

5. Add a coherent multi-qualifier experience.
   - The qualifier phase contains 17 ordinary-postseason qualifiers: 1 Superleague, 8 F1↔F2, 8 F2↔F3.
   - Provide a compact overview showing completed/current/pending qualifiers.
   - Allow playing/revealing a specific qualifier on Live.
   - Provide a "run remaining qualifiers" path for fast progression.
   - Running remaining qualifiers must respect backend canonical order and persisted idempotency.
   - A player should not need to navigate back to Dashboard after each qualifier unless they choose to.

6. Reuse the existing qualifier event presentation for both 32-athlete and 16-athlete fields.
   - Field size, incumbent/challenger labels, source/destination tier, color, rounds, and top-8 cutoff must come from data.
   - Do not clone separate pages per feeder division.

7. Generalize `RebalanceReveal`.
   - Show the per-color cascade through F1/F2/F3.
   - Make it visually obvious that pool connects only to F3.
   - Show structural up/down movements, F3 pool draws, and F3 pool displacements using persisted facts.
   - Preserve progressive first-time reveal, historical final-state view, replay, reduced-motion behavior, and responsive layout.
   - Existing high-quality reveal interactions from MSS-050/MSS-051/MSS-053 should be retained.

8. Update history surfaces.
   - Season history must distinguish F1/F2/F3 championships and standings.
   - Athlete league history must show the division for each season.
   - Movement history must show adjacent-tier source/destination and whether movement was automatic, qualifier-based, or structural rebalance.
   - Qualifier history must identify boundary/color so multiple qualifiers in one transition are unambiguous.
   - Existing v1 historical seasons should still display as their original single feeder level/F1-compatible history.

9. Update search/filter/read-model labels where league membership is exposed.
   - Athlete search league filters should distinguish Superleague/F1/F2/F3/current pool where appropriate.
   - Do not break existing route/query-string behavior.

10. Preserve Cup UX and sporting data.
    - Color/Type Cup flows remain in the same postseason position.
    - Cup selection may consume the new current active bonus values but no Cup format/UI redesign is required.
    - Existing Cup history/pages must remain functional.

11. Handle scale deliberately.
    - Avoid fetching/rendering all detailed standings for all 24 feeder leagues when only summaries are needed.
    - Use existing targeted endpoints/React Query patterns.
    - Keep Dashboard/Standings interactions responsive on desktop and narrow mobile widths.
    - Avoid a giant DOM of all qualifier standings simultaneously; load details on demand.

12. Update documentation and frontend tests for the new terminology and navigation.

## Architectural direction

- Reuse current components with data-driven tier/boundary models instead of creating F1/F2/F3 copies.
- Add shared formatting helpers for league level and boundary labels.
- Treat qualifier and movement identity as route data, not implicit "latest Superleague qualifier".
- Preserve progressive reveal components as presentation over persisted backend facts only.
- Maintain accessibility: meaningful text labels, keyboard-operable controls, reduced-motion support, no color-only status encoding.

## Acceptance criteria

- [ ] Dashboard preserves the recognizable season lifecycle and does not expose 17 qualifiers as 17 unrelated top-level season steps.
- [ ] Standings/navigation clearly expose Superleague + F1/F2/F3 and all eight colors per feeder level.
- [ ] Global stage completion works across the expanded league count.
- [ ] A specific feeder league remains directly navigable.
- [ ] Promotion/relegation reveal groups movements by boundary/color and distinguishes automatic vs qualifier results.
- [ ] Multi-qualifier overview shows completion state and supports individual Live viewing plus "run remaining".
- [ ] The same qualifier UI supports 32-athlete Superleague and 16-athlete feeder qualifiers.
- [ ] Rebalance reveal shows F1↔F2↔F3 cascade and Pool only at F3.
- [ ] Athlete/season/qualifier/movement history identifies feeder division correctly.
- [ ] Existing v1 history remains understandable and unchanged.
- [ ] Cup pages and postseason order remain intact.
- [ ] Responsive/mobile layouts remain usable despite the larger league/qualifier count.
- [ ] No reveal resimulates sporting results.
- [ ] Frontend tests/typecheck/build pass.

## Verification

Run:

```bash
npm ci --prefix src/MtgSoloSports.Web
npm run test --prefix src/MtgSoloSports.Web
npm run typecheck --prefix src/MtgSoloSports.Web
npm run build --prefix src/MtgSoloSports.Web
```

Also run the standard backend suite because API/read-model changes are expected.

Manual/end-to-end verification:
1. Create a fresh tiered save and inspect F1/F2/F3 standings.
2. Complete at least one global stage and verify all active leagues progress correctly.
3. Complete a season and inspect automatic movement across every boundary.
4. Play one feeder qualifier manually on Live, then run the remaining qualifiers.
5. Inspect the movement reveal and confirm no athlete moves more than one level.
6. Inspect a structural color rebalance and confirm pool movement appears only at F3.
7. Complete the Cup and start the next season.
8. Inspect athlete history for an athlete that changed divisions.
9. Open an existing v1 save/history and verify old seasons remain readable.
10. Check desktop, tablet, and phone-width layouts for Dashboard, Standings, qualifier overview, movement reveal, and rebalance reveal.

## Out of scope

- New sporting rules beyond MSS-056–MSS-059.
- Different prestige values per feeder division.
- New Cup formats.
- 3D/bracket-style visualization or animated network graphs.
- Replacing React Query/routing architecture.
