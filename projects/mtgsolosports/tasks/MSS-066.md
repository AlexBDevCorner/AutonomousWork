# MSS-066 — Validate and calibrate tier-aware Cup selection across long-running saves

## Goal

Verify that the redesigned Cup selection rating behaves plausibly over many seasons before changing any top-level weights.

Provide durable diagnostics showing how Superleague/F1/F2/F3 athletes score and get selected for Color Cup and Type Cup, make individual selection decisions explainable, and establish regression scenarios that prevent obvious league-strength inversions.

The task should produce evidence for future tuning, not dynamically rebalance the game or force artificial representation quotas.

## Context

- Depends on MSS-065.
- After MSS-064/MSS-065 the selection model remains:
  - 35% effective bonus;
  - 30% league-adjusted current-season performance;
  - 25% league-adjusted current form;
  - 10% league-aware career prestige.
- Performance/form strength factors begin at Super/F1/F2/F3 = 1.00/0.80/0.60/0.40.
- Bonus generation already uses the stronger Super/F1/F2/F3 = 2/1/1/2/1/4 hierarchy.
- Prestige separately values competition level.
- Because those signals overlap intentionally but differently, long-run behavior must be measured rather than guessed.
- Existing `CupSelectionReports` already persist raw/normalized/final component values and are the natural source for explainability/calibration.
- The project already has an opt-in long-run harness and diagnostics under `tests/.../Diagnostics` / `docs/long-run-baseline.md`.

## Requirements

1. Add an opt-in Cup-selection calibration diagnostic on top of the existing long-run harness or an equivalent deterministic test harness.
   It must be able to simulate a configurable multi-season tiered save using a catalog with enough creature-type diversity to exercise both Color Cup and Type Cup.

2. Collect per-Cup and aggregate statistics by the athlete's **source-season league level**:
   - candidate count;
   - selected athlete count;
   - Color Cup top-four selections;
   - Type Cup allocated squad places;
   - average/median final rating where practical;
   - average normalized bonus/performance/form/prestige components;
   - selected vs nearest-miss component breakdown;
   - number/rate of lower-tier athletes selected ahead of higher-tier candidates.

3. Distinguish lower-tier success from pathological inversion.
   The diagnostic should make examples inspectable rather than enforcing quotas:
   - F2/F3 athletes are allowed to make Cup squads;
   - no league receives guaranteed representation;
   - Superleague athletes are not guaranteed selection merely because of tier;
   - exceptional lower-tier form/performance/history can beat poor higher-tier candidates.

4. Add deterministic synthetic regression scenarios protecting the intended ordering:
   - with otherwise identical sporting inputs, higher league strength produces higher adjusted performance/form;
   - an F3 champion is not automatically equivalent to an F1 champion;
   - an exceptional F2/F3 season can outrank a sufficiently weak higher-tier season;
   - a former Superleague star now in a lower tier can remain competitive via bonus/prestige while those signals decay/are outweighed over time;
   - a long-term Pool athlete cannot retain stale recent-form advantage.

5. Do **not** introduce an absolute league-priority rule.
   - No "Superleague always beats F1" comparator.
   - No minimum/maximum Cup places per tier.
   - No forced diversity quota by league.

6. Keep the outer 35/30/25/10 weights fixed in this task.
   - Record them in diagnostics.
   - If results look questionable, document the evidence and candidate follow-up tuning rather than silently changing them.

7. Keep the initial performance/form strength factors fixed at 1000/800/600/400 in this task.
   - The diagnostic should make future factor changes easy to evaluate.
   - Do not auto-tune factors from observed selection distribution.

8. Extend the user-facing selection explanation where practical so the existing "why selected" experience can communicate tier context.
   For shortlisted candidates show enough information to understand:
   - source league/tier;
   - tier factor;
   - adjusted performance/form;
   - prestige summary;
   - final normalized components/rating.
   Reuse existing Color/Type selection report UI rather than building a new analytics screen solely for players.

9. Add a developer-facing calibration report/document generated from a representative deterministic run.
   At minimum summarize:
   - run seed and season count;
   - Cup editions observed;
   - selection distribution by source tier;
   - notable cross-tier selections/near-misses;
   - whether any component dominates unexpectedly;
   - known limitations of the synthetic catalog/run.

10. Ensure diagnostics do not alter sporting state or production behavior when disabled.
    - Long-run calibration remains opt-in/outside normal CI if too expensive.
    - Fast deterministic unit/regression scenarios remain in normal CI.

## Architectural direction

- Reuse persisted selection reports rather than recomputing old ratings from current career state.
- Prefer diagnostic aggregation over adding production database projections solely for benchmarking.
- Keep the system transparent: if a lower-tier athlete is selected, the report should make it obvious whether bonus, current performance, form, or prestige caused it.
- This task is validation and observability. Do not let the autonomous implementation invent balancing quotas because a distribution "looks uneven."

## Acceptance criteria

- [ ] A deterministic multi-season calibration run can report Color/Type Cup selections by Super/F1/F2/F3.
- [ ] Reports include normalized component distributions and selected/near-miss examples.
- [ ] Synthetic tests protect both league-strength hierarchy and legitimate lower-tier upsets.
- [ ] Pool athletes have no stale-form selection advantage.
- [ ] No tier quota or absolute tier-priority rule is introduced.
- [ ] Outer weights remain 35/30/25/10.
- [ ] Performance/form factors remain 1000/800/600/400.
- [ ] User-facing selection explanations expose league/tier-adjusted inputs.
- [ ] A documented representative calibration run exists with reproducible seed/configuration.
- [ ] Diagnostics are opt-in and do not slow normal gameplay/CI materially.

## Verification

1. Run normal backend/frontend tests.
2. Run the synthetic cross-tier selection regression suite in normal CI.
3. Run the opt-in calibration harness for at least 20 seasons; prefer 50+ where runtime permits.
4. Repeat with the same seed and assert identical aggregate/result checksums.
5. Run at least one different seed and compare whether conclusions are robust rather than seed-specific.
6. Inspect both Color Cup and Type Cup examples where a lower-tier athlete beats a higher-tier athlete and confirm the component explanation justifies it.
7. Inspect high-performing F3 champions that miss selection and verify they are not being treated as equal to equivalent F1/Superleague performance.
8. Verify player selection-report UI remains responsive and old reports still render.

## Out of scope

- Automatically changing weights/factors based on diagnostics.
- Guaranteed Cup representation by league.
- Reworking Type Cup team-allocation nationality rules.
- Changing promotion/relegation.
- Adding an Elo/strength-of-schedule system.
