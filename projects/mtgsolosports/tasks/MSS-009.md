# MSS-009 — Complete stages, standings and bonus activation

## Goal

Implement the 16-round stage lifecycle, stage ranking, championship points and next-stage bonus activation semantics.

## Context

- Project: `mtgsolosports`.
- Target repository: `AlexBDevCorner/MtgSoloSports`.
- Default branch: `main`.
- Product rules: `docs/game-rules.md` in the target repository.
- Technical constraints: `docs/technical-design.md` and `AGENTS.md`.
- Architecture is vertical-slice modular monolith. **MediatR is forbidden.**
- Keep sporting simulation deterministic and use fixed-point integer arithmetic.

## Requirements

1. Allow 16 legal rounds to accumulate into a stage score for all 32 athletes.
2. At stage completion rank athletes using deterministic tie-break rules and persist StageStanding rows.
3. Award championship points with the same 32-position table and no bonus multiplier.
4. Accumulate round and stage bonus earned during the stage as pending contribution; it must not affect any round in that same stage.
5. Activate the completed stage's pending bonus only for the next stage boundary.
6. Record stage placement counts/wins needed for season tie-breaking and career projection later.
7. Add a complete-stage command that is sporting-result equivalent to sixteen individual `AdvanceRound` operations from the same start state.
8. Add focused tests including Stage 32 pending-bonus behavior.

## Architectural direction

- Keep pure ranking/bonus math in `SimulationKernel`; orchestration/persistence stays in the stage slice.
