# MSS-088 — Create season journalism dossiers and a universe historical almanac for ChatGPT

## Goal

Enable one-click download of coherent, factual MtgSoloSports source packs so a ChatGPT Project can cover a season, report on a recent stage, and compare achievements to the universe's history. Provide curated reports that are comprehensive enough for a sports journalist but compact enough to upload, browse and replace as the save advances.

## Context

- Project `mtgsolosports`; target `AlexBDevCorner/MtgSoloSports` (`main`).
- Depends on completed MSS-086 and MSS-087, which supply versioned read-only Markdown/JSON export contracts for athlete, standings, Cup, team and league reports.
- MtgSoloSports has persistent leagues including Superleague and feeder divisions, 32 league stages per season under current rules, promotions/relegations/qualifiers, Color Cup individual/team events, Type Cup qualification and Final, athlete careers, records and a weighted Career Leaders measure.
- User wants ChatGPT to function as a longtime sports columnist, recognizing streaks, upsets, rivals, historical firsts, championship races, qualification cut lines and changing athlete fortunes; copying dozens of UI panels is impractical.
- ChatGPT Project sources are uploaded/reference snapshots, not a live database mirror. Packs need explicit version/scope and freshness, and should be reasonably sized. They should provide **facts and evidence, not prewritten AI opinions**.

## Requirements

1. Add a compact **Reports / Export data** entry or panel (consistent with app navigation) offering at least two types of download for the active save:
   - **Season dossier:** selected season (including currently active season).
   - **Universe almanac:** all-time historical index, current as of the saved snapshot.
   Both types support human-readable **Markdown** and structured **JSON** using the same versioned contract as MSS-086/087. The UI exposes season selection, clear coverage description, download/error state, and fresh export on demand.
2. **Season dossier must include** save/universe and season identifiers, progression snapshot (last completed stage, current competition/phase), appropriate final vs provisional labels, season-wide Superleague standings with full ranking/points, meaningful stage-by-stage Superleague results/progression supported by persisted results, relegation/promotion/qualification outcomes or pending status, and concise league summaries for other feeder leagues. Include all completed major Cup editions associated with that source season (or clearly say not yet held) with individual/team results, Type Cup qualification groups and Final distinction, medals, historically correct rosters where available. Do not present an incomplete Cup as final.
3. Include enough *historical perspective* to support accurate storytelling: previous-season champion(s), recent finish trends/standings changes, defending champions, athlete career/title history relevant to current leaders and major Cup performers, official record holders and notable historical comparisons that can be computed exactly. If a comparison is not stored/derivable, omit it rather than hallucinating. Explicitly label facts, time windows and competition scope.
4. **Universe almanac** must offer a curated, all-time reference: season champions/podiums for Superleague and other leagues as appropriate, Color/Type Cup medal history, important records with scope/holders, all-time Career Leaders **with clearly labelled weighted career points** and league-specific points leaders as different statistics, notable consecutive title streaks and historically grounded career achievements. Cover inactive athletes as well as active ones.
5. Control report size by design: curated summaries/projections, not complete compressed round payloads, card artwork or every athlete's every placement. Do not arbitrarily omit official standings rows in explicitly labelled full tables. Provide clear scope/coverage metadata and predictable file names; expose **only existing authoritative results** and deterministic facts, not unrequested raw SQL tables.
6. Include a prominent **snapshot/coverage header** in each report: save ID, report type, schema version, season range, last finished stage and event phase where relevant, generated timestamp (metadata only), and an optional stable source-state fingerprint/checksum if already available. Make it obvious that uploads become stale as simulation progresses.
7. Markdown should be clean, navigable and explain scoring/term distinctions (official points vs weighted career points; group vs final; team vs individual; provisional vs official) without needing the UI. JSON must retain stable IDs, clear event keys, typed values/units, and source status for downstream machine analysis; report types should be consistently versioned.
8. Use existing per-save persisted query/projection code and read-only consistent snapshots. Avoid N+1 loading of hundreds of profiles, expensive all-history decompression and loading all raw placement payloads in memory. All report content must derive from durable data with stable deterministic ordering; generation must not mutate a universe, advance events or use sporting RNG.
9. Add an in-app explanation/workflow: export the almanac occasionally as an updated reference source and a fresh season dossier for new coverage; users can attach these to a ChatGPT Project or chat. Do not claim the app synchronizes project knowledge automatically. Optionally provide a short, copyable example journalist prompt as help text; don't build AI narrative generation into the application.
10. Test partial/early seasons, historical completed seasons, multi-season saves, legacy formats, ongoing league stages and Cup stages, empty optional data, tied ranks and non-Superleague champions. Handle data not yet computed explicitly, rather than inferring sporting events.

## Architectural direction

- Implement focused report handlers/aggregators reusing existing history, stage/standings, Cup, qualifier, records, leagues and Career Leaders projections. Keep Endpoint → Handler with no MediatR.
- Prefer two bounded dossier/almanac queries rather than a general-purpose query language or a collection of arbitrary report filters.
- Snapshot data should be *journalism ready* without constructing claims about unplayed stages; distinguish facts from derived comparisons and specify scope/season.
- Reuse report metadata/format and download plumbing from MSS-086/087. Only add a reports UI surface and small read-side projections; preserve all simulation and backup contracts.

## Acceptance criteria

- [ ] From a multi-season save, user can download a single readable season Markdown dossier and valid structured JSON dossier for a chosen season.
- [ ] Dossier includes full Superleague table, completed stage progress/highlights, league/qualifier/Cup context, and explicit incomplete or unavailable states with correct season linkage.
- [ ] Type Cup qualification and Final, Color Cup individual vs team, and championship/record contexts are not conflated.
- [ ] Historical almanac exports all-time reference material incl. champions, medals, records, career and league leaders, with clear definitions and coverage.
- [ ] Reports surface useful historical context (defending champions, recent achievements/trends, streaks) with identifiable sources and no fabricated facts.
- [ ] Metadata makes report source, season scope, status and freshness unambiguous; generated outputs have predictable filenames.
- [ ] Reporting works for completed and in-progress seasons, survives historical league structure differences, and is read-only.
- [ ] Formats agree on sporting numbers, standings, athletes, season associations, and status.
- [ ] Large-save performance stays practical using bounded data projections; tests cover deterministic content and efficient reads.
- [ ] The UI explains how to attach/refresh reports manually in a ChatGPT Project and makes no false sync promises.

## Verification

Run backend/React build, test, type-check and format gates from `AGENTS.md`. Generate and inspect Markdown + parsed JSON for (a) a long-running save's current mid-season, (b) a completed historical season with leagues, promotion and both Cups, (c) a season where Type Cup qualification is partially finished, and (d) early/legacy season missing later feeder tiers. Cross-check report ranks/points/champions/qualifier fields against existing API queries. Assert no save mutation and verify generation does not require Scryfall/network access. Validate that exported filenames, headers, status and relevant past-season context make sense when reports are read independently of the UI.

## Out of scope

- General SQL/report-query editor, custom dashboard/pivot builder, arbitrary report builder or direct SQLite download as a ChatGPT report.
- Built-in LLM, auto-written articles, AI-generated stories or heuristic claims not grounded in recorded statistics.
- Live ChatGPT connector, MCP server, hosted API, cloud export/sync, automatic upload/project-file replacement or credential management.
- Broad database migrations or caching systems solely to generate exports, redesigning Athlete/Cup/Standings pages, and any changes to sport simulation or scored outcomes.
