# MSS-021 — Add structured deterministic story events

## Goal

Generate lightweight sporting narratives from meaningful state transitions without AI affecting the simulation.

## Context

- Project: `mtgsolosports`.
- Target repository: `AlexBDevCorner/MtgSoloSports`.
- Default branch: `main`.
- Product rules: `docs/game-rules.md` in the target repository.
- Technical constraints: `docs/technical-design.md` and `AGENTS.md`.
- Architecture is vertical-slice modular monolith. **MediatR is forbidden.**
- Keep sporting simulation deterministic and use fixed-point integer arithmetic.

## Requirements

1. Persist structured story events for at least first stage win, first league title, first Superleague appearance, promotion, relegation, return from pool and notable repeat-title milestones available at this stage.
2. Store event type and structured context rather than only rendered prose.
3. Render deterministic authored text templates in API/UI.
4. Emit events transactionally with the sporting operation that causes them and avoid duplicates on retries/reloads.
5. Expose recent stories on the dashboard and athlete profile where relevant.
6. Design the event model so future Cup/record tasks can add types without changing old events.

## Architectural direction

- No LLM/API dependency. AI may only be an optional future presentation layer over structured events.
