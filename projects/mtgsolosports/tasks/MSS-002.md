# MSS-002 — Implement versioned rules and deterministic RNG primitives

## Goal

Create the stable deterministic foundation that every sporting simulation slice will depend on.

## Context

- Project: `mtgsolosports`.
- Target repository: `AlexBDevCorner/MtgSoloSports`.
- Default branch: `main`.
- Product rules: `docs/game-rules.md` in the target repository.
- Technical constraints: `docs/technical-design.md` and `AGENTS.md`.
- Architecture is vertical-slice modular monolith. **MediatR is forbidden.**
- Keep sporting simulation deterministic and use fixed-point integer arithmetic.

## Requirements

1. Represent the complete Game Rules v1 constants in strongly typed versioned rule objects, including scoring table, round/stage bonus tables, decay, league sizes, stage/round counts and Cup selection weights.
2. Implement a small explicit versioned deterministic PRNG (for example PCG32 v1) with serializable state.
3. Provide deterministic Fisher-Yates shuffle functionality that consumes only this RNG.
4. Use fixed-point integer value types/primitives for points, bonus and weighted scores; no `double` or `float` in sporting calculations.
5. Add golden tests proving identical seed/state produces identical random sequence and shuffle.
6. Add validation that a Rules v1 snapshot is internally consistent and immutable from simulation code.

## Architectural direction

- `SimulationKernel` must remain pure and have no EF Core, HTTP, filesystem, clock or network dependency.
- No direct `Random.Shared`, `new Random()`, GUID ordering or wall-clock entropy anywhere in sporting code.
