# MSS-037 — Default live-event card reveal to manual progression

## Goal

Make a newly completed **Live event** reveal manual by default. The fun should come from choosing when to turn over each card, not from an automatic timer immediately revealing the entire field. Keep automatic playback available as an intentional action.

## Context

- Project: `mtgsolosports`; target repository: `AlexBDevCorner/MtgSoloSports`; default branch: `main`.
- Existing shared presentation: `src/MtgSoloSports.Web/src/features/reveal/RoundReveal.tsx` calls `useRoundReveal.ts`. `LivePage.tsx` and `HistoryPage.tsx` both render `RoundReveal`; preserve the shared implementation.
- Currently, `useRoundReveal.ts` initializes to `animated` by default (unless reduced motion or a stored mode preference overrides it), and the new-`revealKey` effect starts playing immediately for animated mode. Its `setMode('animated')` and `replay()` paths also auto-start. This makes live results uncover cards without the user doing anything.
- The existing controls already include Play/Pause, Restart, step -1/+1, Show all, speed, and Instant/Animated mode. Prefer reusing these, not introducing an unrelated reveal mechanism.
- Follow `AGENTS.md`, `docs/game-rules.md`, and `docs/technical-design.md`. Backend remains direct Endpoint → Handler, no MediatR. This task is frontend presentation only.

## Requirements

1. A newly available completed round in **Live event** must start in a **paused, manual progressive reveal** state for users without a reduced-motion preference: 0 cards revealed and no timer running. It must not automatically reveal cards simply because the stored mode is `animated`, a previous round was playing, or the component mounts/remounts.
2. The existing `+1` button becomes the natural default action: each activation reveals exactly one additional card in the established lowest-finisher-to-winner order and leaves playback paused. `-1` removes one revealed step and remains paused. Show accurate progress and pending cards without spoiling unrevealed results.
3. Automatic one-by-one reveal must still be available via an **explicit Play** action. Pause, Resume, playback speed, Show all and the rest of the existing controls must continue working as expected. Restart on the manual Live flow should rewind to 0 **without starting autoplay**; after Restart, the user can step or explicitly press Play again. Switching from Instant back to Animated on Live must not start autoplay by itself.
4. When navigating to the next newly completed Live round (a new `revealKey`), stop any playback from the prior round and initialize the new round paused at 0. Do not let timer callbacks from the previous round reveal cards in the new one.
5. Distinguish **presentation mode** (`instant` versus `animated` progressive) from **playback state** (manually paused versus playing). A persisted `animated` preference must not imply permission to autoplay a Live round. Preserve an explicitly chosen `instant` preference if present, where showing all at once is the user's deliberate alternative. Keep existing preference storage compatible; avoid a new global setting unless strictly necessary.
6. Preserve accessibility: users with `prefers-reduced-motion` should continue receiving the existing instant/no-motion experience rather than being forced into an animated reveal. Update visible control text or brief helper text, where useful, so users understand that manual stepping is the default and Play starts autoplay.
7. The **History replay** uses the same `RoundReveal` component. Keep its current playback behavior unless a shared change is unavoidable; prefer a small explicit Live-only option passed to the shared component/hook instead of duplicating the reveal UI. Don't regress history navigation or exact replay.
8. This is a **presentation-only** adjustment over immutable persisted round placements. Do not resimulate events, consume RNG, change standings/scoring, mutate saves, or alter the reveal board layout from MSS-035.

## Architectural direction

- Inspect the current `useRoundReveal` initialization, its new-round effect and the `setMode`/`replay` transitions. Use a narrowly scoped option (such as `autoPlayOnStart: false` for Live) or equivalent explicit state transition, rather than globally removing features or duplicating the hook.
- Ensure mode/speed preferences remain distinct from auto-play authorization; a new round must never inherit an in-progress timer.
- Preserve the existing lowest-to-winner ordering, `RevealBoard`, progress, fixed-point formatting and shared UI. Any new option should have a clear default to avoid accidentally changing History.

## Acceptance criteria

- [ ] On the Live page with no saved reveal preference and normal motion settings, a newly completed round initially shows 0/N revealed, Play available, and no cards flip until a deliberate user action.
- [ ] Reopening Live with a stored `animated` preference still starts each newly completed round **paused**, not autoplaying; moving from an already-playing round to a new round also starts paused.
- [ ] Live `+1` reveals exactly one card per click, Live `-1` steps back one, and both leave the reveal paused.
- [ ] Live Play initiates automatic lowest-to-winner progression; Pause/Resume and speed controls work. Live Restart and switching from Instant to Animated reset to a manual, paused state rather than secretly triggering Play.
- [ ] Instant/Show all explicitly display complete persisted results without a timer. An explicitly stored Instant preference and reduced-motion accessibility behavior remain intact.
- [ ] History replay retains its existing initial and playback semantics; both pages keep using the shared reveal component.
- [ ] Add focused automated coverage for Live initial state, stored-mode behavior, new-round reset, step/restart/mode transitions, opt-in Play, and History/reduced-motion regression as practical. No backend calls or mutations are introduced.
- [ ] Full repository verification succeeds.
