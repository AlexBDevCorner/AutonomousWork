# MSS-011 — Build the initial dark UI shell and save/dashboard navigation

## Goal

Replace the seed screen with the first real browser experience for selecting a save and viewing the current sporting state.

## Context

- Project: `mtgsolosports`.
- Target repository: `AlexBDevCorner/MtgSoloSports`.
- Default branch: `main`.
- Product rules: `docs/game-rules.md` in the target repository.
- Technical constraints: `docs/technical-design.md` and `AGENTS.md`.
- Architecture is vertical-slice modular monolith. **MediatR is forbidden.**
- Keep sporting simulation deterministic and use fixed-point integer arithmetic.

## Requirements

1. Organize React code by vertical frontend features rather than technical folders.
2. Add save list/create/open UI using existing save APIs.
3. Create the dark sports-database visual shell, main navigation and current save/season/stage header.
4. Add dashboard cards for current competition state, league roster/pool counts and the next available simulation action from currently implemented backend data.
5. Handle empty/no-catalog/no-save states clearly.
6. Keep API access in feature-local hooks and introduce shared UI only for proven reusable primitives.
7. Add lightweight frontend tests only if the repository's foundation supports them; otherwise ensure typecheck/build coverage and keep behavior simple.

## Architectural direction

- Do not add a heavy global state framework unless a concrete requirement demands it.
- No MTG/Wizards UI cloning.
