# MSS-131 - Release SQLite test handles before deleting Windows fixture directories

## Goal

Release SQLite test handles before deleting Windows fixture directories while preserving existing save data and unrelated behavior.

## Context

- Project: `mtgsolosports`; target: `AlexBDevCorner/MtgSoloSports`.
- Bug scan on 2026-11-03, audited [main revision 321eb36](https://github.com/AlexBDevCorner/MtgSoloSports/tree/321eb367316252ad259aea6b2fc66cc1ce08b6a1). Line numbers refer to that revision.
- The normal Release backend suite on Windows fails in many finally/cleanup blocks with IOException: catalog.db or a GUID-named save database is being used by another process. Examples include ImportFromScryfallHandlerTests.EmptyDownload_LeavesCatalogIntact at line 119, AdvanceRoundApiTests.AdvanceRound_UnknownSave_ReturnsNotFound_UnknownLeague_ReturnsConflict at line 72, and TypeCupOver32Tests.Run_ThirtyTwoTeams_ScoringMatchesLeagueTable at line 167. These sites call Directory.Delete(root, recursive:true) without draining disposed SQLite pools. TestSaveStores.DeleteRoot already exists, but many tests bypass it. Cleanup exceptions can mask the assertion or application exception and leave temporary roots behind. This is separate from production SaveStore's file-sharing defect in MSS-125.

## Requirements

1. Audit backend fixture cleanup for pooled save and catalog connections, and make Windows directory deletion reliable after hosts/contexts/transactions have been disposed.
2. Reuse the established cleanup helper where appropriate, including existing factory-based fixtures. Do not add a parallel fixture framework or mask IOException with unconditional catches.
3. Keep independent tests isolated. Handle pool cleanup safely with the suite's parallel execution and ensure cleanup cannot conceal an original test failure.
4. Preserve every named test's assertions, deterministic seeds, coverage, lifecycle trigger and normal CI eligibility. Add only focused cleanup coverage where it demonstrates behavior; do not optimize by skipping tests.

## Architectural direction

Inspect tests/Features/TestSaveStores.cs:DeleteRoot, ImportFromScryfallHandlerTests, AdvanceRoundApiTests, TypeCupOver32Tests and other direct Directory.Delete(root...) sites. Follow docs/testing.md and retain prepared-save isolation. Distinguish production file I/O failures, owned by MSS-125, from test-owned cleanup failures. Follow target AGENTS.md and docs/testing.md; direct vertical slices, deterministic sporting math, no MediatR.

## Acceptance criteria

- [ ] Representative catalog, API and Cup classes run alone on Windows without cleanup IOException.
- [ ] Windows suite cleanup no longer masks assertion failures or leaks test roots.
- [ ] Parallel tests retain isolated databases and deterministic assertions.
- [ ] Linux tests and existing correctness coverage remain intact.

## Verification

Run the three named representative classes individually from fresh processes on Windows, then the normal Release backend suite with TRX and inspect failures by their real cause. Run the Linux suite. Report any remaining production failures separately rather than labeling every backend failure a cleanup problem.

## Out of scope

No production storage changes, test assertion removal, serializing the entire suite, skipping Windows tests, broad performance optimization or changes to autonomous task execution.
