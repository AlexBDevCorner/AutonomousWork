# MSS-001 — Harden the repository quality and test foundation

## Goal

Turn the seed repository into a reproducible build/test baseline suitable for unattended autonomous changes.

## Context

- Project: `mtgsolosports`.
- Target repository: `AlexBDevCorner/MtgSoloSports`.
- Default branch: `main`.
- Product rules: `docs/game-rules.md` in the target repository.
- Technical constraints: `docs/technical-design.md` and `AGENTS.md`.
- Architecture is vertical-slice modular monolith. **MediatR is forbidden.**
- Keep sporting simulation deterministic and use fixed-point integer arithmetic.

## Requirements

1. Add `tests/MtgSoloSports.Tests` using xUnit and a small assertion library; add it to `MtgSoloSports.slnx`.
2. Introduce Central Package Management entries for all .NET dependencies and commit NuGet lock files so `dotnet restore --locked-mode` works.
3. Add the curated analyzer baseline: built-in .NET analyzers plus Meziantou.Analyzer and xUnit analyzers, with development-only/private asset configuration.
4. Generate and commit the frontend `package-lock.json`; change CI to `npm ci`.
5. Strengthen `.editorconfig` only with a conservative set of deterministic correctness/maintainability rules. Do not import a giant opinionated ruleset.
6. Update CI so restore/build/test/format and frontend install/typecheck/build are mandatory.
7. Add at least one backend smoke test for `/api/health` or the application composition baseline without introducing a layered test architecture.

## Architectural direction

- Preserve the single backend production project and vertical-slice layout.
- Do not add MediatR, generic repositories, Domain/Application/Infrastructure projects or unrelated frameworks.
- Numeric `AnalysisLevel` remains pinned; warnings remain errors.
