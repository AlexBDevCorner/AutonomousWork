# MSS-118 — Calibrate Chaos fairness and Cup selection impact

## Goal

Provide opt-in deterministic multi-season measurement of agreed rules without automatic retuning.

## Context

- Project `mtgsolosports`, target `AlexBDevCorner/MtgSoloSports` (`main`). .NET + React, direct vertical-slice Endpoint → Handler, no MediatR; follow `AGENTS.md`. Approved Chaos Cup: 8 sporting colors, 1024 entrants (all source-season league athletes plus random Pool invitations), six 32-athlete group stages [32,16,8,4,2,1], top 16 from each nonfinal group; 16 game rounds per group, active bonus used but not earned; no league points/promotion, group scores reset; first draw exactly 4/color/group, later draws pure random. Runs after 32 league stages and before promotion qualifiers, only for a new season after deployment; odd/even Color/Type Cups keep alternating. Existing sporting history must remain unchanged.
- Scope: **Calibrate Chaos fairness and Cup selection impact**. This is a single small PR, target roughly 200–600 changed lines where practical; if work expands materially, propose follow-up rather than bundling unrelated features.
- Dependencies: MSS-103, MSS-104, MSS-105, MSS-106; tasks with incomplete dependencies must wait.

## Requirements

1. Add optional (not default CI) 50+ season simulation harness/checksum with 8 colors, 1024 entrants and all stage sizes.
2. Report medals/finalists by source tier/Pool and color, 450-weight champion versus Super/Color/F1 careers, and attributable effects of 5% Chaos form on Color/Type team selection.
3. Include targeted tests for five P6 Superleague careers, Pool champion later in F3, Final P32 versus fifth-stage exit and manually interleaved vs bulk-group RNG equivalence.
4. Record readable calibration evidence and any suggested changes separately; never silently modify approved numbers.

## Architectural direction

- Reuse existing feature/simulation/report patterns; keep deterministic integer calculations, save-scoped state and clear compatibility boundaries. Do not introduce MediatR or unrelated refactors.

## Acceptance criteria

- [ ] Harness yields reproducible reports and ordinary CI stays fast.
- [ ] Initial 35/30/20/5/10 and career weight 450 remain unchanged.

## Verification

`dotnet build MtgSoloSports.slnx --configuration Release` and `dotnet test MtgSoloSports.slnx --configuration Release` from target root. Add focused regression tests for the task's acceptance criteria and validate compatibility with prior editions. 

## Out of scope

- No automatic sports balancing or wholesale UI redesign.
- Do not implement any other task or modify unrelated history/data merely for convenience.
