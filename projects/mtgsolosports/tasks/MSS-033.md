# MSS-033 — Fix local NuGet NU1507 restore failures with multiple package sources

## Goal

Make a clean local clone of MtgSoloSports restore, build, and test successfully on a developer machine that has additional NuGet package sources configured globally, without weakening repository warnings-as-errors or Central Package Management.

## Context

- Project: `mtgsolosports`.
- Target repository: `AlexBDevCorner/MtgSoloSports`.
- Default branch: `main`.
- Product rules: `docs/game-rules.md` in the target repository.
- Technical constraints: `docs/technical-design.md` and `AGENTS.md`.
- Architecture is vertical-slice modular monolith. **MediatR is forbidden.**
- Keep sporting simulation deterministic and use fixed-point integer arithmetic.

## Reproduction

On Windows / Visual Studio, the developer has two configured NuGet package sources: `nuget.org` and `SD`. Visual Studio shows two NU1507 errors (warnings treated as errors), one for `src/MtgSoloSports/MtgSoloSports.csproj` and one for `tests/MtgSoloSports.Tests/MtgSoloSports.Tests.csproj`:

> There are 2 package sources defined in your configuration. When using central package management, map your package sources with package source mapping or specify a single package source. The following sources are defined: nuget.org, SD.

The project uses `Directory.Packages.props` for Central Package Management, `Directory.Build.props` with `TreatWarningsAsErrors=true`, and committed NuGet lock files. The package references currently inspected in the backend and tests are public packages; the `SD` source is inherited from the developer's machine, not an intentional requirement of this application.

## Requirements

1. Inspect **all** target repository projects, centrally managed package versions, lock files, and existing NuGet configuration to confirm whether any non-nuget.org package feed is actually needed.
2. If all dependencies come from nuget.org, commit a solution/repository-root `NuGet.Config` that uses `<clear />` under `<packageSources>` and declares only `https://api.nuget.org/v3/index.json`. This should isolate the repo from additional user/machine NuGet feeds without asking developers to remove their legitimate `SD` source globally.
3. If any dependency genuinely requires another feed, use explicit NuGet package source mapping instead, mapping every direct and transitive package correctly; do not silently remove a required feed.
4. Confirm that NuGet finds the repository configuration during both Visual Studio solution restore and ordinary `dotnet restore MtgSoloSports.slnx --locked-mode` from the repository root.
5. Demonstrate that an extra user-level package source no longer triggers NU1507 for either the app or tests. Do not change a real developer's machine-level NuGet configuration as part of the solution.
6. Preserve Central Package Management, locked-mode restore, analyzers, and warnings-as-errors. Avoid unrelated dependency upgrades or architectural changes.
7. Add a short troubleshooting note to the repository's local setup documentation so fresh clones are expected to restore even if a developer has company/private feeds configured.

## Architectural direction

- Fix this at repository NuGet configuration level when feasible, not by weakening diagnostics or changing application architecture.

## Acceptance criteria

- [ ] With both `nuget.org` and an extra user-level feed (such as `SD`) present, restoring the solution from the repository root does not produce NU1507.
- [ ] Visual Studio solution restore/build resolves both projects without NU1507 on a machine with multiple user-level sources.
- [ ] No user-level NuGet source needs to be deleted or disabled; the fix is checked into MtgSoloSports.
- [ ] Warnings-as-errors, Central Package Management, and locked-mode restore remain enabled.
- [ ] No non-public feed required by the application is inadvertently excluded.
- [ ] Document the reason for the repository-local configuration and how to troubleshoot local restore.
- [ ] The full repository verification succeeds.

## Verification

Run from the target repository root:

```bash
dotnet restore MtgSoloSports.slnx --locked-mode
dotnet build MtgSoloSports.slnx --configuration Release --no-restore
dotnet test MtgSoloSports.slnx --configuration Release --no-build --no-restore
dotnet format MtgSoloSports.slnx --verify-no-changes --no-restore
npm ci --prefix src/MtgSoloSports.Web
npm run typecheck --prefix src/MtgSoloSports.Web
npm run build --prefix src/MtgSoloSports.Web
```

Also verify with a simulated/isolated user-level second NuGet source (or an equivalent local reproduction) that both project restores are clean. Document the result in the PR.

## Out of scope

- Disabling the `SD` feed for other repositories.
- Suppressing NU1507, disabling warnings-as-errors, or removing Central Package Management.
- Unrelated application or simulation changes.
