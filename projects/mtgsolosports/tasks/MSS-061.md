# MSS-061 — Introduce scalable Type Cup qualification groups and a fixed 32-team final

## Goal

Replace the current unbounded single-field Type Cup with a scalable tournament format that keeps every actual round field at 32 teams or fewer.

When 32 or fewer creature-type teams are eligible, preserve the current direct-final format. When more than 32 teams are eligible, randomly draw them into balanced qualification groups, advance exactly 32 teams, and then run a fresh 32-team Type Cup Final.

This removes the need for the current sporting workaround where positions beyond 32 all receive one base point.

## Context

- Project: `mtgsolosports`; target repository: `AlexBDevCorner/MtgSoloSports`; default branch: `main`.
- Depends on MSS-060 so the expanded Superleague + F1 + F2 + F3 active population is already integrated.
- The feeder expansion increases the active population substantially and is expected to make many more creature types capable of fielding valid four-athlete Type Cup teams.
- Current Type Cup supports an arbitrary team count `N` in one event. `ScoringCalculator.TypeCupBasePointsForPosition` uses the normal 32-place scoring table for positions 1-32 and assigns the table minimum (1 point) to every position beyond 32.
- `TypeCupOver32Tests` explicitly protects the current 33/35/40+ behavior. That behavior was acceptable as a compatibility extension for slightly-over-32 fields but should not be the new tournament format.
- Current persistence assumes one Type Cup team event per season:
  - `TypeCupTeamRoundEntity.GroupNumber` means athlete selection rank group #1..#4;
  - one set of `TypeCupTeamGroupStandingEntity`;
  - one final `TypeCupTeamStandingEntity`.
- The new format needs a separate tournament phase / qualification-group identity so qualification rounds and final rounds cannot collide.
- Type Cup squad allocation from MSS-055 remains authoritative: permanent nationality is an eligibility restriction, maximum valid team count is preserved, and squads are chosen before tournament group draw.

## Required tournament format

### 1. Direct final for 1-32 teams

If the selected Type Cup field contains at most 32 teams:
- run exactly the current Type Cup team competition;
- four athlete-rank groups (#1, #2, #3, #4);
- eight rounds per rank group;
- normal 32-position scoring table;
- no qualification stage.

### 2. Qualification stage for more than 32 teams

If the field contains more than 32 teams:

1. Compute qualification-group count as:
   `ceil(teamCount / 32)`.

2. Randomly distribute all selected teams into that many groups using the save's versioned RNG.
   - Groups must be as balanced in size as mathematically possible.
   - Group-size difference must never exceed one team.
   - Assignment is random, not seeded by team strength/rating.
   - Equivalent starting state + RNG must produce the same draw.
   - The draw must be persisted before competition so reload/history never redraws it.

3. Each qualification group runs the normal Type Cup team format internally:
   - the group's #1 athletes compete against each other;
   - then #2, #3, #4;
   - eight rounds per athlete-rank group;
   - normal scoring table because every group has at most 32 teams;
   - team qualification score is the sum of the four leg scores using the existing deterministic team-ranking/tie-break model.

4. Exactly 32 teams qualify for the Final.

5. Final places are allocated as evenly as possible across qualification groups.
   - `basePlaces = floor(32 / groupCount)`;
   - `remainder = 32 % groupCount`;
   - every group receives `basePlaces`;
   - the first `remainder` groups receive one additional place.
   - Qualification groups themselves must be numbered only after the randomized balanced draw, and any unequal group sizes should be assigned deterministically so the larger groups receive the extra final place before equal-sized groups; ties resolve by persisted group number.
   - For 33-64 teams this gives two groups and 16 qualifiers from each.
   - For 65-96 teams this gives 11/11/10.
   - The total must always equal 32.

6. Finalists start the Final from zero.
   - Qualification scores do not carry over.
   - The Final is a fresh four-group × eight-round Type Cup event.
   - Final team standings alone determine Gold/Silver/Bronze and the official Type Cup title.

## Requirements

1. Add a versioned Type Cup tournament-format rule to the rules snapshot for new rules/saves.
   - Preserve the ability to read old historical Type Cups that used the previous single-field >32 format.
   - Do not rewrite old persisted Cup results.

2. Add explicit persisted tournament identity.
   The data model must be able to distinguish at least:
   - tournament phase: qualification or final;
   - qualification group number where applicable;
   - athlete rank group #1..#4;
   - round number.
   Do not overload one integer field with all three meanings.

3. Persist the random qualification draw as authoritative data.
   At minimum persist:
   - source season;
   - creature type/team;
   - qualification group;
   - group size / field metadata sufficient for validation;
   - RNG before/after or equivalent deterministic provenance/checksum following existing project conventions.

4. The group draw occurs after Type Cup team allocation and before qualification rounds.
   - Squad membership must not change depending on group assignment.
   - Permanent nationality eligibility/allocation from MSS-055 remains unchanged.

5. Keep all qualification groups at 32 teams or fewer.

6. Replace new-format dependence on `TypeCupBasePointsForPosition(position > 32)`.
   - New-format qualification/final rounds must never generate a placement greater than 32.
   - Keep the legacy >32 scoring path only where necessary to replay/read existing historical saves created under the old format.

7. Introduce pure/testable helpers for:
   - qualification-group count;
   - balanced group sizes;
   - deterministic random group assignment;
   - final-place quota allocation;
   - validation that all teams appear exactly once in qualification and exactly 32 qualify.

8. Update `docs/game-rules.md` and technical documentation with the new Type Cup tournament structure.

## Architectural direction

- Treat "Type Cup team selection" and "Type Cup tournament draw" as separate persisted concepts.
- Prefer a small explicit qualification-group/draw entity rather than encoding the group in a display string.
- Keep existing `TypeCupSelectionEntity` as squad selection history unless there is a compelling schema reason to extend it.
- Tournament-format math should be pure and independently unit-tested.
- Do not seed groups by strength. Random group distribution is a deliberate sporting rule.

## Acceptance criteria

- [ ] 1-32 teams use the current direct-final format.
- [ ] 33-64 teams produce exactly two balanced random qualification groups and 16 finalists from each.
- [ ] 65-96 teams produce three balanced groups and 32 total final places distributed 11/11/10.
- [ ] General `N > 32` group count is `ceil(N / 32)`.
- [ ] Qualification group sizes differ by at most one.
- [ ] Every selected team appears in exactly one qualification group.
- [ ] Group assignment is deterministic for equivalent RNG state and persisted for replay.
- [ ] No new-format round has more than 32 teams.
- [ ] Qualification points never carry into the Final.
- [ ] Existing historical >32 Type Cups remain readable without resimulation.
- [ ] New rules/docs describe the scalable format explicitly.

## Verification

1. Run the full backend test suite.
2. Add format tests for team counts 1, 2, 31, 32, 33, 35, 64, 65, 96, 97, and a larger realistic field.
3. Assert group-size balance and exact 32-finalist quota math.
4. Assert deterministic random draw/checksum under identical RNG state and a different draw under a different seed.
5. Assert no team is duplicated or omitted.
6. Assert the new format never calls >32-position scoring.
7. Preserve compatibility tests that can read an old persisted >32 single-field Type Cup.

## Out of scope

- Running the qualification/final round lifecycle itself; MSS-062 owns that.
- UI/Live/history presentation; MSS-063 owns that.
- Changing Type Cup team allocation or permanent-nationality eligibility.
- Seeding groups by strength.
- Carrying qualification scores into the Final.
- Changing Color Cup.
