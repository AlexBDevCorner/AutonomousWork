# MSS-105 — Apply 35/30/20/5/10 selection weights with Chaos form

## Goal

Use a small separate Chaos result component alongside league form in Color and Type squad selection.

## Context

- Project `mtgsolosports`, target `AlexBDevCorner/MtgSoloSports` (`main`). .NET + React, direct vertical-slice Endpoint → Handler, no MediatR; follow `AGENTS.md`. Approved Chaos Cup: 8 sporting colors, 1024 entrants (all source-season league athletes plus random Pool invitations), six 32-athlete group stages [32,16,8,4,2,1], top 16 from each nonfinal group; 16 game rounds per group, active bonus used but not earned; no league points/promotion, group scores reset; first draw exactly 4/color/group, later draws pure random. Runs after 32 league stages and before promotion qualifiers, only for a new season after deployment; odd/even Color/Type Cups keep alternating. Existing sporting history must remain unchanged.
- Scope: **Apply 35/30/20/5/10 selection weights with Chaos form**. This is a single small PR, target roughly 200–600 changed lines where practical; if work expands materially, propose follow-up rather than bundling unrelated features.
- Dependencies: MSS-096, MSS-097, MSS-102; tasks with incomplete dependencies must wait.

## Requirements

1. New outer weights: effective bonus 35%, tier-adjusted completed-season league performance 30%, last-ten-league-stages form 20%, Chaos form 5%, shared career prestige 10%.
2. Chaos form is one outcome of the relevant completed source-season edition (reached stage and Final rank), not a sum of 16-round group scores or addition to league stage form; no pool selection rights.
3. Normalize and report five distinct components; retain Super/F1/F2/F3 performance factors 1.0/.8/.6/.4, Type Cup nationality and old selections/old reports.
4. Handle legacy source seasons with no Chaos Cup cleanly; version new formula and test small 5% impact, F3 finalists, and eligible/candidate pools.

## Architectural direction

- Reuse existing feature/simulation/report patterns; keep deterministic integer calculations, save-scoped state and clear compatibility boundaries. Do not introduce MediatR or unrelated refactors.

## Acceptance criteria

- [ ] Both Color and Type selections show explainable 35/30/20/5/10.
- [ ] No change to active bonus or retroactive selection; historic report parse works.

## Verification

`dotnet build MtgSoloSports.slnx --configuration Release` and `dotnet test MtgSoloSports.slnx --configuration Release` from target root. Add focused regression tests for the task's acceptance criteria and validate compatibility with prior editions. 

## Out of scope

- No tournament gameplay, new bonus or automatic invitation.
- Do not implement any other task or modify unrelated history/data merely for convenience.
