# MSS-078 — Separate Type Cup Live reveal into independent qualification groups and Final

## Goal

Make a live Type Cup easy to follow by presenting **each qualification group as its own distinct competition stage** and the **Final as a separate, fresh stage**. The player should always understand which stage is being played or replayed, its round number and progress, which teams are competing, and how to move to the next stage. Eliminate the confusing combined sidebar and ambiguous round grid shown in the reported UI.

## Context

- Project: `mtgsolosports`; target repository: `AlexBDevCorner/MtgSoloSports`, branch `main`.
- Reported 2026-10-12 while playing Type Cup **Qualification Group 3 of 3**. The Live sidebar shows a combined `Qualification + Final · 3 groups` section with Group A/B/C/Final statuses, `Current stage: Qualification Group 3 of 3`, and a separate **Rounds** card titled `Squad rank group 2 · Qualification Group 3 of 3`. It then offers numeric squad-group buttons and a matrix of round buttons with **1–8 repeated**, followed by the stage's team standings. This is difficult to scan and distinguish from the three actual qualification groups.
- Current source places the whole event in `src/MtgSoloSports.Web/src/features/live/LiveEventView.tsx`; `typeCupLiveStages.tsx` renders the all-stage summary, while `RoundReveal.tsx` renders a persisted round. `eventModel.ts` uses generic `Group N · Round N` labels. The same `group` field in persisted rounds is used for **squad rank groups inside a sporting stage**, not for Type Cup qualification Group A/B/C; treating those as the same is especially misleading.
- The existing backend progresses through the persisted qualification groups in canonical draw order and then the Final. The Final starts at zero and runs on the authoritative selected field. Current **Run remaining rounds** finishes all remaining qualification groups *and* the Final, despite appearing next to the current stage's rounds.
- This is primarily a Live information-architecture, navigation, and presentation problem. Preserve the established Type Cup format and authoritative persistence.

## Requirements

1. **Give each tournament stage its own Live workspace.**
   - Provide clearly separated **Qualification Group A**, **Qualification Group B**, etc., and **Type Cup Final** views. Only the **selected stage's** rounds, team standings, reveal, and controls appear in the stage workspace.
   - Use a compact stage navigation/progress overview to choose completed stages for replay and show the active/next stage. Avoid displaying a giant mixture of all stage details in the sidebar.
   - Completed qualification groups have distinct completed summaries and qualification/cutoff outcomes; the upcoming/active Final is unmistakably separate. Stage count must be data-driven, not hardcoded to three groups.
   - While the backend plays the next canonical stage, the UI follows that stage unless the user explicitly selects another completed stage for replay.

2. **Make round numbering immediately understandable.**
   - Show stage-local **Round X / Y** progress, restarting at Round 1 for every new qualification group and for the Final. If there are 32 rounds, represent them as 1–32 **for that stage** (with exact totals derived from authoritative stage data).
   - Avoid the current large grid of repeating 1–8 buttons without context. Prefer a simple chronological round selector; if keeping squad-rank group subnavigation, make it secondary, unmistakably named (`Squad #1`, etc.), and show the unambiguous overall stage round number alongside any local 1–8 round number.
   - Never confuse qualification Group A/B/C with squad rank groups, and never make a round in one stage appear to belong to another. Show the currently selected stage and round in the reveal heading and standings caption.
   - Support partially played stages, completed-stage replay, and saves with different stage counts.

3. **Respect visible stage boundaries when progressing.**
   - **Next Round** advances only the currently playable canonical stage, with the existing persisted round reveal behavior.
   - A **Finish current stage** (or equivalently clear stage-scoped fast-forward) action must stop at the end of the active qualification group or Final. If necessary, add a safe backend stage-scoped operation rather than silently invoking the current tournament-wide runner.
   - If tournament-wide fast-forward is retained, label it explicitly **Finish entire Type Cup** and distinguish its scope from the stage-specific action, with appropriate confirmation or disclosure for the wider action.
   - At qualification-group completion, present its final standings, guaranteed qualifiers and wildcard-candidate status (where applicable), and an obvious **Continue to next qualification group / Final** path. The Final should open as a new stage with fresh scores and separate rounds.
   - Respect backend legality and canonical order. Do not let viewing or replaying an older stage trigger simulation in that stage or silently skip intermediate stages.

4. **Keep reveal and standings in the selected stage.**
   - The reveal should show only its persisted stage/round. Switching stages or rounds must refresh the correct reveal, baseline, team standings, and labels; no stale data from a different stage.
   - Explicitly distinguish **team standings in the current qualification group** from **Final standings**. Group points must not carry into the Final.
   - Preserve the existing manual/animated reveal behavior, cards, persisted results, and athlete links. Do not re-simulate outcomes during replay.
   - Preserve stage/round selection across reload and Back/Forward where feasible, using explicit stage-aware URL/state rather than conflating `?group=` squad-group parameters with qualification-stage identity.

5. **Polish the Live layout and usability.**
   - Make the active stage, round progress, and primary action prominent. The sidebar should present concise context and current-stage standings, not long repeated technical explanations and multiple unrelated panels.
   - Make desktop and narrow-window layouts readable, accessible and keyboard-friendly; handle many stages without a sprawling sidebar or excessive scrolling.
   - Maintain compatibility with direct-final or legacy Type Cups and other postseason events. Do not apply Type Cup-specific navigation or labels to Color Cup or feeder qualifiers.

## Architectural direction

- First trace persisted Type Cup stage identity/cursor, round payload identity, event-round listing, API filtering, team-standings snapshots, and frontend routing. `round.group` is the squad-rank group *inside* a stage, so the same group/round coordinates may recur in several tournament stages; stage-aware filtering/identities MUST disambiguate them.
- Prefer a focused Type Cup-specific Live stage shell and stage-scoped round selector, reusing `RoundReveal` and existing display components. Do not regress generic Live event views.
- Build on `typeCupLiveStages.tsx`, `LiveEventView.tsx`, `typeCupTournamentModel.ts`, `eventModel.ts` and related API models as appropriate. Inspect the backend's authoritative persisted stage mapping before choosing the implementation.
- If APIs cannot retrieve or progress individual Type Cup stages correctly, add the minimum compatible backend support. Never assume that the existing global `Run remaining` action can serve as stage-scoped fast-forward.
- Avoid a redesign of the overall Type Cup tournament results/history page unless needed for consistent stage replay links.

## Acceptance criteria

- [ ] For a Type Cup with three qualification groups, Live offers distinct Group A, Group B, Group C and Final stage views with unambiguous current/completed/pending states.
- [ ] Entering Group C shows only Group C's rounds, reveal, standings and controls. The user does not need to decode mixed A/B/C/Final sidebar details or repeated unlabeled 1–8 round sequences.
- [ ] Round labels display an intelligible stage-local sequence with correct totals; squad-rank groups, if exposed, cannot be mistaken for qualification groups.
- [ ] Finishing a single qualification group stops before the next group. Tournament-wide fast-forward, if present, is clearly differentiated.
- [ ] After completing the final qualification group, the Final opens as a distinct new stage with its own Round 1, zeroed starting scores and the correct persisted finalists.
- [ ] Completed qualification groups and the Final can be replayed independently without changing scores, results or RNG, including after reload and navigation.
- [ ] Partial reveals and live team standings remain correct when changing stage/round; no stale cross-stage reveal or totals.
- [ ] Stage counts and stage-local totals derive from saved authoritative data; direct-final/legacy saves and other cup/qualifier Live flows continue working.
- [ ] Layout and navigation remain understandable on narrow and desktop viewports.

## Verification

1. Add/update frontend tests for stage navigation, stage-local round numbering, view isolation, replay, Back/Forward/refresh, and handling multiple qualification groups. Cover confusion between qualification-group identity and squad-rank-group identity.
2. Add backend tests only if stage-specific progress/listing/fast-forward API support needs to change. Assert stage boundaries, idempotent resumption, legal cursor order and preservation of existing results.
3. Run `npm test`, `npm run typecheck`, and `npm run build` from `src/MtgSoloSports.Web`; run relevant .NET tests for any changed backend project.
4. Manually verify a tournament with three qualification groups and the 32-team Final: partial Group B/C; completed group replay; completion transition; Final at Round 1; completed Final. Check desktop and narrow layouts.

## Out of scope

- No changes to Type Cup draw, group allocation, qualification/wildcard selection, competition rules, scoring, medal awards or persisted outcomes.
- No new reveal animation system, card redesign, or broad application-wide navigation redesign.
- No refactoring of unrelated Live competitions, feeder qualifier pages, league standings, or completed Cup result layouts.
