# MSS-143 - Make Live follow the active season event, including Chaos Cup

## Goal

The **Live** entry in the sidebar must open the **currently active competition** in the selected save, regardless of whether the season is in league play, Chaos Cup, or another supported playable postseason event. It must not keep showing Superleague data when the season is already in Chaos Cup.

## Context

- Project `mtgsolosports`; target repository `AlexBDevCorner/MtgSoloSports`, branch `main`.
- Reported behavior: while a Chaos Cup edition is in progress, clicking **Live** in the sidebar shows Superleague standings/content and the message/button **"Continue the postseason on the Dashboard"**, rather than the current Chaos Cup.
- The Dashboard already handles postseason progression; this task concerns the **Live navigation target and content**, not the order of the season lifecycle.
- Treat the selected save's authoritative persisted season/lifecycle state as the source of truth. Do not infer the active event solely from the most recent league stage, cached component state, or hardcoded Superleague defaults.

## Requirements

1. Resolve the **active event** for the selected save/season when Live opens (and when lifecycle state changes). Reuse existing authoritative season-flow/current-action data and existing competition views where practical; avoid introducing a second independent lifecycle state machine.
2. During league play, keep the existing Live league/stage behavior. During an **in-progress Chaos Cup**, Live must present the appropriate active Chaos Cup view, with its current round/stage, participants and results/progression as available in the existing Chaos UI. Do not show stale Superleague as the current live competition.
3. Apply the same routing principle to other **supported active playable events** in the season/postseason (qualification, Cups, etc., according to the actual lifecycle). Keep scope narrow: reuse existing views/navigation rather than implementing missing tournament simulators.
4. A Dashboard redirect/CTA is appropriate only when there is **no playable live event to display** and the next legal step genuinely must be performed on the Dashboard (for example, a setup/selection action), not as a generic fallback for any postseason phase.
5. Keep Live consistent after completing a round, stage, or tournament and after refreshing, deep-linking to Live, switching saves/seasons, or navigating away and back. Do not show data from the previous phase while the next phase is active. Preserve existing valid Live interactions.
6. Use clear context labeling so the user knows **which competition and phase** Live is showing. Do not conflate an active event with past historical results.

## Architectural direction

- Inspect sidebar Live route and current Live page/controller plus Dashboard season-flow resolution. Prefer a shared read-only active-event resolver or adaptation of existing season-lifecycle fields rather than duplicate special-case `if Chaos` logic scattered in components.
- Reuse the existing Chaos Cup presentation and any already supported active competition views, with minimal adapter/routing work.
- Keep the change focused on navigation/rendering and necessary read projections; do not alter competition state transitions or simulation logic.

## Acceptance criteria

- [ ] With Chaos Cup actively underway (including after at least one Chaos round), choosing sidebar **Live** displays the current Chaos Cup and its persisted progress; **Superleague + "Continue the postseason on the Dashboard"** is not shown as the active Live content.
- [ ] While an official league stage is active, Live still shows the correct league/stage experience.
- [ ] For each other currently supported playable postseason phase, Live opens the relevant event rather than stale Superleague. For non-playable setup/transition phases, a Dashboard CTA is displayed only when appropriate.
- [ ] On Chaos round completion and tournament completion, Live moves to the new authoritative current event/next action without stale competition data.
- [ ] Reloading Live, direct URL navigation, switching saves/seasons and navigating away/back consistently resolve the correct active event.
- [ ] Focused UI tests cover league play, active Chaos Cup, post-Chaos transition, fallback Dashboard CTA and at least one supported non-Chaos postseason phase; no regressions in existing live controls.

## Verification

- Add deterministic frontend tests around the current-event resolver and Live route/rendering, using season-lifecycle fixtures rather than running entire tournaments.
- Run `npm test --prefix src/MtgSoloSports.Web`, `npm run typecheck --prefix src/MtgSoloSports.Web` and `npm run build --prefix src/MtgSoloSports.Web`.
- If backend contracts change, add focused .NET tests and run repository-required checks from `AGENTS.md`.
- Manually verify with a save mid-Chaos Cup and a save during league play.

## Out of scope

- Changing Chaos Cup formats, scoring, progression, simulation or timing in the season.
- Redesigning the Dashboard, sidebar, historical archive, or entire Live UI.
- Building new event presentations where no playable view currently exists; if one is genuinely missing, document the gap rather than silently replacing it with unrelated Superleague data.
