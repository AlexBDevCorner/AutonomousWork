# MSS-044 — Remove the artificial 32-team limit from Type Cup

## Goal

Allow the Type Cup postseason team event to run with **every valid creature-type team actually formed from currently active league creatures**, even when the field contains more than 32 teams. Team count must be derived from the legitimate selection, not capped at ordinary league size. A field of 35 teams must simulate, persist, replay, and finish normally.

## Context

- Project: `mtgsolosports`; target repository: `AlexBDevCorner/MtgSoloSports`; default branch: `main`.
- During a real Season 2 Type Cup test, selection successfully formed **35 teams**. On **Next Round**, the Live screen reported: **"The round did not complete — Type Cup team event supports at most 32 teams, was 35."** The event stayed at Group 1, Round 0/8.
- `docs/game-rules.md` §15 already explicitly says: **"Every creature type capable of fielding four distinct currently active athletes may participate; there is no artificial team limit."** Selection must continue to respect existing active-athlete eligibility, deterministic global allocation, distinct members, and permanent Type Cup nationality.
- Current code has at least two 32-team guards in `Features/Cups/RunTypeCupTeam/TypeCupTeamInvariants.cs` (`ValidateField`, `ValidateGroups`) and further ordinary-league-size assumptions in `SimulationKernel/Cups/TeamEvent.cs`. Audit **all** Type Cup paths; deleting the visible exception alone is insufficient. In particular, round scoring and invariant checks may use only the first N entries of a league-size scoring table.
- Existing format: **four rank groups** (#1/#2/#3/#4 athletes, one from each team), **eight rounds per group**, then a team ranking from all four legs. A varying number of teams must not change this format.
- Follow `AGENTS.md`, `docs/game-rules.md`, and `docs/technical-design.md`: vertical slices, direct Endpoint -> Handler, no MediatR, fixed-point scoring, deterministic versioned RNG, and immutable persisted round replay.

## Requirements

1. Remove the arbitrary dependency on `rules.LeagueSize` (32) for Type Cup participant/team counts everywhere it incorrectly restricts valid fields: selection validation, group setup, shared Cup simulation, scoring, rankings, payload and persistence validation, result queries, and frontend rendering. Preserve the ordinary 32-athlete **league** rules and Color Cup's genuine fixed-size rules. Do not broadly remove safety checks for unrelated competitions.
2. Determine Type Cup team count from the completed valid selection. Keep all eligible selected teams: **35 means 35 teams**, each represented once in each of the four rank groups, without truncation, dropping teams, or splitting them into an undocumented secondary competition. Keep existing four groups and eight rounds per group.
3. Audit the full score/bonus path for positions beyond #32. Define and document a deterministic, integer/fixed-point, valid scoring behavior for all Type Cup placements beyond the existing 32-entry league scoring table. No out-of-range lookups, overflow, duplicated/missing ranks, or hidden cap. Keep results for existing fields of 2–32 teams unchanged, including their scoring, tie-breaks, RNG consumption, and persisted replay; where an outcome-affecting rule must be extended, honor the repository's save-scoped/versioned-rules compatibility policy.
4. Preserve existing deterministic shuffles, cumulative scores, active-bonus rules, leg/team tie-breaks, team medals, permanent nationality, and no-championship-points/no-new-bonus Cup behavior. Correctly rank all participating teams and validate each placement 1..N once per round and leg.
5. Ensure both **Next Round** and **Run remaining rounds** work from a fresh event and after partially completed groups for over-32 fields, including persistence, reopening the save, replay/history and completed results. Preserve transactionality: no partial round write after a genuine failure and no silent changes to previous saves/results.
6. Search for other Type Cup-specific or accidentally shared 32-team assumptions in backend/DTO/frontend/tests. Keep unrelated league-size invariants intact. Fail clearly only for *genuinely invalid* fields (e.g. incomplete four-athlete teams, duplicate athletes, too few teams), never solely because the valid field exceeds 32.

## Architectural direction

- Start by tracing the error from `RunTypeCupTeam` through `TypeCupTeamInvariants`, `SimulationKernel/Cups/TeamEvent.cs`, shared round scoring, payload validation and persistence. The current 32 guard is a symptom; the entire flow must support N teams.
- Preserve the documented team-group competition model; do **not** introduce brackets, qualifying cuts, or an arbitrary configurable maximum as a workaround.
- Prefer the narrowest clear Type Cup-specific extension to scoring/validation; do not unintentionally change ordinary league or fixed-size Color Cup outcomes.
- Use offline deterministic test fixtures; no live Scryfall requests required.

## Acceptance criteria

- [ ] A saved Season 2 Type Cup selection containing **35 valid creature-type teams** can advance Group 1 Round 1 using Next Round without the reported error, finish all 32 group rounds, persist and reopen, and show all 35 teams in final results.
- [ ] Run remaining rounds also completes an over-32 Type Cup event; resuming mid-event succeeds without duplicating previously saved rounds.
- [ ] Each of the four groups contains exactly one athlete for each team; all over-32 round placements, cumulative totals, leg ranks and final team ranks are valid and replay consistently.
- [ ] Scoring positions beyond 32 have an explicit tested deterministic rule; no IndexOutOfRange/overflow; existing 2–32-team Type Cup outputs remain unchanged for the same rules/seed.
- [ ] Deterministic tests cover at least 32, **33, 35**, and another larger valid field, including validation, full-event simulation, save/reload and history/replay where the project has integration coverage.
- [ ] No new 32-team limit appears elsewhere in Type Cup; normal leagues and Color Cup retain their existing constraints.

## Verification

1. Run the project's standard backend build/test/format checks from `AGENTS.md` and frontend typecheck/build if frontend files change.
2. Run new deterministic Type Cup tests for fields of 32, 33, 35, and a larger valid field. Assert the exact number of selected teams, four members per team, four groups, eight rounds per group, stable scoring/rankings and persisted replay.
3. Reproduce the original 35-team Season 2 failure (or a faithful save/test fixture), confirm Next Round succeeds, then finish via Run remaining rounds and inspect persisted final results.
4. Verify the existing <=32-field Type Cup regressions, normal league simulation and Color Cup team-event tests still pass.

## Out of scope

- Changing Type Cup eligibility, four-athlete selection, global allocation or permanent nationality policy.
- Introducing new tournament brackets, qualifiers or artificial participant limits.
- Rebalancing ordinary league or Color Cup scoring, schedules or awards.
- Redesigning the Live UI or making unrelated postseason changes.
