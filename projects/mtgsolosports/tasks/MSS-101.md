# MSS-101 — Simulate one 32-athlete Chaos group incrementally or fully

## Goal

Run/replay one group's 16 game rounds with standard point table and effective active bonus.

## Context

- Project `mtgsolosports`, target `AlexBDevCorner/MtgSoloSports` (`main`). .NET + React, direct vertical-slice Endpoint → Handler, no MediatR; follow `AGENTS.md`. Approved Chaos Cup: 8 sporting colors, 1024 entrants (all source-season league athletes plus random Pool invitations), six 32-athlete group stages [32,16,8,4,2,1], top 16 from each nonfinal group; 16 game rounds per group, active bonus used but not earned; no league points/promotion, group scores reset; first draw exactly 4/color/group, later draws pure random. Runs after 32 league stages and before promotion qualifiers, only for a new season after deployment; odd/even Color/Type Cups keep alternating. Existing sporting history must remain unchanged.
- Scope: **Simulate one 32-athlete Chaos group incrementally or fully**. This is a single small PR, target roughly 200–600 changed lines where practical; if work expands materially, propose follow-up rather than bundling unrelated features.
- Dependencies: MSS-099, MSS-100; tasks with incomplete dependencies must wait.

## Requirements

1. Use existing 32-athlete 77..1 base-point round, randomized positions, fixed-point active-bonus score and deterministic group tie-breakers; no new bonus or league championship points.
2. Persist each round, partial standings and final P1..P32; support play-next-round and finish-selected-group operations.
3. Use isolated persisted/derived group RNG so group simulation order and complete-group vs next-round calls produce identical results.
4. Retried or restarted group processing must not replay committed rounds or award points twice.

## Architectural direction

- Reuse existing feature/simulation/report patterns; keep deterministic integer calculations, save-scoped state and clear compatibility boundaries. Do not introduce MediatR or unrelated refactors.

## Acceptance criteria

- [ ] 16 incremental rounds and instant complete-group produce identical replay and standings.
- [ ] Other group timing cannot influence outcomes; league/bouns remain unmodified.

## Verification

`dotnet build MtgSoloSports.slnx --configuration Release` and `dotnet test MtgSoloSports.slnx --configuration Release` from target root. Add focused regression tests for the task's acceptance criteria and validate compatibility with prior editions. 

## Out of scope

- No tournament-stage advancement, other group bulk completion or UI.
- Do not implement any other task or modify unrelated history/data merely for convenience.
