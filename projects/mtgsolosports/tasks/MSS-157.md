# MSS-157 - Remove avoidable from-scratch setup and fixed sleeps from the test suite

## Goal

Three concrete testing-rule violations are fixed: two tests doing avoidable full from-scratch season setup where prepared templates exist, and Drive publishing tests sleeping fixed delays where a polling helper exists. All named actions and assertions keep executing in each test.

## Context

- A repository review (2026-11-19) verified the following; re-verify on the live checkout.
- AGENTS.md testing rules: never add avoidable full-season/multi-season/qualifier setup - fork the cheapest applicable prepared save in `SharedSaveTemplates` when that history is incidental; keep the named action, regression trigger, seeds, RNG expectations and assertions executing in each test; but also keep at least one normal-suite from-scratch path per critical lifecycle transition (do not thin correctness coverage for timing).
- `tests/MtgSoloSports.Tests/Features/Dashboard/DashboardPolishTests.cs:84-137` builds a full from-scratch Season 1 + Chaos + movement + rebalance + Color Cup selection chain merely to exercise profile read models with structural, seed-independent assertions (`honours.Count.ShouldBe(72)`); the same lifecycle chain is already covered by `CupLifecycleIntegrationTests`. `ForkSeason1CompleteAsync` (or the closest prepared template) provides the needed state.
- `tests/MtgSoloSports.Tests/Features/History/SeasonPlacementsScoringBoundsTests.cs:117-142` runs `SimulateSeasons(1)` from scratch only to assert read-only bounds for a completed season; `ForkSeason1CompleteAsync` provides exactly that state.
- `Features/Reports/GoogleDriveAutoPublishTests.cs:120,161,195,340` (and Library/Athlete publishing tests) sleep fixed `Task.Delay(3s)` plus `DateTime.UtcNow` deadlines, adding ~seconds of fixed latency and mild flakiness, while `WaitForAutoStatusAsync` polling already exists in the same file.
- `Features/Diagnostics/LongRunInvariantTests.cs:104-130` and `LongRunChecksumHandlerTests.cs:104-131` duplicate private `CreateStore`/`TestHostEnvironment` boilerplate although `TestSaveStores.CreateStore` exists.

## Requirements

1. Convert `DashboardPolishTests` and `SeasonPlacementsScoringBoundsTests` to fork the cheapest prepared template; the assertions (and any named action they verify, e.g. a read-model refresh call) still execute in each test. If a transition's only from-scratch coverage would be lost by the conversion, keep one thin from-scratch fact for that transition and note it in the test file.
2. Replace every fixed `Task.Delay` wait in the Drive publishing tests with the existing `WaitForAutoStatusAsync` polling (bounded, no wall-clock deadline assertions beyond the helper's existing bound); behavior under test unchanged.
3. Replace the duplicated store/environment boilerplate in the two diagnostics test files with `TestSaveStores.CreateStore`.
4. Do not touch golden-seed, rule-version, determinism, RNG, or from-scratch lifecycle-proof tests otherwise; templates must not silently replace pinned seeds or versions (AGENTS.md).
5. Record rough before/after timing for the affected classes (TRX + `scripts/test-timing.py` per repo instructions).

## Architectural direction

- Test-infrastructure only; no production code changes. Fork discipline per the existing `SharedSaveTemplates` rules (built once per process through production handlers; consumers mutate only their fork and clean up).

## Acceptance criteria

- [ ] The two converted tests run their assertions on forked template state and pass; the suite keeps at least one genuine from-scratch path per critical lifecycle transition they used to cover (explicitly noted if retained as a thin fact).
- [ ] No `Task.Delay` fixed sleeps remain in the Drive publishing tests; polling helper used; tests still verify the same outcomes.
- [ ] Diagnostics test files use the shared `CreateStore`; no private duplicates remain.
- [ ] Full backend suite green; affected classes pass alone from a fresh process; measured timing delta recorded.

## Verification

Standard AGENTS.md backend sequence: locked restore, Release build, full test suite, `dotnet format --verify-no-changes`; TRX capture with `python scripts/test-timing.py <trx> --top 20` for the before/after evidence; run the four affected test classes alone from fresh processes.

## Out of scope

- Building new templates beyond what the conversions need, changing production Drive publishing code, performance work beyond these tests (MSS-122 already owns suite-wide runtime), and any sporting expectation changes.
