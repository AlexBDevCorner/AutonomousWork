# MSS-134 - Build factual Superleague stage review evidence from one SQLite snapshot

## Goal

Give the journalist agent compact, verifiable evidence for the latest completed Superleague stage or a specifically requested historical stage, including all round results, championship standings changes and relevant historical context, without leaking later outcomes.

## Context

- Project: `mtgsolosports`; target: `AlexBDevCorner/MtgSoloSports`, branch `main`. Extend MSS-133's local snapshot helper.
- The user corrected the requested cadence to after every Superleague stage, not after every individual round. Current rules have 16 rounds per stage and 32 stages per season; read the actual save-owned rule version rather than hard-coding these numbers.
- Existing source areas include `Features/History/GetRoundReplay`, `RoundPayloadCodec`, `Features/Reports/SeasonDossier`, `UniverseAlmanac`, standings/history queries and `docs/reports.md`.
- Historical round payloads support compact plain JSON and Brotli-prefixed data. Persisted results and saved rules are authoritative. Replaying a payload means reading it, never simulating it again.
- Existing dossiers are useful references, but current all-time aggregates or a present-day athlete profile may include events after a requested historical stage. Existing report handlers can also perform migration checks. Do not use them indiscriminately on the read-only snapshot.

## Requirements

1. Add an offline stage-evidence operation over the verified snapshot from MSS-133. Resolve the latest durably completed official Superleague stage across season transitions, or accept an explicit season/stage. Resolve Superleague from persisted identity, not display-name guesses. Report the selected save/season/league/stage and completion evidence.
2. Do not review a partial stage as completed, silently switch a requested target, advance the game or substitute the next season's unfinished stage for the previous season's last completed stage. Return a clear no-completed-stage/not-found/partial-stage outcome where appropriate.
3. Produce versioned structured JSON, with a concise readable summary if useful, that includes the complete stage table, all covered round placements and scores, round winners, stage score/finish, awarded championship points, and championship standings immediately before and after the stage. Include signed rank/gap changes with explicit units.
4. Handle stage one, final stage, first available season, tied points, official tie-breaking, zero points, absent prior context and historical rule versions correctly. Distinguish raw round/stage scores, season championship points, bonuses and weighted career points. Preserve fixed-point integer values and provide clear display conversion.
5. Derive championship changes from authoritative persisted results and saved ranking rules, including tie-break information. Reuse existing pure ranking/formatting/query logic where safe, without introducing RNG, migrations or synthetic resimulation.
6. Support bounded follow-up context for a named athlete and earlier Superleague stages/seasons: recent finishes/form, prior stage wins/titles and relevant historical comparisons. Keep results source-linked and scoped to the covered stage. Avoid loading or printing every athlete's full history for an ordinary review.
7. Treat the target stage as an explicit knowledge cutoff. Exclude later stages, later season outcomes, later Cup results, current mutable bonuses and future achievements from factual context. Reconstruct supported as-of statistics from dated persisted evidence; label unavailable context rather than substituting current aggregates. A record/first/best claim must have defined scope and checked history, otherwise omit it.
8. Decode each needed round through the existing codec and verify identity/checksum/placement completeness consistent with the history replay contract. Corrupt or missing required evidence must fail visibly; do not silently invent a result or rank.
9. Carry source metadata from MSS-133, target cutoff, saved rules/schema version and stable evidence references into the output. Every numeric highlight must be traceable to a row, round payload or explicit aggregation. All queries for an article must remain on one snapshot, with no background calls to the advancing live app.
10. Keep ordinary evidence compact; offer targeted detail for investigation. Document coverage limits and measure output size and elapsed time on a representative multi-season fixture rather than claiming token savings without evidence.
11. Add focused tests for latest-completed selection with partial progress, season transition, before/after rankings and ties, stage-one/final-stage cases, supported payload encodings and corruption. Add a historical-cutoff test that introduces later outcomes/achievements and proves they do not change evidence for the earlier stage.

## Architectural direction

Extend the same local helper, not a new endpoint/service. Prefer extracting or reusing small pure result interpretation functions over copying ranking algorithms or invoking handlers that initialize a save. Use AsNoTracking/read-only connections as appropriate, and preserve the existing vertical slices and pure SimulationKernel. Reuse cheap prepared-save forks; use a small genuine lifecycle proof only where completion/transition is the subject. Source references are local evidence identifiers, not a requirement for an external citation platform.

## Acceptance criteria

- [ ] One command produces evidence for the latest completed Superleague stage, and explicit historical season/stage selection works.
- [ ] The article source includes all stage rounds plus correct before/after championship standings, awarded points, rank changes and gaps.
- [ ] Partial stages and unavailable/corrupt evidence cannot be presented as completed results.
- [ ] Athlete/history follow-up queries respect the same snapshot and as-of cutoff.
- [ ] Later events do not contaminate earlier stage coverage, and unsupported historical claims are explicit omissions.
- [ ] Evidence has defined units, identity, provenance and a versioned format; output size and elapsed-time observations are documented.
- [ ] Focused tests and command examples demonstrate the above without modifying sporting state or consuming RNG.

## Verification

Run the new focused evidence/CLI tests and relevant existing standings, history/replay and report tests, followed by target AGENTS.md required quality gates. Record exact commands and results. Compare a known stage's extracted results with persisted replay and official standings; compare stage one and a completed season's final stage. Prepare an earlier stage plus later simulation history and verify the earlier evidence is unchanged apart from disclosed source snapshot metadata. Test a partially played subsequent stage/season, tie-breaking and corrupt payload handling. Record representative JSON size and extraction duration with fixture scope and environment.

## Out of scope

- Writing articles, storing editorial notebooks or archive workflow, covered by MSS-135.
- New sporting calculations, rule changes, simulations, migration/backfill or repairing saves.
- Global all-sport analytics, exhaustive record engines, feeding the entire database into model context or unrestricted SQL/network services.
- Drive synchronization, frontend redesign, automation, model/API integration or container changes.
