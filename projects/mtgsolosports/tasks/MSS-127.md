# MSS-127 - Allow a verified checkpoint to recover an unreadable or missing live save

## Goal

Allow a verified checkpoint to recover an unreadable or missing live save while preserving existing save data and unrelated behavior.

## Context

- Project: `mtgsolosports`; target: `AlexBDevCorner/MtgSoloSports`.
- Bug scan on 2026-11-03, audited [main revision 321eb36](https://github.com/AlexBDevCorner/MtgSoloSports/tree/321eb367316252ad259aea6b2fc66cc1ce08b6a1). Line numbers refer to that revision.
- RestoreCheckpointAsync verifies the selected checkpoint, then unconditionally creates a pre-restore-safety checkpoint at SaveStore.cs:1151. CreateCheckpointAsync calls ReadDetailAsync and MapDetail, which require the live save's metadata, rules and RNG rows to be valid. A damaged live save therefore prevents the recovery operation intended to repair it. Reproduction: create a save and verified checkpoint, DELETE FROM RngStates in the live database, then restore the checkpoint. It fails with 'Save ... is missing required rows' through CreateCheckpointAsync:890 instead of restoring. This path was reproduced after diagnostic-only removal of MSS-125's Windows sharing blocker; those diagnostic changes were reverted. File.Exists(livePath) also prevents recovery when the live file has been lost.

## Potential damage if not fixed

If your current save becomes damaged or its file is lost, the game may refuse to restore a healthy backup that you already have. You could be left unable to continue that universe through the normal recovery process. The backup itself can still be valid, but recovering it would require manual help; without that help, you may have to abandon the save.

## Requirements

1. Restore a checksum- and identity-verified checkpoint when the live save has missing required rows, malformed rules/RNG, an unreadable database or no live database file.
2. Preserve the damaged live bytes for diagnosis when they exist, without requiring them to pass normal save validation. Keep this distinct from a verified healthy gameplay/recovery checkpoint.
3. Validate the selected backup before replacing anything. Corrupt backups, mismatched identities and failed replacement must not destroy the live file or the last good backup.
4. Keep normal healthy-live pre-restore safety protection, invalidate stale handles/cache correctly, and verify the recovered live save. Add focused tests for missing RNG, malformed live state, missing file and corrupt selected checkpoint.

## Architectural direction

Inspect Persistence/Saves/SaveStore.cs:1095-1158, CreateCheckpointAsync:873-904, MapDetail:1193 onward and OverwriteLiveFromCheckpointAsync:1414 onward. Reuse existing save-scoped paths and checkpoint verification. Coordinate Windows handle behavior with MSS-125 without depending on valid live metadata to recover. Follow target AGENTS.md and docs/testing.md; direct vertical slices, deterministic sporting math, no MediatR.

## Acceptance criteria

- [ ] A known-good checkpoint restores successfully after the live RNG row is deleted.
- [ ] Recovery works with an unreadable or missing live database.
- [ ] Existing damaged bytes are preserved when possible; invalid backups never replace live data.
- [ ] Healthy-save safety copies and checkpoint identity/checksum validation remain effective.

## Verification

Add cheap fresh-save integration tests to SaveCheckpointTests and HTTP coverage where needed in SavePortabilityApiTests. Run those classes plus required backend checks on Windows and Linux. No simulated seasons are needed.

## Out of scope

No user-facing gameplay undo, sporting resimulation, automatic repair of bad history, cloud recovery or unrelated save-format changes.
