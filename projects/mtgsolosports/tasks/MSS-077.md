# MSS-077 — Keep the Standings page focused on standings only

## Goal

Simplify the **Standings** section in MtgSoloSports so that it contains only league standings. Remove feeder rebalancing and promotion/relegation data and UI from this section. Those activities belong in their existing dedicated workflow views, not alongside the league tables.

## Context

- Project: `mtgsolosports`; target repository: `AlexBDevCorner/MtgSoloSports`, branch `main`.
- Reported 2026-10-12: the player does not want **feeder rebalance** or **promotion and relegation** information within **Standings**. Their expectation is straightforward: "There should be only, well, standings."
- The game includes a Superleague and multiple feeder tiers; Standings should remain the place to inspect league rankings and results, not postseason movement or rebalance operations.
- This is a focused presentation and information-architecture cleanup, not a request to alter competition rules.

## Requirements

1. **Remove non-standings content from Standings.**
   - Remove Standings-page panels, cards, sections, summaries, action controls, explanatory copy, or other displays dedicated to **feeder rebalancing**.
   - Remove Standings-page panels, cards, sections, summaries, action controls, or other displays dedicated to **promotion and relegation**.
   - Do not replace them with new movement/rebalance summaries, badges, or separate subsections on Standings. The page should display standings only.
   - Remove now-unused page-specific component code where safe; avoid broad unrelated refactoring.

2. **Keep actual league standings intact.**
   - Preserve league selection, season selection, rankings, athlete/team names, standings statistics, sorting, navigation, and any existing useful standings-specific context.
   - Support Superleague and all configured feeder tiers, including universes with different numbers of feeder levels.
   - Keep standing positions and competition results accurate, including completed or historical seasons.
   - Remove promotion/relegation and feeder-rebalance indicators from this page if they are merely extra movement/rebalance information, while retaining ranking and statistical values that are part of the table itself.

3. **Preserve movement and rebalance functionality elsewhere.**
   - Do **not** delete the underlying data, APIs, simulation rules, history, or workflows for promotion/relegation and feeder rebalance.
   - Existing dedicated Dashboard/postseason/Live views (or other appropriate current locations) must continue to expose and run those processes as before.
   - Avoid breaking navigation or state refresh for other pages that consume the same data or shared UI components.

4. **Keep the page coherent after the cleanup.**
   - Remove orphaned headings, blank containers, excess whitespace, or broken grid/card layouts left behind by the removed content.
   - Preserve existing responsiveness and scrolling behavior for league tables; do not redesign the standings table unnecessarily.
   - Ensure empty/new-season and historical standings states still have sensible standings-only presentation.

## Architectural direction

- Inspect the current Standings page and its child components to identify which elements render tables versus feeder-rebalance and promotion/relegation data.
- Prefer a small, localized frontend change. Only remove shared components if no other page uses them; otherwise remove their inclusion from Standings.
- Reuse existing table queries/read models rather than changing domain logic or persistence. No backend change should be needed unless it is necessary to preserve existing standings behavior.

## Acceptance criteria

- [ ] The Standings section contains league standings and standings-specific controls only.
- [ ] No feeder-rebalance details, action controls, badges, or dedicated sections appear in Standings.
- [ ] No promotion/relegation details, action controls, badges, or dedicated sections appear in Standings.
- [ ] Superleague and available feeder standings retain their correct rows, rankings, statistics, navigation, and season/league selection.
- [ ] The page remains clean and responsive, with no empty card shells or unexplained gaps where removed content used to be.
- [ ] Dedicated promotion/relegation and feeder-rebalance workflows and their data remain functional elsewhere.
- [ ] Regression checks cover an in-progress season, a completed season, and at least one multi-feeder-tier universe.

## Verification

1. Run the frontend test, type-check and build commands from `src/MtgSoloSports.Web/package.json` (adjust if the workspace has moved).
2. Add or update focused Standings rendering tests to assert that tables remain and rebalance/movement sections are absent.
3. Inspect Standings in the UI for Superleague and feeder leagues, including at least one completed season. Check narrow and desktop layouts for gaps or broken table sizing.
4. Open the dedicated postseason screens to confirm promotion/relegation and feeder rebalance remain visible and runnable there, with no changes to game outcomes.

## Out of scope

- No changes to actual promotions, relegations, feeder-rebalance algorithms, league scoring, standings calculations, or persisted history.
- No removal or redesign of the dedicated postseason/Live/Dashboard views.
- No broad UI redesign or reorganization of other pages.
- No new standings metrics or replacement movement/rebalance widgets.
