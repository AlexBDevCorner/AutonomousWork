# MSS-047 — Count 2nd and 3rd places as honours

## Goal

Fix honour counting so that a competition podium finish counts as an honour: **1st, 2nd, and 3rd place** should all contribute to an athlete's honours, not only wins.

## Context

- Project: `mtgsolosports`; target repository: `AlexBDevCorner/MtgSoloSports`; default branch: `main`.
- Current behaviour appears to count only competition victories as honours.
- Finishing **2nd** or **3rd** in a competition is also an honour and should be represented anywhere honours are calculated, queried, or displayed.
- This task changes the meaning of **honours** only. Existing statistics explicitly representing wins, titles, or championships should remain win-only.
- Follow `AGENTS.md`, `docs/game-rules.md`, and the existing vertical-slice architecture.

## Requirements

1. Define a qualifying competition honour as a final placement of **1st, 2nd, or 3rd**.
2. Audit every place where honours are derived or displayed, including athlete/profile statistics, history/result projections, queries, DTOs, persistence-derived calculations, and relevant frontend views.
3. Keep statistics explicitly named or intended as **wins**, **titles**, or **championships** restricted to actual victories. A win remains a 1st-place result; an honour is any top-three finish.
4. Ensure an athlete receives exactly one honour for each qualifying competition result and avoid double-counting the same persisted result through multiple projections.
5. Historical persisted results must be interpreted correctly so existing 2nd- and 3rd-place finishes start contributing to honour totals without recreating old competitions.
6. Apply the rule consistently across all competition types that currently contribute wins to honours, unless the documented game rules explicitly exclude a competition from honours.
7. Preserve simulation, scoring, tie-breaks, podium results, and deterministic behaviour. This is a statistics/history interpretation change, not a sporting outcome change.

## Acceptance criteria

- [ ] A 1st-place finish contributes one honour.
- [ ] A 2nd-place finish contributes one honour.
- [ ] A 3rd-place finish contributes one honour.
- [ ] A 4th-place or lower finish contributes no honour.
- [ ] Win/title/championship counters remain win-only where applicable.
- [ ] Historical persisted podium results are reflected correctly in honour totals.
- [ ] Multiple podium finishes across seasons and competition types accumulate correctly without duplication.
- [ ] Backend/frontend tests cover 1st, 2nd, 3rd, and non-podium placements and protect the distinction between honours and wins.

## Verification

1. Run the standard backend build/test checks from `AGENTS.md` and frontend typecheck/tests/build if frontend code changes.
2. Add focused tests proving placements 1/2/3 each contribute exactly one honour while 4th does not.
3. Verify win/title statistics still distinguish victories from runner-up and third-place finishes.
4. Open athlete/profile/history views containing historical 2nd- and 3rd-place results and confirm the displayed honour totals include them.

## Out of scope

- Changing competition scoring, simulation, qualification, tie-breaks, or podium placement rules.
- Renaming existing win/title statistics.
- Introducing new honour categories or weighting 1st/2nd/3rd differently.
