# MSS-087 — Extend textual downloads to Cups, color/type teams and league profiles

## Goal

Make detailed, standalone Markdown and JSON reporting available from Cup editions, Color Cup and Type Cup team pages, and league profiles, reusing the export foundation from MSS-086. A reader should be able to obtain the selected competition's data without copying many tables from the browser.

## Context

- Project `mtgsolosports`; target `AlexBDevCorner/MtgSoloSports` (`main`).
- Depends on completed MSS-086; reuse its versioned JSON envelope, Markdown conventions, download UI and error handling. Do not implement a second incompatible report engine.
- Current code has backend `Features/Cups` slices for Cup history/editions, Color Cup individual/team results and selection reports, Type Cup tournament and team results/history, and `Features/Leagues/Profiles` for podium history, records and all-time league points.
- React has `CupEditionPage`, `CupTeamPage`, `CupsHubPage`, `LeagueProfilePage` and related Cup/team views. The Type Cup can have qualification groups, wildcard rules, and a 32-team Final; these results are not interchangeable.
- Purpose: supply factual, historical competition data to ChatGPT, including unusual performances, squad composition and qualification drama. Never generate fictional narratives or re-simulate results.

## Requirements

1. Add consistent `Download report` controls (Markdown and JSON) for **selected Cup edition** views, **Color Cup team** views, **Type Cup team** views and **league profile** views. Respect the exact selected save, edition/source season, event phase/group, colour or creature type, and league identity as applicable. Do not silently export the latest/current event instead of the displayed historical one.
2. **Cup edition report:** include competition type, source season, edition identity, status/phase, format, participants/teams, full authoritative result/standings table (not just podium), scores, medals/podiums and relevant stage/round aggregates where existing persisted data supports them. Distinguish individual and team competitions.
3. **Type Cup qualification and Final:** include each group's teams, placement/points, qualification threshold/slots, wildcard allocation and adjusted-score explanation if persisted, plus Final entrants and official Final placements. Explicitly distinguish qualification standings from final standings; qualifier success must not be misreported as a title. For an unfinished Cup, label finished vs pending phases and omit unknown results.
4. **Color and Type team reports:** include specific team identity, historical edition/season, actual participating roster, selected members' athlete IDs/names, official selection details/rationale where already persisted, relevant group/final outcomes, medals, and available historical team achievements. Do not substitute *current* athlete league/team for historical affiliations.
5. **League profile report:** include its stable league key/level/colour, completed-season podium history, official all-time **league points** leaderboard, league-specific records and holders, and separately labelled current provisional-season information. Reuse existing `Leagues/Profiles` semantics; never confuse career weighted rating with league points.
6. Include all rows relevant to the chosen page/report (not just viewport or frontend truncation). Reuse authoritative backend records, stable IDs, persisted scoring values/precision, deterministic ordering and MSS-086 report metadata/formatting.
7. Markdown must convey hierarchy/semantics clearly for a reader who has no UI: headings for groups, distinct final standings, squad composition and historical context. JSON must preserve enough structure to allow future automated comparisons; do not serialize raw EF entities or UI component state.
8. Handle missing/unfinished Cups, pre-qualification legacy editions, sparse rosters, old saves, ties, absent optional selection explanations, multiple feeder divisions and long team names without fabricated placeholders or errors.
9. Export is read-only and reasonably efficient. Prefer batched existing query/read models, not one network request per result or repeated full-history decompression. Avoid new database tables solely for export.
10. Keep code localized to report slices and existing pages; no generic query designer or wholesale Cup/league UX redesign.

## Architectural direction

- Reuse MSS-086's `schemaVersion` envelope, renderer, filename and download action. Add narrowly focused handlers/adapters over existing `Features/Cups` and `Features/Leagues/Profiles`.
- Observe the exact competition distinction used in `GetTypeCupTournament` (qualification groups and separate Final) and the historical roster/selection snapshots. Do not reconstruct old results using today's memberships.
- Keep exports consistent with existing Cup/league API responses and UI labels; a reviewer should be able to compare a downloaded report to its originating view.

## Acceptance criteria

- [ ] A chosen Color Cup individual edition, Color Cup team edition, and Type Cup edition can each be downloaded as `.md` and `.json` with correct season and full relevant results.
- [ ] Color Cup and Type Cup team pages can export historical roster, participation and performance data accurately.
- [ ] Type Cup reports distinguish qualification groups, wildcard/cutoff logic (when applicable) and Final, including incomplete states.
- [ ] A selected league profile exports complete podium history, league records and all-time league-points leaderboard, not weighted career score.
- [ ] Current/historical pages never silently export another edition, colour, team or league.
- [ ] Official results, ranks, points, medals, history and stable IDs agree across the UI and both formats.
- [ ] Ties, empty states, legacy Cup formats and partially completed events are clearly handled.
- [ ] Exports do not modify sporting data and the UI remains accessible/responsive.
- [ ] Representative backend and frontend tests validate all report families and data integrity.

## Verification

Run all standard .NET and React test/type-check/build/format gates documented in `AGENTS.md`. Compare exported Markdown/JSON to visible pages and persisted results for: Color Cup individual; Color Cup team (one colour); Type Cup group qualifier plus Final, including wildcard cut line; a specific historical type team; Superleague profile; and Feeder profile. Include an in-progress tournament and an old/legacy edition. Confirm JSON schema version/units, consistent names, complete row counts and no save mutations.

## Out of scope

- Generic report builder/SQL querying or charts produced by arbitrary user configuration.
- Generated journalistic prose, automated AI analysis, ChatGPT/Google Drive integrations.
- Full-universe/season bundles (MSS-088), bulk per-round raw placement export, or database backup replacement.
- Reworking Cup rules, qualification, scoring, roster selection, historical standings, records calculation or league identity.
