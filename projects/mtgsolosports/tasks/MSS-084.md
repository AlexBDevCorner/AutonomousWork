# MSS-084 — Default Standings to Superleague and preserve league selection across seasons

## Goal

Make browsing historical seasons in **Standings** more convenient: show **Superleague** by default when there is no previously selected league, and retain the currently selected league when the user switches between seasons instead of unexpectedly resetting the league selector.

## Context

- Project: `mtgsolosports`; target repository: `AlexBDevCorner/MtgSoloSports`, default branch `main`.
- Requested 2026-10-23.
- In **Standings**, the user selects a season and views standings for a league within that season. The current selection behavior requires unnecessary repeated navigation: Superleague should be the initial/default league, and switching seasons should not discard an explicitly selected league.
- A universe can contain Superleague and multiple Feeder divisions/leagues; availability may differ across historical seasons and old saved universes. The UI must not display results from the wrong season or an unavailable league.

## Requirements

1. **Select Superleague by default.**
   - On first opening Standings for a universe (or when no valid league has been chosen yet), initialize the selected league to **Superleague** for the displayed season if it exists.
   - The Superleague standings should be visibly selected and actually loaded, not just placed first in a dropdown while another league's results render.
   - If a historical/legacy season has no Superleague, fall back deterministically to the first valid available league and show an appropriate empty state if no leagues exist.

2. **Keep league selection while switching seasons.**
   - When the user explicitly selects a league (e.g. a particular Feeder 1 color division) and then changes the season in either direction, keep that same league selected **when it exists in the newly selected season**.
   - Preserve the league's stable identity rather than its list index or display position. Different option orderings between seasons must not silently select a different league.
   - If the selected league is not available in the destination season, fall back to Superleague when available, otherwise the first valid league. The league selector and displayed standings must always agree.
   - After falling back, use the now-selected fallback league as the selection for subsequent season navigation, unless the user picks another league.

3. **Keep transitions consistent.**
   - Ensure changing either season or league loads standings for exactly that combination; prevent stale data, mismatched headings, or a temporary incorrect league selection from out-of-order requests.
   - Preserve existing loading, empty, and error behavior, including historical saves and seasons with different league configurations.
   - Do not change league ordering, competition results, scoring, navigation to athlete details, or other Standings behavior.

## Architectural direction

- Inspect the React/TypeScript Standings page and the season/league selector state and data-fetching dependencies.
- Initialize the selection only when necessary; avoid an effect that resets the league whenever `seasonId` changes.
- Use the existing canonical league identifiers and selectors/query keys. Derive the selected league from the season's available leagues, only applying a fallback when the existing choice is invalid.
- Keep this a focused frontend behavior change. Avoid introducing cross-session persistence or backend changes unless the existing UI architecture genuinely requires them.

## Acceptance criteria

- [ ] On first opening Standings, the displayed league is Superleague by default when available.
- [ ] Choosing Feeder 1 (or another league), then moving from season N to N-1 and back to N preserves that league as long as it exists in both seasons.
- [ ] Switching seasons does not reset a valid selection to Superleague or the first league.
- [ ] When a selected league is missing in the target season, the selector and results consistently fall back to Superleague (or first available league if Superleague is absent).
- [ ] After fallback, subsequent season switches preserve the fallback selection, unless a different league is manually chosen.
- [ ] Rapid season switches and async data loading do not show a season/league mismatch or stale standings.
- [ ] Existing Standings features and historical save compatibility remain intact; frontend tests/type-check/build pass.

## Verification

1. On a multi-season universe, open Standings fresh and confirm Superleague is selected and shown.
2. Select a non-Superleague division, switch between at least two seasons where it exists, and verify both the selector and standings data remain on that exact division.
3. Test a season where a selected division is absent (if supported by saved history), verify deterministic fallback, then switch again.
4. Switch seasons rapidly and refresh/re-enter the page; ensure the component never displays a league/season mismatch. No cross-session persistence is required.
5. Add or update focused frontend tests for default selection, valid preservation, fallback, and async transitions; run the project's existing frontend test, type-check, and build commands.

## Out of scope

- Changes to league structures, simulation, relegation/promotion rules, or historical results.
- Redesigning Standings tables, adding new filters, or changing the ordering of leagues in selection controls.
- Persisting selected league across browser sessions, devices, or different universes.
