# MSS-106 — Insert Chaos between league completion and promotion qualifiers

## Goal

Add lifecycle orchestration and forward-only activation without rewriting already started seasons.

## Context

- Project `mtgsolosports`, target `AlexBDevCorner/MtgSoloSports` (`main`). .NET + React, direct vertical-slice Endpoint → Handler, no MediatR; follow `AGENTS.md`. Approved Chaos Cup: 8 sporting colors, 1024 entrants (all source-season league athletes plus random Pool invitations), six 32-athlete group stages [32,16,8,4,2,1], top 16 from each nonfinal group; 16 game rounds per group, active bonus used but not earned; no league points/promotion, group scores reset; first draw exactly 4/color/group, later draws pure random. Runs after 32 league stages and before promotion qualifiers, only for a new season after deployment; odd/even Color/Type Cups keep alternating. Existing sporting history must remain unchanged.
- Scope: **Insert Chaos between league completion and promotion qualifiers**. This is a single small PR, target roughly 200–600 changed lines where practical; if work expands materially, propose follow-up rather than bundling unrelated features.
- Dependencies: MSS-100, MSS-102, MSS-104, MSS-105; tasks with incomplete dependencies must wait.

## Requirements

1. For newly eligible seasons, lifecycle order is completed league tables → Chaos draw/play/Final → existing promotion qualifiers and rebalancing → alternating Color/Type Cup → next season.
2. Persist save-specific effective-start season/format version so only seasons started after implementation receive Chaos, including Season 1 inaugural branch; never inject a tournament into current/historic seasons.
3. Wire legal next actions, Dashboard, AdvanceToNextEvent and bulk CompleteSeason/SimulateSeasons gates; incomplete Chaos prevents qualifiers.
4. Freeze eligibility before movement, keep existing bonus aging and Season 32 conventions and preserve manual/fast outcome equivalence.

## Architectural direction

- Reuse existing feature/simulation/report patterns; keep deterministic integer calculations, save-scoped state and clear compatibility boundaries. Do not introduce MediatR or unrelated refactors.

## Acceptance criteria

- [ ] Existing saves in-progress continue previous rules, while new eligible seasons follow new chain.
- [ ] Retries, bulk progress and restarts cannot skip unfinished Chaos or duplicate it.

## Verification

`dotnet build MtgSoloSports.slnx --configuration Release` and `dotnet test MtgSoloSports.slnx --configuration Release` from target root. Add focused regression tests for the task's acceptance criteria and validate compatibility with prior editions. 

## Out of scope

- No frontend Chaos work or changes to promotion rules.
- Do not implement any other task or modify unrelated history/data merely for convenience.
