# MSS-152 - Harden SimulationKernel guards, rule-version extensibility, and dead code

## Goal

Close the latent robustness gaps inside `SimulationKernel`: unchecked bit-packing, an unbounded search, per-call revalidation, version-dispatch casts, silent honour-kind swallowing, and dead code. No sporting outcome changes.

## Context

- A repository review (2026-11-19) verified the following across all 50 kernel files; re-verify on the live checkout.
- `SimulationKernel/Seasons/SeasonCalculator.cs:492-501` (`EncodeRawTotals`) shifts a stage score left 32 bits into a signed long with no bound assertion; `checked` does not cover shifts, so a stage score >= 2^31 thousandths would silently produce a negative ordering key. Current maxima leave ~35x headroom, so this is a guard, not an active bug.
- `SimulationKernel/Cups/TypeCupAllocation.cs:959-1005` (`SearchSubset`, feasibility at `:1007-1029`) is branch-and-bound with a max-flow check per node and no component-size/step guard; a pathological athlete-type graph could hang a synchronous mutation.
- `rules.Validate()` re-runs ~80 invariants on every kernel call (`Scoring/RoundSimulator.cs:29,56`, `Stages/StageCalculator.cs:47,129`, `Cups/TeamEvent.cs:124,156,224`) - roughly 150 ops per round x 512 rounds x 25 leagues per season advance.
- `Cups/CupPrestigeCalculator.cs:111` dispatches on `rules is RulesV3` with five `(RulesV3)rules` casts (`:184,239,327,354,364`), unlike the virtual `GetBonusScale`/`SupportsLevel` members; a future RulesV4 silently falls into the legacy path.
- `Rules/RulesV3.cs:354-385` has a 40+ same-typed positional parameter constructor/Create (also `RulesV2.cs:36-86`) plus three near-identical ~30-line copy blocks (`RulesV2.cs:212-253`, `RulesV3.cs:321-349,401-429`); adjacent same-typed ints make transposition undetectable.
- Dead code with no callers in src or tests: `RoundSimulator.cs:240` (`ValidateResult`), `StageCalculator.cs:232,270,324,365` (`ValidateRound`/`ValidateRoundEntry`/`TrackRoundEntry`/`ValidateTotals`), `TypeCupAllocation.cs:371` (`AllocateGreedy`) and `:479` (`PickFour`).
- `CupPrestigeCalculator.cs:302-305` silently ignores unknown honour kinds, swallowing genuinely corrupt kind ints instead of aborting (violates the fail-loud spirit).
- `Careers/CareerPerformanceScorer.cs:40-86` hard-codes scorer weights outside the rules snapshot, persisting only a `WeightsVersion` string.
- `Cups/ChaosCupFormat.cs:330-334` re-runs a per-group 4/color check already performed by `ValidateStageGroups(0, ...)` at `:363-369`.
- `TieBreaking/TieBreaker.cs:23-26,177-183` validates count vectors on every sort comparison (O(n log n) redundant work).

## Requirements

1. Assert the packing bound in `EncodeRawTotals` (fail loudly if a stage score exceeds the key's capacity).
2. Add a documented component-size or step guard (or memoize flow results) to the `SearchSubset` feasibility search so worst-case inputs fail loudly instead of hanging.
3. Validate rules once at snapshot load; keep cheap guards in hot paths. No observable behavior change; validation failures still abort the mutation.
4. Replace `is RulesV3` dispatch with virtual tiered-prestige accessors on the rules hierarchy so RulesV4+ resolve correctly.
5. Reduce construction risk in RulesV2/V3: introduce a shared carrier snapshot or equivalent compile-time-checked construction; the persisted rules JSON bytes and `RulesSnapshots` compatibility must remain unchanged (existing saves re-validate byte-identically).
6. Delete the listed dead code after re-verifying zero callers.
7. In prestige resolution, whitelist the known prestige-neutral honour kinds and abort on anything else.
8. Career scorer: either move the weights into the versioned snapshot or prove the persistence boundary rejects a mismatched `WeightsVersion` with a test; whichever is smaller.
9. Drop one of the redundant Chaos group validations; validate tie-break vectors once per entry (as `RankWithSeededDraw` already does).

## Architectural direction

- Kernel stays pure (no HTTP/EF/filesystem/clock/network). Fixed-point integers everywhere. No new abstractions beyond the carrier/accessors demanded above. Persisted rules JSON and all rule-version semantics are frozen.

## Acceptance criteria

- [ ] Guards exist for the packing bound and the subset search; focused kernel tests trigger both failure paths deterministically.
- [ ] Rules validation executes once per snapshot load, not per round call (asserted by test or by a counted-validation seam kept minimal).
- [ ] No `is RulesV3` casts remain; a test documents that V4-style subclasses resolve the new accessors.
- [ ] Dead code deleted; grep proves no references.
- [ ] Unknown honour kinds abort; known neutral kinds keep today's behavior.
- [ ] Existing golden seeds, checksums, rules JSON bytes, and the full kernel test tree are unchanged and green.

## Verification

Standard AGENTS.md backend sequence: locked restore, Release build, full test suite, `dotnet format --verify-no-changes`. Add the focused kernel tests above; run the kernel test tree alone from a fresh process.

## Out of scope

- Pipeline/comparator consolidation (MSS-151), qualifier engines (MSS-150), any rule default changes, persisted-JSON format changes, and any sporting outcome difference.
