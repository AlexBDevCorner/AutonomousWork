# MSS-154 - Consolidate the drifted frontend data hooks and fetch idioms

## Goal

One shared save-data hook with the out-of-order abort guard, one `isAbort` helper, one `formatPoints` implementation - removing copies that have already drifted and caused a real stale-data race.

## Context

- A repository review (2026-11-19) verified the following; re-verify on the live checkout.
- Four near-copies of a `useAsync`-style fetch hook exist and have drifted: `src/MtgSoloSports.Web/src/features/history/HistoryPage.tsx:48-92`, `features/qualifiers/QualifiersPage.tsx:44-89`, `features/records/RecordsPage.tsx:364-407` (`useSaveData`), and `features/standings/StandingsPage.tsx:77-86`. Only the Standings copy has the out-of-order `signal.aborted` guard, so the others can write stale data when a promise resolves just after a save/scope change, killing the new spinner or showing wrong-save data.
- The abort idiom `failure instanceof DOMException && ...` is inlined ~56 times across ~25 files; only `features/athletes/useAthleteProfile.ts:26` extracts it.
- `formatPoints(thousandths)` is copied 11 times: `features/reveal/format.ts:2`, `features/standings/matrix.ts:35`, `features/cups/cupFormat.ts:12`, `features/athletes/AthleteProfilePage.tsx:53`, `features/history/HistoryPage.tsx:44`, `features/history/HistoryEventView.tsx:25`, `features/live/LiveEventView.tsx:59`, `features/live/LivePage.tsx:30`, `features/qualifiers/QualifiersPage.tsx:40`, `features/dashboard/DashboardPage.tsx:27`, `features/dashboard/FeederLeaders.tsx:11`.
- `features/reports/ReportsPage.tsx:35-37` re-implements `fetchHistorySeasons` from `features/history/historyApi.ts:161`.
- No router/state libraries exist; hooks are hand-rolled `useEffect` + `AbortController` + revision counters. Keep that architecture.

## Requirements

1. Create one shared save-data hook (in `src/shared/`, it is a genuinely global concept) with: the out-of-order abort guard, refresh support, and the loading/error contract the pages already use. Migrate the four drifted copies to it; delete the copies.
2. Move `isAbort` into `src/shared/api/http.ts` and use it at every inline site.
3. Keep one `formatPoints` in a shared formatting module; delete the ten other copies.
4. `ReportsPage` consumes `fetchHistorySeasons` from the history API module.
5. No behavior change on happy paths beyond the bug fix: after migration, a stale resolution cannot overwrite newer state (this is the fix for History/Qualifiers/Records).
6. No new dependencies; no global state store.

## Architectural direction

- AGENTS.md: shared code only for genuinely global concepts - these are (fetch-abort handling, points formatting). Everything else stays feature-local. Dark presentation unchanged.

## Acceptance criteria

- [ ] One hook, one `isAbort`, one `formatPoints`; greps for the duplicated bodies return single hits.
- [ ] A regression test proves a slow stale response cannot overwrite a newer scope's data in a migrated page (simulate by resolving the old promise after a key change).
- [ ] Existing colocated hook tests (`historyHookOrder.test.ts`, `standingsHookOrder.test.ts`) and the full web test suite pass.

## Verification

Standard AGENTS.md web sequence: `npm ci`, `npm run test`, `npm run typecheck`, `npm run build` (backend sequence unchanged and green). Add the stale-response regression test colocated with a migrated page.

## Out of scope

- ReportsPage decomposition beyond the fetch reuse (MSS-155), ESLint gating (MSS-156), Live error-state work (MSS-146), and any UI redesign.
