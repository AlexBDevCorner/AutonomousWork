# MSS-018 — Implement full season state machine and Next Event progression

## Goal

Connect league stages, postseason movement and season boundaries into one legal backend progression model.

## Context

- Project: `mtgsolosports`.
- Target repository: `AlexBDevCorner/MtgSoloSports`.
- Default branch: `main`.
- Product rules: `docs/game-rules.md` in the target repository.
- Technical constraints: `docs/technical-design.md` and `AGENTS.md`.
- Architecture is vertical-slice modular monolith. **MediatR is forbidden.**
- Keep sporting simulation deterministic and use fixed-point integer arithmetic.

## Requirements

1. Represent legal phases/state transitions explicitly, including Season 1 special handling and normal Season 2+ postseason.
2. Implement `AdvanceToNextEvent` so the user can progress without knowing internal command ordering.
3. After Stage 32 execute/finalize movement, qualifier and rebalancing in the correct order while exposing each inspectable event boundary.
4. Finalize bonus season aging so next-season effective contributions use 80/60/40/20/0 correctly.
5. Start the next season only from a fully valid 32-per-league roster.
6. Expose legal next actions in dashboard/read models.
7. Reject illegal transitions rather than silently skipping/repairing state.
8. Add end-to-end tests through at least Season 1 -> inaugural Superleague -> Season 2 start and a normal later postseason.

## Architectural direction

- Avoid one giant god-service. The state-machine/orchestration slice should call focused feature operations.
