# MSS-058 — Generalize postseason movement and run qualifiers across adjacent league tiers

## Goal

Replace the current Superleague-only movement model with a generic adjacent-tier postseason system.

Athletes must earn every upward move through sporting results; there is **no division skipping**. The existing Superleague movement remains dynamic, while F1↔F2 and F2↔F3 gain their own automatic movement and qualifiers. An athlete may move at most one league level in one postseason.

## Context

- Depends on MSS-057.
- Current code is centered under `Features/Superleague` and assumes one boundary:
  - Superleague ranks 1-16 safe;
  - 17-24 qualifier incumbents;
  - 25-32 automatic relegation;
  - one champion from each of eight feeder leagues automatically promoted;
  - feeder ranks 2-4 (24 total) challenge in a 32-athlete qualifier;
  - top 8 qualifier athletes take/remain in Superleague.
- `QualifierRoundEntity` and `QualifierStandingEntity` currently identify only a season transition, so they cannot safely persist multiple qualifiers in the same transition.
- A literal copy of the current 8-incumbent + 24-challenger qualifier at every feeder boundary does **not** work: F2/F3 are intermediate divisions and the same athletes would become candidates for both upward and downward boundaries.
- The intended pyramid must preserve sportsmanship:
  - no exceptional skip promotion;
  - no strength-based shortcut;
  - every normal movement is one adjacent level only.

## Required movement semantics

### A. Superleague ↔ Feeder 1

Keep the existing rule unchanged:

**Superleague**
- ranks 1-16: safe;
- ranks 17-24: Superleague qualifier incumbents;
- ranks 25-32: automatically relegated to F1 of their sporting color.

**Feeder 1**
- rank 1 from each of the eight colors: automatically promoted to Superleague (8 total);
- ranks 2-4 from each color: Superleague qualifier challengers (24 total);
- ranks 5-16: remain in F1 unless affected later by structural rebalance;
- ranks 17-24: candidates for the F1↔F2 qualifier as incumbents;
- ranks 25-32: automatically relegated to F2.

The Superleague qualifier remains 32 athletes / 16 rounds / 8 winners and awards no new bonus.

### B. Feeder 1 ↔ Feeder 2, per sporting color

For each color independently:

**F1**
- ranks 17-24: qualifier incumbents (8);
- ranks 25-32: automatically relegated to F2 (8).

**F2**
- ranks 1-8: automatically promoted to F1 (8);
- ranks 9-16: qualifier challengers (8).

Run one **16-athlete qualifier** for that color:
- 8 F1 incumbents + 8 F2 challengers;
- same 16-round qualifier simulation principles;
- active bonus applies;
- no championship points or new career bonus;
- top 8 occupy/remain in F1;
- bottom 8 occupy/remain in F2.

This permits 8 guaranteed + up to 8 qualifier promotions into F1: at most 16/32 new F1 athletes.

### C. Feeder 2 ↔ Feeder 3, per sporting color

Use the same partition:

**F2**
- ranks 17-24: qualifier incumbents (8);
- ranks 25-32: automatically relegated to F3 (8).

**F3**
- ranks 1-8: automatically promoted to F2 (8);
- ranks 9-16: qualifier challengers (8);
- ranks 17-32: remain in F3 unless structural pool rebalance later requires movement.

Run one 16-athlete / 16-round qualifier per color; top 8 occupy/remain in F2, bottom 8 occupy/remain in F3.

### D. Common pool

- Pool is not a competitive tier.
- There is no ordinary "F3 bottom positions are relegated to pool" rule.
- Pool movement remains a structural rebalance mechanism handled by MSS-059.

## Requirements

1. Generalize automatic movement selection away from `Superleague`-specific assumptions.
   - Model a movement boundary explicitly.
   - Persist source/destination league and boundary identity unambiguously.
   - Every normal movement must be between adjacent levels.

2. Preserve the exact Superleague movement semantics above.

3. Implement eight F1↔F2 qualifiers and eight F2↔F3 qualifiers per ordinary postseason, one per sporting color.

4. Persist multiple qualifiers safely.
   - Add a qualifier/event identity to `QualifierRoundEntity` and `QualifierStandingEntity` (or equivalent normalized model).
   - Uniqueness/indexing must prevent rows from different qualifiers in the same season transition from colliding.
   - APIs must be able to request/list a specific qualifier and all qualifiers for a transition.

5. Feeder qualifier participants must be non-overlapping by rank band.
   - F2 ranks 1-8 are automatic-up only.
   - F2 ranks 9-16 can challenge upward only.
   - F2 ranks 17-24 can defend downward only.
   - F2 ranks 25-32 are automatic-down only.
   - No F2 athlete may appear in both the F1↔F2 and F2↔F3 qualifier fields.

6. An athlete may change at most one tier in one postseason.
   - A qualifier winner cannot immediately enter the next higher qualifier.
   - An automatically relegated athlete cannot also compete to avoid the next lower tier in the same transition.
   - All candidate bands come from the just-completed source season standings, not provisional next-season positions.

7. Qualifier simulation remains deterministic.
   - Use the existing versioned RNG and active-bonus scoring.
   - No new career bonus.
   - No normal league championship points.
   - Persist immutable replay payload/checksum/RNG before/after for each qualifier.
   - Define canonical qualifier execution order so equivalent state consumes RNG identically. Suggested order: Superleague qualifier first, then F1↔F2 by sporting-color enum, then F2↔F3 by sporting-color enum.

8. Generalize movement kinds/provenance as needed.
   - Historical UI/API must distinguish automatic promotion, automatic relegation, qualifier challenger/incumbent, qualifier win/loss, source tier, destination tier, and sporting color.
   - Do not overload "Superleague" names for feeder-boundary results.

9. Update lifecycle state so "qualifiers" is a phase containing multiple persisted qualifier events.
   - The phase is complete only when every required qualifier for that transition is resolved.
   - A retry resumes from persisted completed qualifiers and must not rerun them.
   - "Run all" automation may execute the remaining qualifiers in canonical order, but individual qualifier execution must remain possible for Live UI.

10. Keep Season 1's special inaugural transition supported.
    - The normal multi-boundary movement rules apply only where source standings/tier structure exist as intended.
    - Do not invent a normal pool qualifier.

11. Add robust invariants.
    - Exact participant counts per qualifier.
    - Exact rank bands.
    - Unique athlete per qualifier.
    - No athlete in contradictory movement roles.
    - Correct final higher/lower occupancy contributed by automatic + qualifier results.
    - No cross-color feeder movement.

12. Update career/history projections so qualifier participation across feeder boundaries is retained as history without pretending it is a major honour/title.

## Architectural direction

- Extract generic boundary concepts rather than cloning the entire `Features/Superleague/RunQualifier` folder 16 times.
- A qualifier should have a stable identity such as `Boundary + SportingColor(optional)` in addition to season transition.
- Keep the simulation kernel reusable across 16- and 32-athlete qualifiers. Do not hard-code `rules.LeagueSize == qualifier size` where the feeder qualifier is 16 athletes.
- Preserve the current Endpoint → Handler architecture; do not introduce MediatR.
- The one-tier-per-postseason invariant is a hard rule.

## Acceptance criteria

- [ ] Existing Superleague movement remains 16 safe / 8 automatic relegation / 8 incumbents, with 8 F1 champions automatic up and 24 F1 ranks 2-4 challenging.
- [ ] Each F1 color can receive 8 automatic F2 promotions plus up to 8 qualifier promotions.
- [ ] Each F2 color can receive 8 automatic F3 promotions plus up to 8 qualifier promotions.
- [ ] F1↔F2 and F2↔F3 qualifiers each contain exactly 8 incumbents + 8 challengers and produce exactly 8 higher-tier occupants.
- [ ] No athlete appears in two qualifier boundaries in the same postseason.
- [ ] No athlete moves more than one tier in the same postseason.
- [ ] F3 ranks 17-32 do not automatically enter the pool.
- [ ] Pool never participates in a qualifier.
- [ ] All 17 ordinary-postseason qualifiers (1 + 8 + 8) can be persisted, queried, replayed, and resumed independently.
- [ ] Qualifier replay uses persisted facts and never resimulates.
- [ ] Deterministic RNG order is fixed and tested.
- [ ] Active bonus applies in qualifiers but no new bonus/championship points are generated.
- [ ] History records source/destination tier and qualifier provenance correctly.

## Verification

1. Run full backend tests.
2. Preserve/add regression tests for the existing Superleague qualifier.
3. For one sporting color, test every F1/F2 and F2/F3 rank band boundary.
4. Test a full transition and assert no athlete id appears in more than one qualifier.
5. Test max-turnover cases where all eight lower challengers beat all eight upper incumbents.
6. Test zero-turnover-through-qualifier cases where all incumbents survive.
7. Test deterministic canonical execution order and retry after some qualifiers are already persisted.
8. Test API/history retrieval for multiple qualifiers in one transition.
9. Test that F3 bottom athletes remain in F3 before structural rebalance.

## Out of scope

- Pool draws/displacements and cascading structural rebalance.
- Broad UI/UX presentation of the 17 qualifiers.
- Any division skipping or "elite newcomer" exception.
- Different bonus generation inside qualifiers.
