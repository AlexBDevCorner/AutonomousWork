# MSS-005 — Import the MTG creature catalog and classify sporting colors

## Goal

Provide a local catalog of eligible unique creature-card names with the metadata required to create saves.

## Context

- Project: `mtgsolosports`.
- Target repository: `AlexBDevCorner/MtgSoloSports`.
- Default branch: `master`.
- Product rules: `docs/game-rules.md` in the target repository.
- Technical constraints: `docs/technical-design.md` and `AGENTS.md`.
- Architecture is vertical-slice modular monolith. **MediatR is forbidden.**
- Keep sporting simulation deterministic and use fixed-point integer arithmetic.

## Requirements

1. Implement a catalog-import slice that can ingest MTG card data from a well-defined bulk JSON input without requiring live network access in tests.
2. Only creature cards are eligible; exclude tokens and non-creature cards.
3. Collapse multiple printings of the same card name into one athlete candidate while retaining suitable display/art metadata.
4. Extract front-face printed color, hybrid-mana presence, Devoid, artifact status and creature types required by the game.
5. Implement sporting-color classification exactly: mono colors, Multicolor, Hybrid precedence, Devoid Colorless, and front-face handling for double-faced cards.
6. Persist/import catalog data separately from save databases so saves can later copy their selected athlete snapshot.
7. Add fixture-driven tests for mono-color, multicolor, hybrid, Devoid, artifact creature and double-faced cases.
8. Report catalog counts by sporting color and fail save creation later if any category cannot supply 256 unique athletes.

## Architectural direction

- Keep external-data parsing isolated from pure sporting classification rules; classification itself should be deterministic and unit-testable.
