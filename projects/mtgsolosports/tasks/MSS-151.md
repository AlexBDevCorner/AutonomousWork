# MSS-151 - Consolidate duplicated kernel selection and team-round pipelines

## Goal

Duplicated sporting logic inside `SimulationKernel` is consolidated so tie-break chains and round pipelines change in one place. Outcomes are byte-identical; the kernel stays pure.

## Context

- A repository review (2026-11-19) verified the following; re-verify on the live checkout.
- `SimulationKernel/Cups/TypeCupAllocation.cs:238-285` and `SimulationKernel/Cups/ColorCupSelection.cs:311-358` contain two verbatim copies of the seven-field selection comparator on near-identical records. A comparator change today must be made twice or the selections drift.
- `SimulationKernel/Cups/TeamEvent.cs:489-614` mirrors the shuffle/score/rank/validate pipeline of `SimulationKernel/Scoring/RoundSimulator.cs:113-297`.
- `Stages/StageCalculator.cs:209` re-implements `ScoringCalculator.ChampionshipPointsForPosition` by direct table indexing.
- The team-size literal `4` is repeated at `TypeCupAllocation.cs:537,612,1061,1263,1527` while feasibility uses `rules.TypeCupMinTeamSize` (`:1027`); today validation pins them equal, but a future `MinTeamSize < 4` would let feasibility accept subsets the min-cost stage then rejects at runtime.
- AGENTS.md: kernel purity, fixed-point integers, versioned RNG, fail-loud validation are normative. All consolidation must stay inside the kernel with no new dependencies.

## Requirements

1. Extract one shared selection comparator (shared kernel type, e.g. in `Cups` or `TieBreaking` as fits) used by both Type Cup allocation and Color Cup selection.
2. Extract one shared round pipeline (shuffle -> score -> rank -> validate) consumed by both `RoundSimulator` and `TeamEvent`, parameterized by the genuine differences (team vs individual context, rules accessors). Keep every validation and error message semantics.
3. `StageCalculator` uses `ScoringCalculator.ChampionshipPointsForPosition` instead of re-indexing the table.
4. Replace every literal team-size `4` in `TypeCupAllocation` with the rules value end-to-end (selection, feasibility, min-cost, and validation agree on one source).
5. Byte-identical outcomes: golden pinned seeds for affected Cup paths (Type Cup, Color Cup, stage scoring) produce identical payloads, checksums, and RNG consumption before and after. Do not replace pinned seeds or rule versions.

## Architectural direction

- Kernel-internal consolidation only; no HTTP/EF/filesystem/clock may appear. No generic abstractions - extract only what is genuinely shared today. Keep `checked` arithmetic and fail-loud validation intact.

## Acceptance criteria

- [ ] One comparator and one round pipeline exist; the duplicates are gone; a grep for the duplicated comparator body returns one hit.
- [ ] No team-size literal remains in `TypeCupAllocation`; all paths read the rules value.
- [ ] Golden-seed equivalence tests pass unchanged versus pre-refactor baselines recorded in the task evidence; the full kernel test tree passes.

## Verification

Standard AGENTS.md backend sequence: locked restore, Release build, full test suite, `dotnet format --verify-no-changes`. Record pre-refactor golden outputs for the affected Cup/stage paths first, then diff after. Run kernel-focused classes alone from a fresh process.

## Out of scope

- Qualifier engine consolidation (MSS-150), rule changes, seed changes, sporting-formula changes, or any outcome difference.
