# MSS-036 — Diagnose blank local startup and prevent reveal-board import regressions

## Goal

Make the MtgSoloSports frontend start reliably from an up-to-date clean checkout, and prevent an incorrect reveal-board import from silently breaking the whole application into a blank page. Diagnose whether the reported failure exists in the repository or comes from an outdated/mixed local checkout before making any code changes.

## Context

- Project: `mtgsolosports`; target repository: `AlexBDevCorner/MtgSoloSports`; default branch: `main`.
- User reported a completely blank local browser page at `http://localhost:5173` with the Vite console error:

  ```text
  Uncaught SyntaxError: The requested module '/src/features/reveal/revealBoard.ts'
  does not provide an export named 'RevealBoard'
  (at RoundReveal.tsx:3:10)
  ```

- A separate `/favicon.ico` 404 also appeared; it is unrelated and must not distract from the fatal import problem.
- IMPORTANT: inspection of the repository's current `main` on 2026-09-28 already showed the correct separation: `features/reveal/RoundReveal.tsx` imports `RevealBoard` from `./RevealBoard`; `features/reveal/RevealBoard.tsx` exports the React component and imports presentation helpers from lowercase `./revealBoard`; `features/reveal/revealBoard.ts` exports pure helper functions/types, NOT a `RevealBoard` component. The screenshot may therefore represent an earlier commit, mixed local files, stale Vite cache, or another local state. Do not assume `main` has the erroneous import without reproducing it.
- `MSS-035` introduced the larger reveal board and is currently in review; this task depends on it to avoid concurrent/conflicting edits. Start from the latest target branch once that task is done.
- Existing frontend `package.json` scripts: `test`, `typecheck` (`tsc -b`), and `build` (`tsc -b && vite build`). Existing `.github/workflows/ci.yml` already runs `npm ci`, frontend typecheck and frontend build.
- Follow `AGENTS.md` and existing React/TypeScript feature conventions. Maintain direct backend Endpoint → Handler architecture; no MediatR or unrelated sporting changes.

## Requirements

1. Investigate the exact reported exception. Compare imports and exports in `RoundReveal.tsx`, `RevealBoard.tsx` and `revealBoard.ts` on the latest target branch. Establish whether the error is reproducible on a fresh, matching checkout rather than assuming the screenshot is evidence of a current-branch defect.
2. Run the frontend tests, typecheck and production build from a clean dependency install. Start the Vite development server and verify that the app entry point and its reveal-board module graph load without the reported missing-export exception. Document the inspected commit and precise observations in the PR.
3. If the defect is present in the target branch, repair the actual cause with the smallest appropriate import/export or module-resolution change. Keep the React `RevealBoard` component distinct from the lowercase pure `revealBoard` helpers. Do not hide errors or add a duplicate/re-exported component to the wrong module merely to silence the exception.
4. If the clean target branch already works, explicitly document that the code is already correct; do not fabricate or introduce a source fix. Provide a short, reproducible local recovery procedure for an old/mixed checkout (checking branch and commit, fetching/pulling safely without discarding uncommitted changes, `npm ci`, stopping/restarting Vite and refreshing the browser; cache clearing only when genuinely necessary).
5. Ensure a reliable automated safeguard for this kind of whole-app import failure. First assess and preserve the existing CI frontend `typecheck` and `build` gates. If they already catch the exact wrong-import regression, prove that with a safe temporary local negative check (do not commit the intentional bug) and document the evidence; otherwise add a focused, lightweight regression check and wire it into CI. Avoid introducing a heavy new end-to-end test framework solely for this import issue.
6. Add/update concise frontend local-development troubleshooting instructions in `README.md` covering the reported failure and how to distinguish stale local files/Vite state from a committed source regression. Deliver a small PR even if the code on `main` needs no correction.
7. Confirm both Live-event reveal and historical replay still use the shared component, and leave the reveal experience and its presentation logic intact.

## Architectural direction

- Keep `RevealBoard.tsx` as the React component module and `revealBoard.ts` as pure presentation helpers; use unambiguous imports and consistent filename casing across platforms.
- Prefer an accurate diagnosis and a narrow regression guard to speculative changes to Vite config, bundling, global caches or unrelated code.
- Never reset or overwrite a developer's uncommitted files in troubleshooting instructions.

## Acceptance criteria

- [ ] The PR identifies the exact target commit investigated and explains whether the screenshot reflects a current source bug or likely stale/mixed local state, backed by clean-checkout verification.
- [ ] The local Vite application starts and its reveal-board module graph resolves without the missing `RevealBoard` export error.
- [ ] If a source fix was needed, `RoundReveal` imports the real component from the component module, and tests/build remain green; if not, the PR says plainly that no source fix was needed.
- [ ] Existing frontend test, typecheck and production-build gates all pass; the PR demonstrates whether the existing gates catch the reported wrong import and adds a focused guard only if necessary.
- [ ] README documents safe commands for inspecting/updating a stale local checkout and restarting Vite without deleting uncommitted changes.
- [ ] Live reveal and History replay behavior remains unchanged, and no sporting or backend logic is touched.
