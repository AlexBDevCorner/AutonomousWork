# MSS-057 — Seed three feeder divisions and provide a safe v1-to-tiered-save transition

## Goal

Make the tiered league model usable by real saves.

New tiered saves must start with three 32-athlete feeder divisions for every sporting color. Existing v1 saves must remain usable and gain a deterministic, non-destructive path into the tiered system without deleting career history or retroactively changing past seasons.

## Context

- Depends on MSS-056.
- Current Season 1 has eight feeder leagues: one 32-athlete league per color, with the remaining 224 athletes per color in the common pool.
- The save universe remains 2,048 athletes / 256 per sporting color.
- Under the new model, Season 1 should have:
  - 8 Feeder 1 leagues × 32;
  - 8 Feeder 2 leagues × 32;
  - 8 Feeder 3 leagues × 32;
  - no Superleague yet, preserving the existing inaugural-Superleague concept.
- That means 96 active feeder athletes per color and 160 athletes per color in the common pool.
- Pool remains a non-competitive reservoir.
- Current code with strong one-feeder assumptions includes `InauguralDrawSelector`, `Season1Invariants`, `Season1PersistedInvariants`, `GetSeason1Leagues`, and create-save/initial-league persistence.
- Existing saves may contain many seasons of valuable history. They must not require recreation.

## Requirements

1. New tiered saves must create exactly 24 Season 1 feeder leagues:
   - one F1, one F2, and one F3 league for each of the eight sporting colors;
   - each league contains exactly 32 athletes;
   - no athlete belongs to more than one active league.

2. Use a deterministic inaugural draw per color.
   - Start from the existing deterministic name-sorted + versioned-RNG shuffle principle.
   - From each 256-athlete color population, assign:
     - shuffled positions 1-32 to F1;
     - 33-64 to F2;
     - 65-96 to F3;
     - 97-256 to the common pool.
   - Preserve one persisted draw order/source of truth so reveal/replay never resimulates.

3. Update Season 1 invariants/checksums/read models for:
   - 96 active feeder athletes per color;
   - 160 pool athletes per color;
   - 768 active athletes globally;
   - 24 feeder leagues;
   - explicit feeder division in roster responses.

4. Preserve the special inaugural-Superleague concept.
   - Season 1 still has no Superleague.
   - The inaugural Superleague must still be formed from **F1** sporting performance, not directly from F2/F3 or pool athletes.
   - Existing inaugural rule of positions 1-4 from each color F1 producing 32 Superleague athletes remains the source of the inaugural Superleague.
   - Do not introduce tier skipping.

5. Add a safe sporting upgrade path for existing v1 saves.
   - Never rewrite old Season/Stage/Round/Standing/Bonus/Cup/Movement history.
   - Never reinterpret a historical v1 feeder as if F2/F3 existed at that time.
   - Existing save databases must remain openable.
   - A v1 save must be able to enter the tiered rules at a safe season boundary rather than requiring deletion/recreation.

6. The v1→tiered transition must preserve already-earned sporting positions.
   - Existing Superleague and existing feeder rosters remain authoritative for their current/historical season.
   - The existing feeder becomes F1 when the tiered system is activated.
   - Seed F2 and F3 from that color's current common pool using the same deterministic equal-probability/versioned-RNG principles as other pool draws.
   - Seed exactly 32 F2 and 32 F3 athletes per color.
   - Remaining athletes stay in the pool.
   - Do not demote current F1 athletes merely to populate new divisions.

7. Sporting-rule upgrade must be explicit in code and transactionally safe.
   - Do not hide it inside an EF schema migration.
   - Persist the new rules version, league rows, memberships, RNG-after state, and any upgrade marker atomically.
   - A retry/reload must not create duplicate feeder divisions or consume RNG twice.
   - If the save is not at a safe transition boundary, keep it on v1 until the boundary is reached rather than partially upgrading a live season.

8. Provide an inspectable result/read model for the upgrade/initialization.
   At minimum it must make it possible for later UI work to show:
   - created F2/F3 leagues;
   - which athletes were seeded into them;
   - remaining pool counts;
   - source/target rules version;
   - deterministic checksum/RNG provenance where the project uses those patterns.

9. Update `docs/game-rules.md` / technical documentation with the new Season 1 population and compatibility rule.

## Architectural direction

- Keep initial population selection and historical sporting migration separate from database schema migration.
- Reuse the existing deterministic inaugural-draw and pool-draw conventions rather than inventing a second RNG system.
- Make initialization idempotent and corruption-intolerant: partial tier creation should fail loudly rather than be silently repaired.
- Do not use bonus/rating/strength to seed new F2/F3 leagues during v1 upgrade. This is initial population creation, so equal-probability deterministic draw is the closest analogue to current Season 1/pool behavior.

## Acceptance criteria

- [ ] A new tiered save has 24 feeder leagues in Season 1 and no Superleague.
- [ ] Every color has F1/F2/F3 with exactly 32 athletes each.
- [ ] Every color has exactly 160 athletes in the pool after the inaugural draw.
- [ ] Global Season 1 active membership is exactly 768.
- [ ] The inaugural Superleague source is F1 only.
- [ ] Equivalent seed/catalog/rules state reproduces the same F1/F2/F3/pool assignment.
- [ ] Existing v1 saves still open and retain byte/semantic integrity of historical results.
- [ ] A v1 save can be upgraded at a safe season boundary without deleting history.
- [ ] Existing feeder rosters become F1; F2/F3 are seeded from the pool without demoting F1 athletes.
- [ ] Upgrade is idempotent and RNG-safe across retry/reload.
- [ ] No athlete is duplicated across F1/F2/F3/pool.
- [ ] Documentation reflects the new initial pyramid.

## Verification

1. Run full backend tests.
2. Add deterministic Season 1 draw tests for all three feeder divisions.
3. Assert exact per-color and global membership counts.
4. Verify inaugural-Superleague selection reads F1 only.
5. Build a representative v1 save fixture with historical seasons, upgrade it at the supported boundary, and prove:
   - historical rows/checksums remain unchanged;
   - F1 is preserved;
   - F2/F3 are populated once;
   - remaining pool counts are correct;
   - reopening/retrying does not change assignments or RNG.
6. Verify a v1 save not at a safe boundary is not partially upgraded.

## Out of scope

- Normal F1↔F2↔F3 promotion/relegation logic.
- Multi-qualifier postseason execution.
- Cascading rebalancing after normal movement.
- Final frontend presentation of the new pyramid.
