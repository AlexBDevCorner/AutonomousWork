# MSS-082 — Show Athlete History beside the profile summary at the top

## Goal

Place the existing **History** panel immediately **to the right of the Athlete Profile** summary on the Athlete page at desktop widths. The user frequently opens athlete pages to inspect their season-by-season results and wants History visible immediately, without scrolling past the other panels.

## Context

- Project: `mtgsolosports`; target repository: `AlexBDevCorner/MtgSoloSports`, branch `main`.
- Requested 2026-10-16 with a screenshot of World Breaker's Athlete page.
- The current top-left **Athlete Profile** card displays card artwork, identity, league, season/title/Cup totals, and active bonus. Most of the space directly to its right in the opening viewport is unused.
- **History / Season-by-season** currently sits several rows below Career, Bonus, Identity, Honours, Movements, Selections, and Records. Users must scroll down to reach it despite it being one of the most useful parts of the profile.
- The History table is information-dense and already has a deliberately wide panel as part of MSS-073. MSS-073 (responsive panel widths/heights) and MSS-076 (profile summary contents) are completed; preserve their outcomes.
- This is a **layout and ordering** change, not a request to rewrite the history table, change results, or redesign all cards.

## Requirements

1. **Top-row layout on desktop.**
   - Put the existing Athlete Profile summary on the **left** and the existing **History** panel directly to its **right**, aligned at the top of the page.
   - Prefer a compact profile column occupying roughly one normal card width, with History using the remaining width (approximately two normal columns on a three-column desktop grid), so its season-by-season table is readable.
   - Do not leave a large empty region to the right of the profile header; the first viewport should immediately show several rows of History as well as the athlete's name and career summary.
   - Keep the profile's card image aspect ratio, summary metrics, labels, active bonus and navigation controls intact. Do not squash the profile into unreadable columns to make room for History.

2. **Keep History fully functional.**
   - **Move/reposition the existing History panel**, do not duplicate it or implement a second copy with different data.
   - Retain its current title, season ordering, fields/columns, statuses, finishes, wins, placements, earned bonuses, championship points, interactions, and empty/loading states.
   - Preserve a sufficiently wide table at common desktop widths without hiding meaningful columns, clipping data or introducing avoidable horizontal scrolling.
   - Maintain bounded panel height and independent vertical scrolling for long athlete careers, with the heading accessible and all rows reachable as established by MSS-073.

3. **Reflow the other panels naturally.**
   - The remaining Career, Bonus, Identity, Honours, Movements, Selections, Records, Cups, Stories and any other existing sections should flow beneath the new profile/History top area.
   - Preserve their content and controls. Avoid awkward blank grid cells, overlapping panels, or unexpected giant vertical gaps caused by a tall profile or History.
   - Respect any existing wider-panel treatment (especially Cups); do not make unrelated changes to dashboard layout.

4. **Make responsive behavior deliberate.**
   - On narrower laptop/tablet/mobile viewports, reflow the pair rather than forcing two cramped side-by-side cards or page-level horizontal overflow.
   - When side-by-side presentation is no longer readable, stack **Athlete Profile first, History second**, **before** the less frequently consulted panels, so History remains high-priority.
   - Keep History data accessible in narrower layouts using existing responsive table behavior; maintain readable text and functional controls.
   - Ensure the layout handles new athletes with no history, short histories, and decorated athletes with many seasons.

## Architectural direction

- Inspect the Athlete page component, its responsive grid and the existing panel span/scroll primitives. Reuse existing patterns from MSS-073 rather than adding brittle absolute positioning or fixed pixel offsets.
- Place Profile and History in a leading responsive layout region or use intentional grid placement/order. Keep **one instance** of each panel and a clear DOM/tab order that matches visual reading order.
- Minimize changes to frontend layout markup/styles; no backend, DTO, persistence, game simulation or statistics changes.
- If the page is concurrently undergoing another visual pass, preserve the intent of this task: Profile left, History right and prominent on desktop; Profile then History on narrow screens.

## Acceptance criteria

- [ ] On a wide desktop Athlete page, the **History** panel begins immediately to the **right** of the Athlete Profile card, on the same top row.
- [ ] Season-by-season results are visible in the initial viewport without page scrolling; no large unused top-right area remains.
- [ ] Profile identity, artwork, season/title/cup metrics, active bonus and navigation controls retain their existing functionality and remain legible.
- [ ] The existing single History panel contains the same columns, values, order and interactions as before; no duplicate History appears farther down.
- [ ] History has enough width at typical desktop sizes (~1440px and ~1920px), with contained vertical scrolling for long careers and no unnecessary page-level horizontal scrolling.
- [ ] Career, Bonus, Identity, Honours, Movements, Selections, Records, Cups, Stories and other available panels remain accessible below, without missing content or grid gaps.
- [ ] At narrower viewport sizes, Profile stacks directly **above History**, followed by the remaining panels; neither is clipped or unreadably cramped.
- [ ] New/empty and long-history athlete profiles, navigation between athletes, and refresh behave correctly.
- [ ] Frontend tests, type-check and build remain green.

## Verification

1. View a long-career athlete such as World Breaker at ~1440px and ~1920px: verify Profile at top left and History at top right, with several season rows visible immediately.
2. Confirm the History table's original columns/values and interactions against the prior layout and verify scrolling to its final row.
3. Test smaller laptop/tablet/mobile viewport widths and ensure the reading order is Profile → History → remaining panels, without overlap, clipped fields, or page-level horizontal overflow.
4. Check a new/empty-history athlete, a short-career athlete, and a decorated athlete with many seasons, honours and Cup records.
5. Run the frontend's existing tests, type-check and build commands (currently `npm run test --prefix src/MtgSoloSports.Web`, `npm run typecheck --prefix src/MtgSoloSports.Web`, `npm run build --prefix src/MtgSoloSports.Web`). Include before/after desktop and narrow-width screenshots in the PR.

## Out of scope

- Any changes to athlete career/history data or calculations, statuses, awards, sporting rules or simulation.
- Adding new athlete metrics, restyling the full page, or redesigning individual panels.
- Changes to Dashboard, league standings, Cup pages or unrelated screens.
