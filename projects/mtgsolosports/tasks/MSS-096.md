# MSS-096 — Use Career Leaders points as squad-selection prestige

## Goal

Make career prestige in both Color and Type team selection the same weighted full-placement career history used by Career Leaders.

## Context

- Project `mtgsolosports`, target `AlexBDevCorner/MtgSoloSports` (`main`). .NET + React, direct vertical-slice Endpoint → Handler, no MediatR; follow `AGENTS.md`. Approved Chaos Cup: 8 sporting colors, 1024 entrants (all source-season league athletes plus random Pool invitations), six 32-athlete group stages [32,16,8,4,2,1], top 16 from each nonfinal group; 16 game rounds per group, active bonus used but not earned; no league points/promotion, group scores reset; first draw exactly 4/color/group, later draws pure random. Runs after 32 league stages and before promotion qualifiers, only for a new season after deployment; odd/even Color/Type Cups keep alternating. Existing sporting history must remain unchanged.
- Scope: **Use Career Leaders points as squad-selection prestige**. This is a single small PR, target roughly 200–600 changed lines where practical; if work expands materially, propose follow-up rather than bundling unrelated features.
- Dependencies: MSS-094, MSS-095; tasks with incomplete dependencies must wait.

## Requirements

1. Replace win-only `CupPrestigeCalculator` input for new selections with shared career-performance scores through the selected source season, including nonpodium league and Cup results.
2. Keep prestige weight 10%, normalized per sporting color for Color Cup and globally for Type Cup; preserve other selection weights until the Chaos-form task.
3. Version raw prestige breakdown and selection-report semantics; historical persisted teams and old reports remain readable/unmodified.
4. Test five Superleague P6 finishes versus a small title collection, long-career edge cases and no medal/placement double count.

## Architectural direction

- Reuse existing feature/simulation/report patterns; keep deterministic integer calculations, save-scoped state and clear compatibility boundaries. Do not introduce MediatR or unrelated refactors.

## Acceptance criteria

- [ ] Same historical career earns the same raw points in Career Leaders and new selection.
- [ ] Previously selected squads remain frozen; both new selection paths deterministic.

## Verification

`dotnet build MtgSoloSports.slnx --configuration Release` and `dotnet test MtgSoloSports.slnx --configuration Release` from target root. Add focused regression tests for the task's acceptance criteria and validate compatibility with prior editions. 

## Out of scope

- No Chaos-specific form, Pool eligibility change, or modification of old selection outcomes.
- Do not implement any other task or modify unrelated history/data merely for convenience.
