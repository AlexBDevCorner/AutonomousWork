# MSS-056 — Introduce a three-division feeder league model and tiered bonus scaling

## Goal

Generalize MtgSoloSports from one feeder division per sporting color into a four-level competitive pyramid:

**Superleague → Feeder 1 → Feeder 2 → Feeder 3**

Keep every active league at 32 athletes and preserve the existing sporting model, but make the amount of career bonus earned depend on league level. The new model must be generic enough that later movement, qualifier, rebalance, history, and UI work can reason about adjacent tiers without duplicating Superleague-specific code.

## Context

- Project: `mtgsolosports`; target repository: `AlexBDevCorner/MtgSoloSports`; default branch: `main`.
- Current persistence has `LeagueEntity.Kind` with only `Feeder` and `Superleague`.
- Current rules assume exactly eight regular leagues (`RegularLeagueCount = 8`), one 32-athlete feeder per color.
- `StageCalculator` / `ScoringCalculator` currently receive a boolean `isSuperleague` and `RulesV1.SuperleagueBonusMultiplier = 2`.
- Current regular-league bonus is the baseline; Superleague earns double.
- The new sporting intent is:
  - Superleague bonus = **2×** current regular-league bonus;
  - Feeder 1 = **1×**;
  - Feeder 2 = **1/2×**;
  - Feeder 3 = **1/4×**.
- Bonus decay by season age remains unchanged. Athletes in the pool continue to lose effective historical bonus naturally as seasons pass.
- Championship points, stage/season ranking, round shuffle probability, scoring table, tie-breaks, Cup scoring, and Cup no-new-bonus behavior are unchanged.
- Pool is **not** a fourth competitive division.
- Existing rule snapshots are intentionally immutable. Do not silently reinterpret historical v1 seasons as if they had three feeder divisions.

## Requirements

1. Add an explicit league-level concept capable of representing:
   - Superleague;
   - Feeder 1;
   - Feeder 2;
   - Feeder 3.
   Preserve the distinction between "league kind" and "feeder division" cleanly. Prefer keeping feeder leagues identifiable as feeders and storing/deriving their division explicitly rather than scattering new enum comparisons throughout the code.

2. Centralize hierarchy behavior.
   - Provide one canonical way to determine a league's level/order.
   - Provide helpers for "is feeder", "higher/lower adjacent tier", display name, and bonus scale.
   - Remove assumptions that every non-Superleague league is equivalent where that is no longer true.
   - Avoid hard-coded `if Feeder2 ... else if Feeder3 ...` logic repeated across features.

3. Introduce a new versioned sporting-rules representation for the tiered system rather than mutating the meaning of persisted v1 rules.
   - New saves created after this feature should use the new rules version.
   - Existing v1 rule snapshots must remain readable/valid.
   - Historical v1 results must not be rewritten or recalculated.
   - Database schema migration and sporting-rule migration must remain separate concepts, consistent with `SaveRulesCompatibility`.

4. Replace the single integer Superleague bonus multiplier with an exact, deterministic per-tier scale.
   Required scales:
   - Superleague: 2/1
   - Feeder 1: 1/1
   - Feeder 2: 1/2
   - Feeder 3: 1/4

5. Keep all bonus arithmetic fixed-point/integer-only.
   - No `double`, `float`, decimal rounding drift, or culture-sensitive arithmetic.
   - Define one deterministic truncation rule for fractional tier bonus and test it explicitly.
   - The existing bonus values that are exactly representable at a tier must remain exact.

6. Generalize round/stage bonus APIs away from `bool isSuperleague`.
   - `ScoringCalculator.RoundBonusForPosition`, `StageBonusForPosition`, `StageCalculator.Rank`, and callers should receive enough league-level information to apply the correct scale.
   - Ordinary scoring/championship points remain identical across divisions; only newly earned career bonus is scaled.

7. Preserve current bonus activation/aging rules.
   - Bonus earned in a stage activates at the next stage.
   - Stage 32 bonus first contributes next season at the existing age weight.
   - Historical contributions retain the amount that was actually earned in their original league level; moving divisions later must not retroactively rescale old contributions.
   - Pool residence continues to age bonus by season.

8. Extend league persistence/API read models sufficiently to identify feeder division without inferring it from league names.
   - Schema changes must migrate existing save databases safely.
   - Existing v1 feeder rows should be representable as Feeder 1 for historical display/compatibility, without pretending historical Feeder 2/3 leagues existed.

9. Audit code that currently assumes exactly eight feeder leagues or uses `LeagueKind.Feeder` as "all regular competition" and introduce reusable abstractions needed by later tasks.
   At minimum inspect:
   - `Persistence/Saves/LeagueEntity.cs`, `LeagueKind.cs`;
   - `SimulationKernel/Rules`;
   - `SimulationKernel/Scoring/ScoringCalculator.cs`;
   - `SimulationKernel/Stages/StageCalculator.cs`;
   - stage/season completion handlers;
   - league/standings/history DTOs.

10. Do not change honours/prestige semantics in this task.
    - A feeder championship remains a feeder championship for existing title/honour logic.
    - Do not invent different prestige weights for F1/F2/F3.
    - This task changes the amount of career bonus earned by division, not trophy value.

## Architectural direction

- Treat league level as domain data, not presentation text.
- Prefer an explicit `FeederDivision` / `LeagueLevel` concept plus shared hierarchy helpers.
- Keep `LeagueKind` useful for broad category checks if practical.
- Model fractional bonus scale as a rational numerator/denominator or equivalent exact integer representation in the rules snapshot.
- Existing v1 snapshots should continue through a v1 compatibility path; new tiered saves should use a v2-equivalent snapshot.
- Do not make later tasks depend on league-name parsing such as "Feeder 2 Blue".

## Acceptance criteria

- [ ] The domain can represent Superleague, F1, F2, and F3 distinctly.
- [ ] Feeder division is persisted and exposed without parsing names.
- [ ] New rules snapshots encode the tiered league/bonus model explicitly.
- [ ] Existing v1 snapshots remain valid and historical v1 seasons are not reinterpreted.
- [ ] Superleague earns exactly 2× the current regular bonus.
- [ ] F1 earns exactly the current regular bonus.
- [ ] F2 earns exactly half of F1 bonus.
- [ ] F3 earns exactly one quarter of F1 bonus.
- [ ] Fractional bonus scaling is deterministic fixed-point integer arithmetic with regression tests.
- [ ] Championship points and base round scoring are unchanged across league levels.
- [ ] Historical bonus is never rescaled because an athlete later moves to another division.
- [ ] Pool bonus aging remains unchanged.
- [ ] Stage/bonus code no longer relies on a Superleague boolean as the only league distinction.
- [ ] Existing backend tests for v1 sporting math remain green, with new v2/tier tests added.

## Verification

Run the standard repository checks from `AGENTS.md`, including the full backend test suite.

Add focused tests for:
1. each tier's round bonus;
2. each tier's stage bonus;
3. truncation for halved/quartered values;
4. bonus activation and season-age decay after cross-tier movement;
5. v1 rules snapshot compatibility;
6. v2 rules snapshot round-trip/validation;
7. league persistence/read models carrying feeder division.

## Out of scope

- No promotion/relegation or qualifier implementation yet.
- No pool/rebalance cascade yet.
- No Season 1 24-league population seeding yet.
- No broad frontend redesign.
- No change to Cup selection/scoring, title prestige, championship points, tie-breaks, or shuffle probability.
