# MSS-128 - Make legacy Chaos activation backfill safe under concurrent first reads

## Goal

Make legacy Chaos activation backfill safe under concurrent first reads while preserving existing save data and unrelated behavior.

## Context

- Project: `mtgsolosports`; target: `AlexBDevCorner/MtgSoloSports`.
- Bug scan on 2026-11-03, audited [main revision 321eb36](https://github.com/AlexBDevCorner/MtgSoloSports/tree/321eb367316252ad259aea6b2fc66cc1ce08b6a1). Line numbers refer to that revision.
- The AddChaosActivation migration creates an empty activation table for old saves. ChaosCupLifecycle.EnsureActivationAsync reads Id=1 and then independently inserts it at lines 74-75. Season-status/lifecycle reads call this path without the simulation lock, after the migration gate has been released. Two first readers can both see no row and attempt the same insert. A deterministic two-context reproduction synchronized immediately before SaveChangesAsync fails with SQLite Error 19: 'UNIQUE constraint failed: ChaosCupActivations.Id'. This failure was reproduced on unmodified main and again after removing unrelated Windows file-sharing blockers.

## Potential damage if not fixed

When an older save is first used with Chaos Cup support, two requests arriving together can make one fail. You may see an error while loading season status or trying to continue, and need to retry. The reproduced failure does not show lost match results or a damaged universe, but it makes the first use after an update unreliable.

## Requirements

1. Make first-use activation backfill atomic/idempotent across simultaneous readers and read/mutation overlap. Both callers must observe one validated activation row rather than an exception.
2. Preserve the forward-only legacy rule: EffectiveFromSeasonNumber is the first unstarted season, using CurrentSeason+1 as intended, including an already-created pending successor.
3. Do not allow a stale context to overwrite another caller's activation or leave a failed Added entity tracked. Ordinary reads must remain concurrent after initialization.
4. Add a deterministic regression with an empty activation table and two independent contexts synchronized after the missing-row observation and before insertion. Also cover ordinary retries and legacy pending-successor behavior.

## Architectural direction

Inspect Features/Cups/ChaosCup/ChaosCupLifecycle.cs:33-76, SeasonLifecycleEvaluator callers, and Persistence/Saves/Migrations/20261103000000_AddChaosActivation.cs. Use the smallest existing SQLite/save-scoped synchronization approach. Do not add a global simulation lock to every query. Follow target AGENTS.md and docs/testing.md; direct vertical slices, deterministic sporting math, no MediatR.

## Acceptance criteria

- [ ] Concurrent first backfills both succeed and persist exactly one row.
- [ ] Both callers return the same effective season and format version.
- [ ] Legacy current-season eligibility and pending-successor behavior remain unchanged.
- [ ] Existing ChaosLifecycleTests and the new concurrency regression pass.

## Verification

Run focused ChaosLifecycleTests and the new two-context concurrency test from a fresh process, then required backend checks. A fresh save with the activation row removed is sufficient to test the insertion race; do not simulate seasons for incidental setup.

## Out of scope

No changes to Chaos sporting rules, field selection, rankings, existing results, UI or unrelated schema migration behavior.
