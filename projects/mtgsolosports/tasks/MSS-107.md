# MSS-107 — Expose Chaos edition, group and round replay APIs

## Goal

Supply efficient read-only endpoints for live/historical cup browsing.

## Context

- Project `mtgsolosports`, target `AlexBDevCorner/MtgSoloSports` (`main`). .NET + React, direct vertical-slice Endpoint → Handler, no MediatR; follow `AGENTS.md`. Approved Chaos Cup: 8 sporting colors, 1024 entrants (all source-season league athletes plus random Pool invitations), six 32-athlete group stages [32,16,8,4,2,1], top 16 from each nonfinal group; 16 game rounds per group, active bonus used but not earned; no league points/promotion, group scores reset; first draw exactly 4/color/group, later draws pure random. Runs after 32 league stages and before promotion qualifiers, only for a new season after deployment; odd/even Color/Type Cups keep alternating. Existing sporting history must remain unchanged.
- Scope: **Expose Chaos edition, group and round replay APIs**. This is a single small PR, target roughly 200–600 changed lines where practical; if work expands materially, propose follow-up rather than bundling unrelated features.
- Dependencies: MSS-099, MSS-101, MSS-102; tasks with incomplete dependencies must wait.

## Requirements

1. Return edition status, six stage summaries and stage group counts without downloading 1008 rounds in one request.
2. For a selected group return 32 entrants, source tier/Pool, group standings, current progress and individual persisted game-round replay.
3. Expose official/temporary P16/P17 cutoff with clear provisional status; never simulate or draw via GET.
4. Provide stable save/season/group identifiers and clear not-drawn/in-progress/complete responses; test nonfinal/Final and partial groups.

## Architectural direction

- Reuse existing feature/simulation/report patterns; keep deterministic integer calculations, save-scoped state and clear compatibility boundaries. Do not introduce MediatR or unrelated refactors.

## Acceptance criteria

- [ ] A group can be replayed without fetching the full 1024-athlete edition.
- [ ] No unknown draw or nonexistent Final is portrayed as completed.

## Verification

`dotnet build MtgSoloSports.slnx --configuration Release` and `dotnet test MtgSoloSports.slnx --configuration Release` from target root. Add focused regression tests for the task's acceptance criteria and validate compatibility with prior editions. 

## Out of scope

- No athlete journey statistics, mutations, or frontend.
- Do not implement any other task or modify unrelated history/data merely for convenience.
