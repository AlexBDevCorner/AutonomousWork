# MSS-045 — Update live team standings after every postseason Cup round

## Goal

During a postseason **team** event, refresh the total team points table in the Live page's left sidebar **after every successfully completed round**, including rounds within the currently running rank group. Do not wait until all eight rounds of a group are finished. Watching teams move up and down during the event is part of the live simulation experience.

## Context

- Project: `mtgsolosports`; target repository: `AlexBDevCorner/MtgSoloSports`; default branch: `main`.
- Observed in the Season 2 **Type Cup team event**: the competition progresses correctly group by group and round by round, but the **total team points table in the left sidebar** updates only when a whole rank group has completed all eight rounds. For example, after Group 1 Round 1 the board still shows pre-group totals; the points from Group 1 appear only after Group 1 Round 8.
- Existing team format has four rank groups (team athletes #1 vs #1 through #4 vs #4), eight rounds in each. Team total ultimately comes from its four athletes' leg scores. The existing group-by-group, round-by-round simulation flow is correct; the **live standings refresh/projection** is the problem.
- Use the actual Live postseason UI implementation currently on `main` (and check recently merged changes before implementation). Existing related code includes `src/MtgSoloSports.Web/src/features/live`, `src/MtgSoloSports.Web/src/features/cups`, and backend `Features/Cups` / `SimulationKernel/Cups/TeamEvent.cs`. These are investigation starting points, not assumptions about where the current sidebar lives.
- MSS-044 separately removes the artificial 32-team Type Cup cap. This task must not reintroduce a 32-row display cap or assume a fixed number of team rows. It should be independently useful for existing valid team events and compatible with larger fields once MSS-044 lands.
- Follow `AGENTS.md` and `docs/game-rules.md`: simulation is backend-authoritative and deterministic, points are fixed-point integers, and UI replay uses persisted immutable round results.

## Requirements

1. Refresh the left-sidebar **total team points** table immediately after each successful **Next Round** action during a Type Cup team event, without waiting for the current eight-round rank group to complete. Apply the same behavior to a Color Cup team event if it uses the same round-by-round Live sidebar, without changing Color Cup's separate individual event.
2. Show **running team totals** from all *persisted* completed rounds so far: sum the current group's athlete contributions for rounds already played **plus** completed previous groups, without omitting in-progress group results, awarding unfinished rounds, or double-counting completed groups. Before any rounds, show the valid initial state (e.g. zero for each participating team). Every participating team remains in the sidebar throughout the event.
3. Display updated points and standings order after each persisted round (including any applicable stable/informational tie ordering). Clearly distinguish **provisional live standings** from final official team rank/medals: do not award medals or silently apply the final team tie-break logic before the event is complete unless that is explicitly supported by the existing rules.
4. Keep the existing group/round schedule, round simulation, points calculation, bonuses, official completed-leg rankings, and final Cup results **unchanged**. Read authoritative saved progress/round results or an authoritative backend projection. Do **not** calculate new sporting outcomes independently in React or resimulate to refresh the board; display-only formatting is fine.
5. Keep the sidebar and current event progress consistent after refresh/navigation, page reload, switching saves, entering the next rank group, and reopening an unfinished event. Do not show stale results from another save, event or season; handle an unavailable/failed refresh without displaying invented totals. A failed Next Round must not optimistically award unsaved points.
6. **Run remaining rounds** must still leave the sidebar in the correct final state when the bulk action returns. If that action exposes individual persisted-round progress to the UI, refresh the sidebar at each visible round boundary; do not require adding streaming/polling infrastructure solely for an otherwise atomic bulk operation.
7. Support the actual dynamically sized Type Cup field, including the larger legitimate fields enabled by MSS-044; render all participating teams with no hard-coded 32-team limit. Preserve existing sidebar usability on wide screens.

## Architectural direction

- Investigate whether the sidebar currently reads only completed **leg** standings and therefore ignores persisted rounds in an in-progress group, or whether mutation-driven refresh/invalidation is missing. Resolve the actual cause rather than adding cosmetic client-side score estimates.
- Prefer a single authoritative live-team-standings projection from persisted round payloads and completed legs (or a suitable existing read endpoint) so page reload and incremental UI refresh agree exactly.
- Reuse existing Live refresh and save-scoped request patterns. Ensure asynchronous refresh results cannot overwrite newer state after a subsequent round or save change.
- Keep team event scoreboard behavior feature-local. Do not introduce new generalized state management architecture just for this board.

## Acceptance criteria

- [ ] In a Type Cup event, after **Group 1 Round 1**, the sidebar already includes that round's earned points for all participating teams, without waiting for Group 1 Round 8.
- [ ] Each subsequent Next Round visibly updates cumulative sidebar scores and provisional team ordering using only successfully persisted results.
- [ ] At the Group 1 Round 8 → Group 2 Round 1 boundary, earlier group scores remain counted exactly once, and the first round of Group 2 contributes immediately. The same works through groups 3 and 4.
- [ ] Reloading or reopening halfway through a group reproduces the same live totals and ordering from saved state.
- [ ] All participating teams remain listed for varying valid field sizes; the fix works alongside MSS-044 for a 35-team Type Cup.
- [ ] Final sidebar totals agree with the persisted official completed-event team results; final result/medal behavior is unchanged.
- [ ] Failed round mutations do not change totals, and quick consecutive round actions or save navigation cannot display stale totals.
- [ ] If Color Cup team has the equivalent live sidebar, its points refresh each persisted round too.

## Verification

1. Run the project's documented backend test/build checks; also run frontend typecheck, tests and build where relevant.
2. Add focused deterministic tests of the authoritative live total/projection for zero rounds, the first round, mid-group, crossing group boundaries, and complete event. Include variable Type Cup field sizes where the implementation permits.
3. Add UI tests for successful per-round refresh, failed round actions, reload/reopen, and stale asynchronous responses where applicable.
4. Manually exercise Next Round during a Type Cup team event and verify the left table changes after **each** persisted round; finish via Run remaining rounds and compare with official totals.

## Out of scope

- Changing the four-group/eight-round format, sporting scoring or final medal/ranking rules.
- Implementing the 32-team-cap removal itself (MSS-044 owns that).
- Redesigning the Live sidebar or unrelated league standings pages.
- Adding live server push/streaming for an otherwise atomic bulk simulation operation.
