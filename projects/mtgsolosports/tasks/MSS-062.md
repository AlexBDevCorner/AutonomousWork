# MSS-062 — Run Type Cup qualification groups and the 32-team Final as resumable postseason events

## Goal

Implement the sporting execution of the scalable Type Cup format from MSS-061.

For fields above 32 teams, play every persisted qualification group, advance the required teams, then play a fresh 32-team Final. Preserve the existing step-by-step/one-shot equivalence, deterministic RNG chain, active-bonus behavior, permanent nationality, history, honours, and corruption checks.

## Context

- Depends on MSS-061.
- Current `RunTypeCupTeamHandler` treats the entire Type Cup as one event with four athlete-rank groups and eight rounds each.
- Current `PostseasonEvents` has one stable `type-cup-team` event key and assumes one event shape.
- Current round persistence is resumable and validates a contiguous RNG chain across the four athlete-rank groups.
- The new tournament can have:
  - zero qualification groups + one Final for <=32 teams;
  - two or more qualification groups + one Final for >32 teams.
- Each competition stage still uses the existing four athlete-rank groups and eight rounds per group.
- Qualification is a sporting stage, not a title. Only Final standings award Type Cup medals/title honours.

## Requirements

1. Generalize the Type Cup team event state machine into tournament stages:
   - direct Final when team count <=32;
   - qualification group(s), then Final when team count >32.

2. Qualification groups must run in a fixed deterministic order based on the persisted group number.
   Within each qualification group, preserve the existing rank-group order:
   - #1 group rounds 1-8;
   - #2 group rounds 1-8;
   - #3 group rounds 1-8;
   - #4 group rounds 1-8.

3. Final runs only after every required qualification group is complete and its qualified teams are persisted.

4. The Final always contains exactly 32 teams for an over-32 field.
   - Use the exact persisted quota from MSS-061.
   - Select the top teams from each qualification group by that group's completed team standings.
   - No wildcard/strength/rating override outside the defined quota.

5. Qualification and Final scores are independent.
   - Final leg/team scores start at zero.
   - Qualification performance is retained in history but contributes no points to Final team ranking.

6. Preserve scoring semantics:
   - active career bonus applies in qualification and Final;
   - no Cup round generates new career bonus;
   - no league championship points are generated;
   - all round fields are <=32 and use the standard scoring table.

7. Preserve deterministic team ranking/tie-break behavior independently inside every qualification group and inside the Final.

8. Persist qualification results separately from Final results.
   Historical data must support:
   - qualification group team rank/score;
   - each athlete's qualification leg result;
   - qualified/eliminated state;
   - Final team/leg standings for finalists;
   - tournament checksum/provenance.

9. Permanent Type Cup nationality must reflect actual participation.
   - A selected athlete whose team participates in a qualification group has represented that creature type even if the team is eliminated before the Final.
   - Such athletes must become permanently capped to that Type Cup nationality under the existing rule.
   - Direct-final participants likewise become capped.
   - Do not cap merely selected teams that never actually enter a persisted competition stage because of corruption/cancellation before play.
   - Persist nationality idempotently and never allow an existing cap to change.

10. Honours and medals are Final-only.
    - Qualification group winners receive no Type Cup title/medal honour.
    - Official Gold/Silver/Bronze come only from Final ranks 1-3.
    - Existing MSS-047 top-three honour semantics apply to the Final podium only.
    - Qualification success may appear in career/history statistics but is not a major honour.

11. Generalize round-by-round APIs and `PostseasonEvents`.
    - The backend must expose the current tournament stage/group/rank-group/round.
    - A single "play next Type Cup round" action must resume the correct persisted next round.
    - One-shot "run Type Cup" must execute exactly the same sequence/result as repeated next-round calls.
    - Reload after any persisted round must resume without replaying or consuming RNG twice.

12. Preserve the save RNG ownership rule.
    - A partially played qualification group or Final owns the save RNG until the Type Cup can legally continue.
    - Other random postseason events must not interleave and corrupt the chain.

13. The lifecycle should still treat Type Cup as one high-level postseason competition.
    - Do not create one Dashboard lifecycle step per qualification group.
    - Internal progress may expose "Qualification Group 2 of 3" and Final state.
    - Cup is complete only when Final results are persisted.

14. Update result/query APIs so callers can retrieve:
    - tournament summary;
    - qualification draw;
    - each qualification group result;
    - list of 32 finalists;
    - Final result;
    - champion/podium.
    Preserve convenient direct-final behavior for <=32 teams.

15. Keep old-format Type Cup reads compatible.
    - Existing single-event historical saves must still load.
    - Do not attempt to manufacture qualification history for an old 33-35-team Cup.

## Architectural direction

- Prefer a Type Cup tournament coordinator/state model around the existing team-event simulation kernel rather than duplicating the four-rank-group logic.
- Existing `TeamEvent` ranking/simulation should remain reusable for one competition field.
- Separate "competition stage identity" from athlete rank group.
- Keep direct Endpoint → Handler architecture and existing per-save lock.
- Preserve immutable persisted replay facts; history/query endpoints must never resimulate.

## Acceptance criteria

- [ ] <=32-team Type Cups still behave as a direct Final.
- [ ] >32-team Type Cups run all qualification groups before the Final.
- [ ] Exactly the persisted quota advances from each qualification group.
- [ ] Exactly 32 teams enter the Final.
- [ ] Final scores start from zero.
- [ ] Qualification and Final each use four rank groups × eight rounds.
- [ ] No round field exceeds 32 teams.
- [ ] Active bonus applies; no new Cup bonus/championship points are generated.
- [ ] Eliminated qualification teams/athletes remain in historical results.
- [ ] Qualification participants receive/retain permanent Type Cup nationality correctly.
- [ ] Only Final top 3 receive official podium honours/medals.
- [ ] Step-by-step and one-shot execution produce identical persisted outcomes/checksum/RNG-after state.
- [ ] Reload/retry after partial progress resumes idempotently.
- [ ] Old single-field Type Cup history remains readable.

## Verification

1. Run full backend tests.
2. Add end-to-end cases for 32, 33, 35, 64, 65, and 97 teams.
3. For >32 fields, verify every qualification group contains <=32 teams and Final contains exactly 32.
4. Compare one-shot vs round-by-round execution from identical save/RNG state.
5. Stop/reopen after:
   - qualification group 1 round 3;
   - after one full qualification group;
   - after all qualification groups but before Final;
   - Final group #3 round 4;
   and verify exact continuation.
6. Verify qualification scores are absent from Final score totals.
7. Verify eliminated teams receive no podium honour but their athletes retain nationality after actual participation.
8. Verify Final champion/runner-up/third honours remain exactly four athlete honours per team.
9. Verify old-format Type Cup result endpoints still work.

## Out of scope

- UI/Live/history presentation details beyond API contracts.
- Changes to squad allocation quality/eligibility.
- Strength-based qualification seeding or wildcards.
- Two-leg/knockout/bracket formats.
- Color Cup changes.
