# MSS-130 - Prevent silent precision loss when entering deterministic save seeds and streams

## Goal

Prevent silent precision loss when entering deterministic save seeds and streams while preserving existing save data and unrelated behavior.

## Context

- Project: `mtgsolosports`; target: `AlexBDevCorner/MtgSoloSports`.
- Bug scan on 2026-11-03, audited [main revision 321eb36](https://github.com/AlexBDevCorner/MtgSoloSports/tree/321eb367316252ad259aea6b2fc66cc1ce08b6a1). Line numbers refer to that revision.
- SavesPage.tsx:70-74 parses seed and stream with Number and accepts Number.isInteger. JavaScript rounds integers above 2^53-1, while CreateSaveRequest accepts nullable ulong. Reproduction: Number('9007199254740993') becomes 9007199254740992, passes current validation, and savesApi.ts serializes the rounded number. Two distinct valid ulong inputs therefore create the same request and the UI silently simulates a different universe from the requested seed. The same defect affects stream.

## Potential damage if not fixed

Entering a large seed or stream number can create a different universe from the one you requested, without showing an error. Two different numbers can produce the same request, so attempts to reproduce or compare a particular universe become unreliable. Existing saves are unaffected; the problem happens when you create a new one with a number the form cannot represent exactly.

## Requirements

1. Never silently round an entered deterministic seed or stream. Either preserve the full supported unsigned 64-bit value through a compatible exact transport, or explicitly reject values outside the exactly supported UI range before sending a request.
2. Apply the same validation to seed and stream. Blank must retain random generation; valid existing safe integers must retain their current behavior.
3. Reject negative, fractional, nonfinite and out-of-range input with a clear field-related message. Do not change RNG algorithm, seed interpretation or existing saved states.
4. Add behavioral tests that inspect the request sent by the form. Cover 9007199254740991, 9007199254740992, 9007199254740993 and 18446744073709551615 for both fields, plus blank and ordinary integers.

## Architectural direction

Inspect features/saves/SavesPage.tsx:60-87 and savesApi.ts:createSave, plus backend Features/Saves/CreateSave/CreateSaveRequest.cs. Prefer the smallest compatible fix; do not change the backend API merely to add unsupported flexibility. If retaining numeric JSON, reject unsafe integers instead of claiming full ulong UI support. Follow target AGENTS.md and docs/testing.md; direct vertical slices, deterministic sporting math, no MediatR.

## Acceptance criteria

- [ ] Input 9007199254740993 never submits 9007199254740992.
- [ ] Seed and stream have consistent documented range/error handling.
- [ ] Blank inputs still request random values and safe integers retain exact deterministic behavior.
- [ ] Mounted form/API serialization tests and frontend checks pass.

## Verification

Run frontend tests, typecheck and build. Verify the actual serialized body or verify that an unsafe input produces no request. A standalone Number calculation illustrates the defect but does not replace a regression through the form.

## Out of scope

No RNG/version changes, alteration of saved universes, general numeric-input abstraction or unrelated save UI redesign.
