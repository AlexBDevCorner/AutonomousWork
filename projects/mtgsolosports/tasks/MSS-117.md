# MSS-117 — Add factual Chaos records and conservative Tournament Stories

## Goal

Show useful historic firsts, milestones and occasional surprise cards using only persisted facts.

## Context

- Project `mtgsolosports`, target `AlexBDevCorner/MtgSoloSports` (`main`). .NET + React, direct vertical-slice Endpoint → Handler, no MediatR; follow `AGENTS.md`. Approved Chaos Cup: 8 sporting colors, 1024 entrants (all source-season league athletes plus random Pool invitations), six 32-athlete group stages [32,16,8,4,2,1], top 16 from each nonfinal group; 16 game rounds per group, active bonus used but not earned; no league points/promotion, group scores reset; first draw exactly 4/color/group, later draws pure random. Runs after 32 league stages and before promotion qualifiers, only for a new season after deployment; odd/even Color/Type Cups keep alternating. Existing sporting history must remain unchanged.
- Scope: **Add factual Chaos records and conservative Tournament Stories**. This is a single small PR, target roughly 200–600 changed lines where practical; if work expands materially, propose follow-up rather than bundling unrelated features.
- Dependencies: MSS-104, MSS-108, MSS-112; tasks with incomplete dependencies must wait.

## Requirements

1. Compute titles, medals, finals, consecutive progress, best Pool/F1/F2/F3 performance, color records and repeated P16 survival from completed history.
2. Display conditional, source-linked story cards for defended title failures, record-setting runs and genuinely notable underdogs; absence of a story is allowed.
3. Initial upset definitions must be conservative; ranking above a star in a group is not a head-to-head duel, and the story score has no sport effects.
4. Keep versioned initial thresholds small/easy to calibrate and add counterexample tests.

## Architectural direction

- Reuse existing feature/simulation/report patterns; keep deterministic integer calculations, save-scoped state and clear compatibility boundaries. Do not introduce MediatR or unrelated refactors.

## Acceptance criteria

- [ ] Stories are factually reproducible and can legitimately be empty.
- [ ] No title inflation, invented head-to-head result or points impact.

## Verification

`dotnet build MtgSoloSports.slnx --configuration Release` and `dotnet test MtgSoloSports.slnx --configuration Release` from target root. Also `npm run typecheck --prefix src/MtgSoloSports.Web` and `npm run build --prefix src/MtgSoloSports.Web`. Add focused regression tests for the task's acceptance criteria and validate compatibility with prior editions. 

## Out of scope

- No LLM API, AI-written articles or modified scoring.
- Do not implement any other task or modify unrelated history/data merely for convenience.
