# MSS-139 - Link league, color and Cup team names across Dashboard, Records, Standings, Live, History and search

## Goal

Apply the same linking to league, color team and Cup team names on every other page. Wherever one of these entities is named, the player can click through to its page.

## Context

- Project `mtgsolosports`, target `AlexBDevCorner/MtgSoloSports` on `main`. MSS-138 adds these links to the athlete profile and may add a reusable league link plus backend identity fields. Reuse them.
- Athlete names are already linked everywhere through `AthleteLink`. Cup pages already link teams through `TeamBadge`. League profile, Cup team and Cup edition pages already link well internally.
- An audit of `src/MtgSoloSports.Web/src/features` found these entity names still rendered as plain text:
  - **Dashboard** (`dashboard/DashboardPage.tsx`): the leaders table **Color** column (`row.sportingColorName`), the league honours table **League** column (`honour.leagueName`), and the Cup context honour list (`· Season N · leagueName`).
  - **Records** (`records/RecordsPage.tsx`): the career leaders color sub-label (`row.sportingColorName`), the honours table **League** column (`row.leagueName`, which already has `row.leagueId`), and team record holders (`holder.teamName || holder.teamKey`, shown alone or in brackets after an athlete).
  - **Standings** (`standings/StandingsPage.tsx`): the row color sub-label (`row.sportingColorName`).
  - **Live** (`live/LivePage.tsx`): the standings card title league name, with a **Full standings** link but no league profile link, and the **Color** column (`row.sportingColorName`). In `live/LiveEventView.tsx`, Cup team standings rows show `row.teamName`.
  - **History** (`history/HistoryPage.tsx`, `history/HistoryEventView.tsx`): stage and season table titles name the league, and postseason team standings rows show `row.teamName`.
  - **Athlete search** (`athletes/AthleteSearchPage.tsx`): the result row sub-label shows color and types, and the current league column shows `row.currentLeagueName`.
  - **Qualifiers** (`qualifiers/QualifiersPage.tsx`, `live/LiveQualifierView.tsx`): entrant rows show `row.sportingColor` and `row.fromLeagueName`.
  - **League profile** (`leagues/LeagueProfilePage.tsx`): a colored feeder league does not link to that color's Color Cup team.
  - **Movement and rebalance reveals** (`movement/MovementReveal.tsx`, `rebalance/RebalanceReveal.tsx`): boundary headings and summary tables show league names and `from → to` text.
- Builders live in `features/routing/routes.ts`: `leaguePath`, `standingsLeaguePath`, `cupTeamPath`, `cupEditionPath`. Stable league identity is `LeagueKey` in the backend and `leagueKeyFor` in `features/leagues/leagueKeys.ts`. A Type team key is the creature type exactly as stored. A Type team that never fielded a squad returns 404.

## Requirements

1. On each surface listed in Context, a league name links to that league's profile. The Live and History table titles keep their existing standings links and add a league profile link.
2. A sporting color shown as an athlete or row attribute links to that color's Color Cup team page.
3. A Cup team name in Live, History and Records team rows links to its Color or Type team page.
4. A colored feeder league's profile page links to that color's Color Cup team.
5. Reveal pages link league names only in revealed headings and post-reveal summary tables. Links never reveal hidden placements, never autoplay and never rerun a sporting action.
6. Text that has no reliable identity stays plain text. Never build URLs from parsed display names. Absent or legacy identity renders the name as before.
7. Links use real anchors from the existing router, with native new-tab behavior, visible focus and current table styling. Dense tables must not grow wider or wrap more than they do today.

## Architectural direction

- Reuse the league link and identity fields from MSS-138, `TeamBadge` and the existing route builders. Add backend identity only as additive read-only response fields in the owning feature slice (for example `leagueKey` or `teamKey`). Prefer fields already present (`leagueId`, `sportingColor`, `currentLeagueLevel`, `currentLeagueDivision`) where they identify the entity unambiguously.
- One shared component per entity kind (league, color team) is justified by the real reuse across pages. Keep them minimal. MUST NOT add a generic entity or link registry.
- Each page change stays inside that page's feature folder apart from the shared link components.

## Acceptance criteria

- [ ] On a tiered save, each surface listed in Context shows working links for its league, color and Cup team names. Each link opens the correct page.
- [ ] Records honours and Dashboard honours link to the league profile. A team-only record holder links to its team page.
- [ ] Live and History league titles offer a league profile link, and the existing standings links still work.
- [ ] Reveal pages show no link that exposes an unrevealed result. Continue and Back behavior is unchanged.
- [ ] Missing or legacy identity renders as plain text. No link targets a guessed URL or a never-fielded Type team.
- [ ] Frontend tests cover link targets and fallbacks on each changed page. Backend tests cover any new response fields.

## Verification

- Run the repository-required backend checks in `AGENTS.md`, including focused tests for any changed endpoints.
- Run `npm test --prefix src/MtgSoloSports.Web`, `npm run typecheck --prefix src/MtgSoloSports.Web`, and `npm run build --prefix src/MtgSoloSports.Web`.
- In a test save, click each new link on Dashboard, Records, Standings, Live, History, Athlete search, Qualifiers, a feeder league profile and a completed movement reveal. Check Ctrl-click and Back on each.

## Out of scope

- The athlete profile page, which MSS-138 covers.
- Linking creature types in type lines or search sub-labels to Type Cup teams, since many types have no team page.
- Reverse links from Color team pages to their feeder leagues, new pages, route shapes, navigation menus or breadcrumbs.
- Any change to simulation, persistence schema, sporting rules, reveal ordering or page layout beyond inline links.
