# MSS-064 — Make Cup season performance and recent form league-strength aware

## Goal

Correct the Cup selection inputs so an identical sporting result is worth more when achieved against stronger league competition.

Keep the existing Cup selection composition at **35% effective bonus / 30% completed-season performance / 25% recent form / 10% career prestige**, but make season performance and recent form explicitly aware of Superleague / Feeder 1 / Feeder 2 / Feeder 3.

Also fix the current recent-form semantics so "recent" means the final ten stages of the completed source season, not the athlete's ten most recent appearances across arbitrarily old seasons.

## Context

- Project: `mtgsolosports`; target repository: `AlexBDevCorner/MtgSoloSports`; default branch: `main`.
- Depends on MSS-063, after the multi-division pyramid and Type Cup format are integrated.
- Both Color Cup and Type Cup currently use the same 35/30/25/10 selection formula.
- Current completed-season performance is raw `SeasonStandingEntity.TotalChampionshipPointsThousandths`.
- Current recent form is built from `StageStandingEntity.ChampionshipPointsThousandths` using the latest ten stage rows the athlete has ever played.
- Every league awards the same championship-point table, so current performance/form values do not distinguish a Superleague result from the same F1/F2/F3 result.
- Current effective bonus already contains league-quality information through the tiered bonus generation introduced by MSS-056; therefore performance/form should use a **softer** competition-strength adjustment rather than duplicating the bonus 2×/1×/1/2×/1/4× scale.
- Color Cup considers the whole save population by original sporting color, including Pool athletes. Type Cup considers current active athletes only.

## Required league-strength scale

Add a versioned Cup performance/form competition-strength factor:

| League level | Factor |
| --- | ---: |
| Superleague | 1000 permille (1.00) |
| Feeder 1 | 800 permille (0.80) |
| Feeder 2 | 600 permille (0.60) |
| Feeder 3 | 400 permille (0.40) |

These are selection-rating factors only. They do not alter league scoring, championship points, promotion/relegation, bonus generation, or persisted historical standings.

## Requirements

1. Add the competition-strength factors to the versioned sporting rules used by new tiered saves.
   - Store exact integer permille values.
   - Validate ordering: Superleague > F1 > F2 > F3 > 0.
   - Existing v1 snapshots remain readable and unchanged.
   - Historical single-feeder v1 competition maps conceptually to F1 when a future selection calculation legitimately needs its league strength.

2. Introduce one shared pure helper/calculator for Cup selection league strength.
   It must resolve an explicit persisted league level and return the versioned factor without parsing league names.

3. Redefine **completed-season performance raw** for Cup selection as:
   `source-season championship points × source league strength factor / 1000`
   using checked deterministic integer arithmetic.

4. Performance must use the athlete's league in the completed **source season**.
   - Superleague/F1/F2/F3 athletes receive the corresponding factor.
   - A Pool athlete has no source-season standing and therefore performance raw remains zero.
   - Do not use the athlete's next-season league after postseason movement.

5. Redefine **recent form** as exactly the completed source season's final ten league stages:
   - stages 23-32 under the current 32-stage rules;
   - retain recency weights 1..10 oldest-to-newest within those ten stages;
   - apply the athlete's source-season league-strength factor to the resulting form value.
   Generalize the window from `StagesPerSeason` and `RecentFormStageCount` rather than hard-coding 23/32.

6. An athlete with no league participation in the source season must have form raw = 0.
   - Historical stages from older seasons must not leak into current form.
   - This specifically fixes Color Cup Pool athletes retaining stale "recent form" from seasons ago.

7. An active athlete must have a complete valid source-season form window when Cup selection runs.
   - Missing/corrupt expected stage rows for an active completed-season athlete should fail validation rather than silently fall back to older stages.
   - Preserve compatibility for historical persisted Cup selection reports: never recompute old selections just to apply the new formula.

8. Use the same performance/form implementation in both Color Cup and Type Cup.
   - Avoid two copies of league-level lookup/scaling logic in `SelectColorCupTeams` and `SelectTypeCupTeams`.
   - Type Cup still restricts candidates to active athletes; Color Cup candidate eligibility remains unchanged.

9. Keep the outer selection weights unchanged:
   - bonus 350 permille;
   - performance 300;
   - form 250;
   - prestige 100.
   Do not rebalance these weights in this task.

10. Keep normalization semantics unchanged after the raw values are corrected.
    - Color Cup continues normalizing each component within sporting color.
    - Type Cup continues normalizing globally across active candidates.
    - Tied components retain the existing tied-normalization behavior.

11. Extend persisted Color/Type Cup selection reports to explain the adjusted inputs.
    At minimum retain/expose:
    - source league name/level or Pool;
    - competition-strength factor;
    - unadjusted source-season championship points;
    - adjusted performance raw;
    - unadjusted final-ten-stage form aggregate;
    - adjusted form raw.
    Version the report payload and keep old report versions readable.

12. Update game rules/technical documentation with the distinction:
    - effective bonus reflects accumulated career advantage;
    - performance/form reflect current results adjusted by current competition strength;
    - the softer league-strength factor deliberately avoids counting tier strength three times at the same severity.

## Architectural direction

- Use league level introduced by the pyramid work, never league-name parsing.
- Keep adjustment in Cup candidate-input calculation. Do not mutate `SeasonStandingEntity` or `StageStandingEntity`; those remain objective records of what occurred in that league.
- Prefer one shared `CupSelectionMetrics`-style pure component builder used by both Cup selection slices.
- Apply the tier factor once to each component. Do not also alter normalization or final 35/30/25/10 weighting.
- Integer truncation must be explicit and tested.

## Acceptance criteria

- [ ] Equal source-season championship points produce Super > F1 > F2 > F3 performance raw at 100/80/60/40% respectively.
- [ ] Recent form uses only the source season's final ten stages.
- [ ] A Pool athlete's current performance and form are both zero even if it had excellent historical stages.
- [ ] Equal final-ten-stage results produce Super > F1 > F2 > F3 form raw at the configured factors.
- [ ] An exceptional lower-tier season can still exceed a sufficiently poor higher-tier season after adjustment; tier is a strength factor, not an absolute eligibility wall.
- [ ] Color Cup and Type Cup use the same raw performance/form calculation.
- [ ] Outer 35/30/25/10 weights and normalization behavior are unchanged.
- [ ] Existing persisted historical Cup selections/reports are not rewritten.
- [ ] New selection reports expose source tier and adjusted/unadjusted performance/form values.
- [ ] New rules snapshots persist and validate the four strength factors.

## Verification

1. Run the full backend suite.
2. Add pure tests for all four league factors and integer truncation.
3. Add synthetic comparison tests:
   - identical raw result across all four levels;
   - much stronger F2 result beating a weak F1 result;
   - much stronger F3 result beating a sufficiently weak F2 result.
4. Add a regression test proving a Pool athlete with old stage history gets current form = 0.
5. Add a regression test proving stages from the prior season do not enter current form.
6. Verify Color Cup per-color normalization and Type Cup global normalization still operate on the adjusted raw values.
7. Verify v1 report/snapshot compatibility.
8. Verify new report payload round-trips with league factor and adjusted/unadjusted values.

## Out of scope

- Career prestige redesign; MSS-065 owns that.
- Changing the 35/30/25/10 outer weights.
- Changing league scoring or championship-point tables.
- Changing bonus-generation multipliers.
- Changing Cup eligibility/team allocation rules.
