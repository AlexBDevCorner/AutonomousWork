# MSS-116 — Sync Chaos Cup reports through existing Google Drive publisher

## Goal

Add Chaos editions as one report category to the existing idempotent Drive history synchronizer.

## Context

- Project `mtgsolosports`, target `AlexBDevCorner/MtgSoloSports` (`main`). .NET + React, direct vertical-slice Endpoint → Handler, no MediatR; follow `AGENTS.md`. Approved Chaos Cup: 8 sporting colors, 1024 entrants (all source-season league athletes plus random Pool invitations), six 32-athlete group stages [32,16,8,4,2,1], top 16 from each nonfinal group; 16 game rounds per group, active bonus used but not earned; no league points/promotion, group scores reset; first draw exactly 4/color/group, later draws pure random. Runs after 32 league stages and before promotion qualifiers, only for a new season after deployment; odd/even Color/Type Cups keep alternating. Existing sporting history must remain unchanged.
- Scope: **Sync Chaos Cup reports through existing Google Drive publisher**. This is a single small PR, target roughly 200–600 changed lines where practical; if work expands materially, propose follow-up rather than bundling unrelated features.
- Dependencies: MSS-091, MSS-114, MSS-115; tasks with incomplete dependencies must wait.

## Requirements

1. Add configurable `Chaos Cup/Cups` destination under user-chosen `mtshistory`, reusing MSS-091 file-ID mapping, adopted files, fingerprints and current OAuth permissions.
2. Manual Sync all changed reports includes completed Chaos dossiers, and opt-in post-finalization publication refreshes relevant edition/dossier/almanac; no uploads inside sporting transactions.
3. Do not create duplicates on retries, overwrite unknown files or publish unrelated athlete archive en masse; mock partial failure and multi-save tests.

## Architectural direction

- Reuse existing feature/simulation/report patterns; keep deterministic integer calculations, save-scoped state and clear compatibility boundaries. Do not introduce MediatR or unrelated refactors.

## Acceptance criteria

- [ ] Repeat sync performs no unnecessary Drive updates; existing Color/Type/Seasons mappings preserved.
- [ ] Drive failure does not block a completed Chaos simulation.

## Verification

`dotnet build MtgSoloSports.slnx --configuration Release` and `dotnet test MtgSoloSports.slnx --configuration Release` from target root. Add focused regression tests for the task's acceptance criteria and validate compatibility with prior editions. 

## Out of scope

- No 2048-athlete bulk upload, OAuth redesign or native Google Docs conversion.
- Do not implement any other task or modify unrelated history/data merely for convenience.
