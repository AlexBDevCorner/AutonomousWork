# MSS-031 — Harden long-running universes and 1,000-season performance

## Goal

Validate that the chosen persistence/projection model remains practical for the hundreds/thousands-of-seasons use case.

## Context

- Project: `mtgsolosports`.
- Target repository: `AlexBDevCorner/MtgSoloSports`.
- Default branch: `main`.
- Product rules: `docs/game-rules.md` in the target repository.
- Technical constraints: `docs/technical-design.md` and `AGENTS.md`.
- Architecture is vertical-slice modular monolith. **MediatR is forbidden.**
- Keep sporting simulation deterministic and use fixed-point integer arithmetic.

## Requirements

1. Add an opt-in benchmark/performance harness that can simulate at least 100 seasons routinely and a 1,000-season stress scenario outside normal CI time limits.
2. Measure runtime, database size, memory behavior, common dashboard/profile/records query latency and historical round replay latency.
3. Add structural invariant/property runs over many seeds and seasons covering league sizes, duplicates, bonus timing, qualifier counts, nationality immutability and Cup rotation.
4. Identify and fix measured bottlenecks that make realistic long saves impractical, while preserving exact sporting results/determinism.
5. Add stable checksums/summaries so refactors can prove long-run deterministic equivalence without asserting gigantic full datasets.
6. Document measured baseline results and any retained limitations.

## Architectural direction

- Optimize from measurements; do not replace the modular monolith/SQLite design without evidence and a separate human-approved architectural task.
