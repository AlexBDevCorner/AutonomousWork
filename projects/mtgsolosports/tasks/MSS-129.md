# MSS-129 - Restart Chaos standings loading after the panel is closed mid-request

## Goal

Restart Chaos standings loading after the panel is closed mid-request while preserving existing save data and unrelated behavior.

## Context

- Project: `mtgsolosports`; target: `AlexBDevCorner/MtgSoloSports`.
- Bug scan on 2026-11-03, audited [main revision 321eb36](https://github.com/AlexBDevCorner/MtgSoloSports/tree/321eb367316252ad259aea6b2fc66cc1ce08b6a1). Line numbers refer to that revision.
- In features/cups/ChaosCupEditionPage.tsx, GroupDetailToggle sets loading=true, aborts its fetch when open changes, and returns from AbortError without clearing loading. Reopening then hits 'if (!open || group || loading) return' at line 544, so no replacement request starts. The panel displays a permanent loading state until remounted. A mounted React reproduction opened Show groups, opened Show standings with a deferred request, closed it, then reopened it. The expected second request never occurred, actual request count 1 versus expected 2. Existing 705 frontend tests pass and do not cover this interaction.

## Potential damage if not fixed

If you close group standings before they finish loading, reopening them can leave a spinner on screen forever. You cannot see that group's standings in the panel until you reload the page or leave and return. This interrupts browsing and can make a working game look broken. It does not change saved results or simulate extra games.

## Requirements

1. Closing a standings panel during its pending request must cancel safely and allow reopening to start a new request.
2. Keep request state scoped to the current group/save/season identity. Aborted or stale requests must not clear or replace a newer request's state.
3. Preserve successful-result caching and visible error/retry behavior, without refetch loops or changing tournament state.
4. Add a mounted deferred-fetch test for open, close before completion, reopen, successful completion and unmount. Cover rapid toggling and ensure cancelled requests cannot populate stale standings.

## Architectural direction

Keep the fix in the existing GroupDetailToggle/useEffect lifecycle around ChaosCupEditionPage.tsx:535-570. Reuse existing API helpers and mounted test conventions in chaosEditionPage.test.ts. Do not introduce a generic fetch/state framework. Follow target AGENTS.md and docs/testing.md; direct vertical slices, deterministic sporting math, no MediatR.

## Acceptance criteria

- [ ] Reopening after cancellation issues a fresh request and exits loading when it resolves.
- [ ] Rapid toggles and stale completions cannot mix groups or leave a permanent spinner.
- [ ] Normal cached standings and error rendering still work.
- [ ] Frontend tests, typecheck and build pass.

## Verification

Run npm test --prefix src/MtgSoloSports.Web, npm run typecheck --prefix src/MtgSoloSports.Web and npm run build --prefix src/MtgSoloSports.Web. Use a deferred promise that rejects with AbortError on signal cancellation; do not use a test that resolves before the panel is closed.
