# MSS-141 - Show promotion, qualification, retention and relegation zones in league standings

## Goal

Make the season standings table readable as a sporting league table: each rank has an understandable, visually distinguishable postseason consequence based on the league tier and that save/season's actual rules. The player should immediately see direct promotion, qualification, safe/retained positions and automatic relegation without memorizing cutoffs.

## Context

- Project `mtgsolosports`; target `AlexBDevCorner/MtgSoloSports`, default branch `main`. Follow `AGENTS.md`, `docs/game-rules.md` (sections 9–12) and the existing dark sports-statistics UI.
- Main view is `src/MtgSoloSports.Web/src/features/standings/StandingsPage.tsx`, season standings (not the stage-placement matrix); the page already loads official league identities, seasons and standings. Keep league and athlete links and current URL-backed league/season selection.
- On normal post-inaugural seasons the ranked bands are:
  - **Superleague:** 1–16 retained/safe; 17–24 Superleague qualifier (defending); 25–32 direct relegation to Feeder 1.
  - **Feeder 1 (each color):** 1 direct Superleague promotion (champion); 2–4 Superleague qualifier (challenging); 5–16 retained in F1; 17–24 F1↔F2 qualifier (defending); 25–32 direct relegation to F2.
  - **Feeder 2 (each color):** 1–8 direct promotion to F1; 9–16 F1↔F2 qualifier (challenging); 17–24 F2↔F3 qualifier (defending); 25–32 direct relegation to F3.
  - **Feeder 3 (each color):** 1–8 direct promotion to F2; 9–16 F2↔F3 qualifier (challenging); 17–32 retained in F3; **no ordinary sporting relegation to Pool**.
- **Season 1 is different:** no Superleague/ordinary Superleague qualifier; the top four of each F1 become inaugural Superleague entrants. The remaining inaugural feeder memberships follow the actual persisted inaugural movement rules. Historical single-tier/v1 saves have compatibility behavior: do not apply today's tier bands unconditionally.
- These are *current-position projections*, not confirmed end-of-season outcomes. A separate successor task MSS-142 introduces mathematically guaranteed/clinch states. Postseason qualifier results and structural rebalancing are distinct from these league-table bands.

## Requirements

1. Derive each row's postseason zone from authoritative league level/kind, season phase/number and applicable persisted rules, **not** display-name parsing, athlete color guesses, static generic rank ranges or a single set of bands for all tiers.
2. Apply the correct post-inaugural bands above to each of the 8 sporting colors in F1/F2/F3 and to Superleague, with clear labels distinguishing automatic promotion, upward qualifier, downward/defending qualifier, retention and automatic relegation. Preserve normal championship rank #1/title treatment within each league.
3. Handle inaugural Season 1 explicitly: only show postseason consequences that its saved rules really allow; never display an ordinary Superleague qualifier, F1↔F2/F2↔F3 qualifiers or automatic demotions where those events do not exist. For legacy/single-tier saves, derive supported consequences from saved rules; if the source cannot reliably express a zone, show neutral/unsupported rather than asserting a false movement.
4. In the season standings table, differentiate bands with restrained row accent/border/background and a compact readable legend/key. Make boundaries easy to scan on a long 32-row table; accessible text and/or icons **must** communicate semantics without color alone. Use a palette that works in the current dark theme, at desktop and phone widths.
5. Zones must follow the athlete's official season **rank**, not the current visual row index or an arbitrary sort order. Preserve score/bonus data, rank, athlete links, current league/season selection, navigation, history and loading/empty states.
6. Distinguish provisional standings from completed-season outcomes in wording: before all stages complete, say “currently in … zone” / “if season ended now”; after completion use final positioning. Qualifier results and any later roster rebalancing are not decided merely by a league placement.
7. Keep this a display/read-model feature: no simulation mutations, saved sporting results changes, new promotion/relegation rules or eager computation of mathematical guarantees (MSS-142).

## Architectural direction

- Prefer a focused typed zone model plus a single source of rank-band definitions, owned by the relevant league/standings slice, shared with the UI through existing read models or a small additive API projection if necessary. Do not duplicate band logic across components. Respect source-season rules and league identity.
- Prefer small modifications to `features/standings/StandingsPage.tsx`, its CSS and nearby tests. Reuse existing table styles, components and color tokens; do not add a UI framework or remodel the site. Where existing read models do not expose sufficient rule/phase metadata, add only additive read-only fields.
- Zone definitions should be reusable by MSS-142; keep that extension simple, without implementing clinching here.

## Acceptance criteria

- [ ] Each normal post-inaugural league (Superleague, F1, F2, F3) displays precisely the rank bands and their direction/target stated in Context, including boundaries 1/2/4/8/9/16/17/24/25/32 as applicable.
- [ ] Season 1 does not display an ordinary qualifier or other nonexistent competitive movement; F1's inaugural 1–4 Superleague slots are described correctly.
- [ ] Legacy save rules do not receive misleading new-format zones.
- [ ] A reader can recognize zone transitions and explain the legend without relying on color alone; narrow screens remain usable.
- [ ] Before the final stage, no row claims its placement is guaranteed. Final standings are labeled final only when officially complete.
- [ ] Existing standings sorting/navigation/links and all sporting values remain unchanged.
- [ ] Focused unit/UI tests cover normal tier bands, Season 1, legacy fallback, boundary ranks and rank-vs-render-order behavior.

## Out of scope

- Mathematical guarantees/early clinches (MSS-142).
- Changes to promotion, relegation, qualification, inaugural formation, competition outcomes, tie-breaks, rebalancing or Pool selection.
- Coloring Stage Placements/matrix cells, Dashboard/Live mini tables, historical replay, Cup tables or a global redesign.
- Predictive probabilities, “likely safe” forecasts, season simulation or future qualifier winners.
