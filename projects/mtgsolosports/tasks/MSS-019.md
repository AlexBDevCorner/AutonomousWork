# MSS-019 — Add fast stage, season and multi-season simulation with equivalence guarantees

## Goal

Allow watching slowly or fast-forwarding while guaranteeing identical sporting outcomes from the same starting state.

## Context

- Project: `mtgsolosports`.
- Target repository: `AlexBDevCorner/MtgSoloSports`.
- Default branch: `main`.
- Product rules: `docs/game-rules.md` in the target repository.
- Technical constraints: `docs/technical-design.md` and `AGENTS.md`.
- Architecture is vertical-slice modular monolith. **MediatR is forbidden.**
- Keep sporting simulation deterministic and use fixed-point integer arithmetic.

## Requirements

1. Add commands/endpoints for completing remaining stage, completing season and simulating an explicit number of seasons.
2. Fast mode must use the same sporting kernel, RNG consumption and state transitions as manual round-by-round progression.
3. Avoid constructing expensive animation DTOs in bulk mode.
4. Commit at safe stage/postseason boundaries so cancellation/failure never exposes partial invalid stage state.
5. Provide progress information suitable for a later UI progress indicator.
6. Add equivalence tests: manual round progression and fast progression from identical snapshot/RNG must end with identical sporting state/checksums.
7. Add reasonable upper request bounds to avoid accidental infinite/huge HTTP operations while preserving hundreds-of-seasons capability.

## Architectural direction

- Do not introduce Quartz, background queues or distributed jobs; this is a local single-user process.
