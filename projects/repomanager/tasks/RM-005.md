# RM-005 — Fix Avalonia startup crash when RepositoryGrid is null

## Goal

Fix the RepoManager startup regression introduced after the Avalonia migration so
the application opens normally instead of throwing a
`System.NullReferenceException` while trying to focus the repository grid.
Preserve the keyboard-first startup behavior: the repository grid should receive
initial focus when the main window is loaded.

## Context

- Project: `repomanager`.
- Target repository: `AlexBDevCorner/RepoManager`.
- RM-004 migrated the application from WPF to Avalonia and is complete.
- The current repository builds successfully, but starting the application
  locally on Windows fails during `MainWindow` startup.
- The observed exception is:
  `System.NullReferenceException: Object reference not set to an instance of an object.`
  Visual Studio reports that `RepositoryGrid` is null.
- The exception occurs in
  `src/RepoDashboard.App/MainWindow.axaml.cs` in the `Loaded` handler:
  ```csharp
  Loaded += (_, _) =>
  {
      Dispatcher.UIThread.Post(() => RepositoryGrid.Focus());
  };
  ```
- `MainWindow.axaml` contains a
  `<DataGrid x:Name="RepositoryGrid" ...>`, so the fix must determine why the
  runtime control reference is not available when the posted focus callback
  runs and use the correct Avalonia control/namescope lifetime pattern.
- Existing `MainWindowXamlTests` only parse the AXAML as XML and verify that
  the `x:Name` attribute exists. That test did not catch the runtime failure.

## Requirements

1. Reproduce and fix the startup failure on the current RepoManager codebase.
   Creating and showing `MainWindow` must not throw because
   `RepositoryGrid` is null.
2. Preserve the current keyboard-first startup requirement: after the window is
   loaded, focus must be moved to the repository `DataGrid` so keyboard
   navigation works even while asynchronous repository loading is still in
   progress.
3. Resolve the control using an Avalonia-supported initialization/namescope
   pattern appropriate for this application. Do not depend on a control
   reference that can remain uninitialized after `AvaloniaXamlLoader.Load(this)`.
4. Do not "fix" the crash only by adding a null-conditional operator or silently
   skipping focus. A missing/miswired `RepositoryGrid` is a programming error
   and must be detectable by regression coverage.
5. Add an automated regression test that exercises actual Avalonia XAML/control
   initialization sufficiently to verify that the main window can resolve its
   repository grid at runtime. A test that only parses the AXAML text/XML is not
   sufficient for this regression.
6. The regression test must fail against the current broken implementation and
   pass after the fix. If Avalonia headless test support is needed, a minimal
   test-only package/reference is allowed; do not add a production dependency
   solely for the test.
7. Keep the existing `x:Name="RepositoryGrid"` contract or replace it with an
   equally explicit and testable control lookup contract. Existing keyboard
   shortcuts and repository-grid behavior must remain unchanged.
8. Keep the change focused on startup/view wiring and its tests. Do not modify
   repository loading, Git operations, persisted data formats, or other
   RM-004 behavior unless directly required to make the startup wiring correct.

## Architectural direction

- Treat this as an Avalonia view wiring/lifetime regression, not a view-model or
  Git-layer problem.
- Prefer resolving the named control during/after `InitializeComponent()` via
  Avalonia's supported control lookup/namescope APIs, storing a non-null
  reference if appropriate, and then using that reference from the `Loaded`
  callback.
- The `Loaded` callback may continue posting focus to
  `Dispatcher.UIThread` if that remains necessary for correct focus timing.
- Keep `MainWindowViewModel` UI-framework-independent.
- Add runtime-oriented coverage alongside the existing lightweight XML contract
  tests rather than replacing useful existing shortcut/XAML tests.
- If a test-only Avalonia headless setup is introduced, keep it narrowly scoped
  to `RepoDashboard.App.Tests`.

## Acceptance criteria

- [ ] Starting RepoManager no longer throws a
      `NullReferenceException` from the `MainWindow` loaded/focus path.
- [ ] `RepositoryGrid` is resolvable after the window's Avalonia XAML has been
      initialized.
- [ ] The repository grid still receives initial focus after the window loads.
- [ ] The fix does not merely suppress the null dereference and skip the focus
      behavior.
- [ ] A runtime-oriented automated regression test covers named-control
      resolution/startup wiring and would catch the current broken behavior.
- [ ] Existing `MainWindowXamlTests` and all other tests continue to pass.
- [ ] No repository-management, Git-safety, persistence, shortcut, or UI feature
      is removed or behaviorally changed as part of the fix.
- [ ] No changes are made under `.github/` or `control/`.

control initialization/resolution rather than only inspecting AXAML text.
