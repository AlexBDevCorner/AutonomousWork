# RM-010 — Add Copy Branch to the main toolbar

## Goal

Make the existing **Copy Branch** action directly available from the main
toolbar, alongside the existing **Copy Path** action, without changing the
underlying clipboard behavior.

## Context

- Project: `repomanager`.
- Target repository: `AlexBDevCorner/RepoManager`.
- RepoManager is an Avalonia desktop application running on Windows and Linux.
- The application already has a `CopyBranchCommand`.
- **Copy Branch** is already available from the repository context menu and via
  the `Ctrl+Shift+B` keyboard shortcut.
- The main toolbar currently exposes **Copy Path** but not **Copy Branch**.

## Requirements

1. Add a **Copy Branch** button to the main toolbar.
2. Place it next to the existing **Copy Path** button so the related utility
   actions remain grouped together.
3. Reuse the existing `CopyBranchCommand`; do not introduce a second clipboard
   implementation or duplicate branch-selection logic.
4. Give the button a tooltip that includes the existing
   `Ctrl+Shift+B` shortcut.
5. Preserve the existing context-menu **Copy Branch** action.
6. Preserve the existing `Ctrl+Shift+B` key binding.
7. Preserve the existing **Copy Path**, **Open Folder**, and **Open Terminal**
   toolbar behavior.
8. The button must follow the existing command enable/disable behavior when no
   valid repository is selected.
9. Keep the change cross-platform and do not add packages.
10. Add focused automated coverage for the toolbar wiring where practical.

## Architectural direction

- Prefer a small AXAML-only change that binds the new toolbar button directly to
  the existing `CopyBranchCommand`.
- Do not add code-behind, services, or view-model logic unless existing behavior
  genuinely requires it.
- Match the style and spacing of the neighboring utility-action buttons.

## Acceptance criteria

- [ ] The main toolbar contains a **Copy Branch** button.
- [ ] The button invokes the existing `CopyBranchCommand`.
- [ ] The tooltip advertises `Ctrl+Shift+B`.
- [ ] Existing context-menu and keyboard Copy Branch actions still work.
- [ ] Existing Copy Path, Open Folder, and Open Terminal actions are unchanged.
- [ ] No duplicate clipboard or branch-selection logic is introduced.
- [ ] Automated tests cover the new toolbar wiring where practical.
- [ ] The full existing test suite passes.

## Verification

Run from the RepoManager repository root:

```bash
dotnet build RepoDashboard.slnx --nologo
```

Expected: build succeeds with no errors.

Run the full test suite:

```bash
dotnet test RepoDashboard.slnx --nologo
```

Expected: all tests pass.

For a manual smoke check:

```bash
dotnet run --project src/RepoDashboard.App/RepoDashboard.App.csproj
```

Expected:

1. The main window opens normally.
2. **Copy Branch** appears next to **Copy Path** in the toolbar.
3. Selecting a repository and clicking **Copy Branch** copies its branch using
   the existing behavior.
4. The context-menu action and `Ctrl+Shift+B` still work.
5. With no valid selection, the action remains unavailable according to the
   existing command state.

## Out of scope

- No changes to clipboard implementation.
- No changes to branch-detection logic.
- No changes to Git inspection, fetch, update, persistence, or ordering.
- No redesign of the toolbar.
- No changes to autonomous workflow files or CI configuration.
- No unrelated refactoring.
