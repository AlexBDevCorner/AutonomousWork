# RM-008 — Show RepoManager application version in the main window title

## Goal

Expose the running RepoManager application version in the main window title so
it is immediately visible which build is being tested or used, without opening
logs or inspecting binaries.

## Context

- Project: `repomanager`.
- Target repository: `AlexBDevCorner/RepoManager`.
- RepoManager is now an Avalonia desktop application.
- During local testing and autonomous development it is useful to identify the
  exact application build from the UI itself.
- Keep this deliberately small and low-risk. It should not change repository
  persistence, Git behavior, autonomous workflows, or deployment behavior.
- RM-007 must complete first so this task is based on the corrected post-Avalonia
  main-window behavior.

## Requirements

1. Display the RepoManager application version in the main window title.
2. Keep the existing product name in the title; append the version in a concise,
   human-readable form such as:
   `RepoManager — 1.2.3`.
3. Read the version from assembly/application metadata at runtime rather than
   hard-coding a version string in the UI.
4. Handle development builds gracefully when the informational version contains
   build metadata or when only an assembly version is available.
5. Do not introduce a new configuration file or persistence setting solely for
   this feature.
6. Keep version-display logic separated from unrelated repository-management
   behavior.
7. Add focused automated coverage for the version formatting/resolution logic.
8. Preserve existing main-window behavior, bindings, repository loading,
   selection, add/remove/rename behavior, keyboard shortcuts, and Git actions.
9. Do not modify autonomous workflow files or CI configuration for this task.

## Architectural direction

- Prefer a small reusable helper/service for resolving and formatting the
  application version rather than embedding reflection/version parsing directly
  into AXAML.
- Use standard .NET assembly metadata such as
  `AssemblyInformationalVersionAttribute` when available, with a sensible
  fallback to the assembly version.
- Keep UI wiring minimal.
- Avoid adding third-party packages for this feature.
- The title should remain stable and readable even for development versions with
  suffixes or build metadata.

## Acceptance criteria

- [ ] The main RepoManager window title still contains `RepoManager`.
- [ ] The running application's version is visible in the title.
- [ ] The displayed version comes from runtime assembly/application metadata and
      is not duplicated as a hard-coded UI constant.
- [ ] Development/informational versions are formatted cleanly and do not make
      the title unreadable.
- [ ] Automated tests cover the version-resolution/formatting behavior.
- [ ] Existing application tests continue to pass.
- [ ] Existing repository-management behavior is unchanged.
- [ ] No changes are made under `.github/` or `control/`.

## Verification

Run from the RepoManager repository root:

```bash
dotnet build RepoDashboard.slnx --nologo
```

Expected: build succeeds with no errors.

Run the full test suite:

```bash
dotnet test RepoDashboard.slnx --nologo
```

Expected: all tests pass, including new focused version-display tests.

For a manual smoke check:

```bash
dotnet run --project src/RepoDashboard.App/RepoDashboard.App.csproj
```

Expected: the main window opens normally and its title contains both the
RepoManager product name and the current application version.

## Out of scope

- No changes to repository persistence or configuration schema.
- No changes to Git fetch/update/safety behavior.
- No redesign of the main window.
- No updater or automatic-update functionality.
- No release/version-bumping automation.
- No changes to GitHub Actions, autonomous worker workflows, or CI runners.
- No unrelated refactoring.
