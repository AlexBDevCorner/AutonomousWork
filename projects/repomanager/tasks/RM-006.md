# RM-006 — Run RepoManager automation and CI on Linux

## Goal

Move RepoManager's GitHub-hosted development automation from Windows runners to
Linux now that the application has been migrated to Avalonia and targets
platform-neutral .NET. The autonomous OpenCode worker and normal CI build/test
job should run on `ubuntu-latest` without Windows-only workflow assumptions.

## Context

- Project: `repomanager`.
- Target repository: `AlexBDevCorner/RepoManager`.
- RM-004 migrated RepoManager from WPF to Avalonia and changed the app/tests to
  platform-neutral `net10.0`.
- The current `.github/workflows/autonomous-worker.yml` still uses
  `runs-on: windows-latest`.
- The current `.github/workflows/ci.yml` also uses
  `runs-on: windows-latest`.
- The autonomous worker currently contains several `pwsh` steps and a prompt
  instruction saying `Use PowerShell for Windows environment variables.`.
  Linux runners may still provide PowerShell, but the workflow must no longer
  rely on Windows-specific environment syntax, paths, tools, or assumptions.
- The OpenCode GitHub action, GitHub CLI, Node, .NET, the control-repository
  validator, and RepoManager's Avalonia build/test flow are expected to be
  usable on Linux.
- Windows application support remains required. Moving CI/automation to Linux
  must not make the product Linux-only.

## Requirements

1. Change the RepoManager autonomous worker job in
   `.github/workflows/autonomous-worker.yml` from `windows-latest` to
   `ubuntu-latest`.
2. Change the RepoManager build/test job in `.github/workflows/ci.yml` from
   `windows-latest` to `ubuntu-latest`.
3. Audit every script and shell fragment in the autonomous-worker workflow and
   make it Linux-safe. It is acceptable to keep `pwsh` where PowerShell is
   genuinely cross-platform, but no step may depend on Windows-only paths,
   executables, environment-variable syntax, or runner behavior.
4. Remove or replace worker prompt/comments that tell the model it is running on
   Windows, including `Use PowerShell for Windows environment variables.`.
   The prompt must accurately describe the Linux runner and should prefer
   platform-appropriate shell/environment syntax.
5. Preserve all existing autonomous-worker safety behavior:
   - dispatch-input validation;
   - pinned control checkout;
   - validator build and control SHA recording;
   - authorization guard;
   - GitHub App token minting;
   - explicit `gh` authentication validation;
   - Git credential wiring without exposing credentials;
   - OpenCode permission restrictions;
   - branch/PR/checkpoint behavior;
   - implementation/correction modes.
6. Preserve the existing runner toolchain requirements: .NET 8 for the control
   tooling, .NET 10 for RepoManager, Node 22, GitHub CLI, Git, and the pinned
   OpenCode action.
7. Keep normal RepoManager CI semantically equivalent: checkout, restore, Release
   build, Release tests, and test-result artifact upload must continue to run.
8. Ensure the Linux CI run validates the Avalonia/.NET solution without adding
   a fake Windows compatibility layer or switching the app back to a
   Windows-targeted TFM.
9. Do not remove Windows product support. Existing Windows publish/runtime
   documentation and cross-platform application behavior must remain valid.
10. Keep the change focused on runner/shell portability. Do not change
    RepoManager application behavior, Git logic, task-control semantics, or
    unrelated deployment/release processes.

## Architectural direction

- Prefer Linux-native workflow behavior rather than emulating a Windows runner.
- Keep shell changes minimal. Cross-platform PowerShell is allowed where it
  remains clear and robust; Bash is preferred where a step is naturally
  POSIX-oriented.
- Preserve the current GitHub App authentication design and OpenCode action pin.
- Do not weaken `OPENCODE_CONFIG_CONTENT` restrictions while adapting path or
  shell assumptions.
- The workflow should continue to use GitHub-hosted runners; this task does not
  introduce self-hosted infrastructure.

## Acceptance criteria

- [ ] RepoManager `autonomous-worker.yml` uses `ubuntu-latest`.
- [ ] RepoManager `ci.yml` uses `ubuntu-latest`.
- [ ] No active workflow instruction assumes the worker is a Windows runner.
- [ ] Autonomous-worker validation, control checkout, authorization guard,
      GitHub App auth, Git credential setup, and OpenCode execution remain
      present and Linux-compatible.
- [ ] Normal CI still restores, builds, tests, and uploads test results.
- [ ] `dotnet build RepoDashboard.slnx` succeeds on Linux.
- [ ] `dotnet test RepoDashboard.slnx` succeeds on Linux.
- [ ] RepoManager remains a Windows + Linux Avalonia application; no
      Windows-only target framework is reintroduced.
- [ ] No unrelated product behavior is changed.

## Verification

Run from the RepoManager repository root:

```bash
dotnet restore RepoDashboard.slnx
dotnet build RepoDashboard.slnx -c Release --no-restore --nologo
dotnet test RepoDashboard.slnx -c Release --no-build --nologo
```

Expected: all commands succeed on Linux.

Inspect the workflow definitions and confirm:

```text
.github/workflows/autonomous-worker.yml -> runs-on: ubuntu-latest
.github/workflows/ci.yml                -> runs-on: ubuntu-latest
```

The pull-request CI triggered by this change must run its build/test job on an
Ubuntu GitHub-hosted runner and pass.

After merge, the next autonomous RepoManager task dispatch must start its worker
job on an Ubuntu GitHub-hosted runner and reach the OpenCode action without a
Windows-specific shell/path failure.

## Out of scope

- No application feature changes.
- No redesign of the autonomous-control protocol.
- No self-hosted runner setup.
- No changes to AutonomousWork itself.
- No removal of Windows application support.
- No installer/package-manager work.
