# RM-002 — Define RepoManager task backlog slice

## Goal

Define the next executable slice of work for `AlexBDevCorner/RepoManager`
once RM-001 (bootstrap wiring) is done.

## Context

- Project: `repomanager`.
- Depends on `RM-001` being `done`; not eligible for execution before that,
  even though its own status is `ready`.
- Demonstrates ordered execution via `depends_on` and priority sorting
  (`100` before `90` when both are otherwise eligible).

## Requirements

1. Inspect open issues and TODOs in `AlexBDevCorner/RepoManager`.
2. Propose 1–3 follow-up tasks (RM-003+) with IDs, priorities, and
   dependencies.
3. Open each follow-up as `projects/repomanager/tasks/RM-*.md` with
   `status: draft` first; promote to `ready` only when goal plus acceptance
   criteria are complete (Human role).

Follow the template in `templates/task.md` for every new task file,
including an explicit `Out of scope` section. Keep each proposed task small
enough for a single OpenCode session and a single PR.

## Acceptance criteria

- [ ] `RM-001` is `done` before this task starts (enforced via `depends_on`).
- [ ] Follow-up task files use unique IDs and machine-readable `priority`.
- [ ] This task moves to `review` with a summary of proposed tasks.
