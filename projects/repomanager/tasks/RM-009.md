# RM-009 — Open repository folder on row double-click

## Goal

Make the repository dashboard faster to use by allowing the user to open a
repository folder by double-clicking its row, while reusing the existing
Open Folder behavior and preserving all current keyboard/context-menu actions.

## Context

- Project: `repomanager`.
- Target repository: `AlexBDevCorner/RepoManager`.
- RepoManager is an Avalonia desktop application running on Windows and Linux.
- The application already exposes an `OpenFolderCommand`, an
  `IFolderLauncher` abstraction, an **Open Folder** toolbar/context-menu action,
  and the `Enter` keyboard shortcut.
- A double-click should be only another UI gesture for that existing action; it
  must not introduce a separate folder-launching implementation.

## Requirements

1. Double-clicking a repository row opens that repository's folder.
2. Reuse the existing `OpenFolderCommand` / folder-launcher path instead of
   introducing a second folder-opening code path.
3. The row that was double-clicked must be the repository that is opened.
4. A double-click outside a repository row, or when there is no valid
   repository target, must do nothing and must not throw.
5. Preserve normal single-click selection behavior.
6. Preserve the existing **Open Folder** toolbar action, context-menu action,
   and `Enter` shortcut.
7. Do not change Git inspection, fetch, update, persistence, or repository
   ordering behavior.
8. Keep the implementation cross-platform; do not add Windows-only or
   Linux-only UI behavior.
9. Add focused automated coverage for the new gesture/command wiring where
   practical.
10. Do not modify autonomous workflow files or CI configuration for this task.

## Architectural direction

- Prefer Avalonia command/event wiring that delegates to the existing
  `OpenFolderCommand`.
- Avoid duplicating path validation or launcher behavior already owned by the
  existing view model/service.
- Keep code-behind minimal. If code-behind is needed to identify the clicked
  row, it should only translate the pointer gesture into the existing command.
- Avoid adding third-party packages.

## Acceptance criteria

- [ ] Double-clicking a repository row opens that repository folder.
- [ ] The existing folder-launching service/command path is reused.
- [ ] Double-clicking empty grid space does not open a repository and does not
      throw.
- [ ] Single-click row selection still works normally.
- [ ] Existing toolbar, context-menu, and keyboard Open Folder actions still
      work.
- [ ] Existing Git/repository-management behavior is unchanged.
- [ ] Automated tests cover the new behavior or its command wiring.
- [ ] The full existing test suite passes.
- [ ] No changes are made under `.github/` or `control/`.

## Verification

Run from the RepoManager repository root:

```bash
dotnet build RepoDashboard.slnx --nologo
```

Expected: build succeeds with no errors.

Run the full test suite:

```bash
dotnet test RepoDashboard.slnx --nologo
```

Expected: all tests pass, including focused tests for the new double-click
behavior.

For a manual smoke check:

```bash
dotnet run --project src/RepoDashboard.App/RepoDashboard.App.csproj
```

Expected:

1. The main window opens normally.
2. Double-clicking a repository row opens that repository folder.
3. Single-clicking still only selects the row.
4. Double-clicking empty grid space does nothing.
5. The toolbar/context-menu/Enter Open Folder actions still behave as before.

## Out of scope

- No changes to repository persistence or configuration schema.
- No changes to Git fetch/update/safety behavior.
- No new file-manager integration beyond the existing folder launcher.
- No redesign of the repository grid.
- No changes to autonomous worker workflows or CI runners.
- No unrelated refactoring.
