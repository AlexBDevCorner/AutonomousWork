# RM-001 — Pilot the autonomous worker end to end

## Goal

Prove the manually dispatched worker chain works: a human dispatches this
task, OpenCode implements it in `AlexBDevCorner/RepoManager`, and the run
ends with exactly one PR that satisfies the autonomous PR contract.

## Context

- Project: `repomanager` (`projects/repomanager/project.yaml`).
- Target repo: `AlexBDevCorner/RepoManager`.
- Worker: `.github/workflows/autonomous-worker.yml` in the target repo
  (AutonomousWork steps 8–10). There is no Dispatcher (step 11) and no
  Reconciler (step 12) yet: dispatch is manual and the task stays `ready`
  in this pilot (it is marked `done` by the human only after the pilot PR
  is produced and reviewed). This task tests worker integration only, not
  the lifecycle.

## Requirements

1. Create `docs/autonomous-runs/RM-001.md` in the target repository
   recording the baseline `master` build/test result (exact commands and
   their real output) plus the pinned control spec of this run.
2. Confirm `projects/repomanager/project.yaml` references exactly
   `AlexBDevCorner/RepoManager` and no other repository; record the
   outcome in the report from item 1.
3. Do all work on branch `autonomous/RM-001` from `master` and open exactly
   one PR to `master` satisfying the autonomous PR contract (title
   `[RM-001] …`, labels `autonomous` / `autonomous:opencode` /
   `task:RM-001`, body sections Task / Control specification /
   Implementation / Verification / Autonomous execution).

## Architectural direction

MUST NOT change any `projects/` definition files as part of this task —
this task only observes and reports. This is a docs-only change in the
target repo: MUST NOT touch `src/`, `tests/`, `.github/`, or any
application code. Record findings in the report file and the PR
description; keep this control repo untouched.

## Acceptance criteria

- [ ] Branch `autonomous/RM-001` exists with `docs/autonomous-runs/RM-001.md`
  containing the baseline build/test result and the pinned control spec.
- [ ] Exactly one open PR to `master` from that branch with title starting
  `[RM-001]`, labels `autonomous`, `autonomous:opencode`, `task:RM-001`,
  and all five PR body sections present.
- [ ] `## Verification` in the PR quotes the real `dotnet build` /
  `dotnet test` commands and outputs — no invented results.

## Verification

Dispatch manually (Actions tab or CLI):

```powershell
gh workflow run autonomous-worker.yml `
  --repo AlexBDevCorner/RepoManager `
  -f task_id=RM-001 `
  -f task_path=projects/repomanager/tasks/RM-001.md
```

Expected: the run succeeds; branch `autonomous/RM-001` and one PR as
described above appear without human coding. Do NOT simulate
Dispatcher/Reconciler transitions in this pilot: RM-001 stays `ready`
while the worker is tested (the worker's eligibility gate requires `next`
to still select it — marking it `in_progress` would reject the run and
break retries). After the pilot PR is produced and reviewed, the human
manually marks RM-001 `done`, which makes RM-002 eligible. Real claim
transitions arrive with the Dispatcher (step 11) and Reconciler (step 12).

## Out of scope

- No application code changes in `AlexBDevCorner/RepoManager` (docs-only pilot).
- No Dispatcher, Reconciler, or automatic status transitions.
- No new tasks in this control repo (follow-ups belong to RM-002).
- No changes to priorities, dependencies, or other projects.
