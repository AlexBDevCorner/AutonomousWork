# RM-011 — Establish deterministic .NET build, package, style, and analyzer guardrails

## Goal

Give RepoManager the same kind of deterministic repository-wide .NET quality
foundation already used successfully in MandarinBotNet, so autonomous OpenCode
changes fail early on package inconsistency, compiler/analyzer problems, and
formatting drift instead of relying on the PR reviewer to catch everything.

Centralize repeated project configuration and package versions while keeping the
rules conservative enough for practical unattended development.

## Context

- Project: `repomanager`.
- Target repository: `AlexBDevCorner/RepoManager`.
- Default target branch: `master`.
- RepoManager is a .NET 10 Avalonia desktop application with multiple production
  and test projects.
- Individual project files currently repeat settings such as `net10.0`,
  nullable reference types, implicit usings, and many identical package
  versions.
- The repository currently has no root `Directory.Build.props`,
  `Directory.Packages.props`, or `.editorconfig`.
- Current CI restores, builds, and tests, but does not enforce a repository-wide
  formatting check or a centrally pinned analyzer policy.
- The autonomous worker and reviewer are most reliable when mechanical rules are
  enforced by the build before human/AI judgment is required.

## Requirements

1. Add a root `Directory.Build.props` and centralize common project-level
   settings that genuinely apply across RepoManager, including:
   - `TargetFramework` = `net10.0`;
   - nullable reference types enabled;
   - implicit usings enabled;
   - .NET analyzers enabled;
   - code-style enforcement during build;
   - `TreatWarningsAsErrors`;
   - a pinned numeric .NET analysis level appropriate for .NET 10;
   - `ContinuousIntegrationBuild` when running in CI.
2. Remove the now-redundant common settings from individual `.csproj` files,
   while retaining project-specific properties such as `OutputType`,
   `IsPackable`, Avalonia settings, and test-specific configuration.
3. Add `Directory.Packages.props` with Central Package Management enabled and
   move all existing NuGet package versions out of individual project files.
4. Do not upgrade unrelated application/test packages as part of the
   centralization. Preserve the versions already used by RepoManager unless a
   new analyzer package itself requires a compatible version choice.
5. Add a root `.editorconfig` that establishes deterministic basic formatting
   and C# style conventions without imposing a large subjective rule set.
6. Add a conservative general-purpose C# analyzer package suitable for .NET 10.
   Prefer `Meziantou.Analyzer` unless repository constraints discovered during
   implementation make another focused analyzer clearly more appropriate.
7. Add/enable xUnit-specific analyzers for the test projects.
8. Analyzer packages must be development-only dependencies and must not flow as
   runtime/transitive application dependencies.
9. Keep analyzer enforcement practical:
   - fix straightforward existing violations when the fix is clearly
     behavior-preserving;
   - explicitly configure noisy or unsuitable rules instead of performing broad
     unrelated refactors;
   - do not use blanket `NoWarn` or disable the analyzer package wholesale.
10. Add deterministic package lock files and configure CI to restore in locked
    mode so an autonomous PR cannot silently resolve a different dependency
    graph.
11. Extend CI to run a formatting verification step using
    `dotnet format RepoDashboard.slnx --verify-no-changes --no-restore`.
12. Preserve the current Linux CI runner and the existing full build/test suite.
13. Update `AGENTS.md` so autonomous workers run the same restore/build/test/
    format verification expected by CI. Keep the prose concise and treat the
    build configuration as the source of truth rather than duplicating analyzer
    rules in instructions.

## Architectural direction

Use repository-wide MSBuild features rather than copying configuration into each
project.

The desired validation flow is:

`OpenCode implementation -> locked restore -> compiler/analyzers -> tests -> format -> PR reviewer`

Central Package Management should leave package references in project files but
remove their `Version` attributes. Versions belong in
`Directory.Packages.props`.

For analyzer-only packages, use `PrivateAssets="all"` and appropriate
`IncludeAssets` metadata where needed.

Prefer a pinned numeric `AnalysisLevel` rather than `latest`, so updating the
SDK cannot silently change the Microsoft analyzer baseline.

Do not introduce architectural patterns or abstractions merely to satisfy
analyzer suggestions. RepoManager's existing architectural rules in
`AGENTS.md` remain authoritative.

## Acceptance criteria

- [ ] Root `Directory.Build.props` exists and common .NET project settings are
      no longer duplicated across project files.
- [ ] Warnings, including enabled analyzer warnings, fail the normal build.
- [ ] The Microsoft analyzer baseline uses a pinned numeric analysis level.
- [ ] Root `Directory.Packages.props` exists with Central Package Management
      enabled.
- [ ] Existing package versions are centralized without unrelated upgrades.
- [ ] Individual `PackageReference` entries no longer repeat centrally managed
      version numbers.
- [ ] Root `.editorconfig` exists and supplies deterministic baseline
      formatting/style settings.
- [ ] A focused general-purpose analyzer is active for production code.
- [ ] xUnit analyzer diagnostics are active for test projects.
- [ ] Analyzer dependencies do not flow as runtime/transitive application
      dependencies.
- [ ] Existing code is green under the new analyzer configuration without broad
      suppressions or unrelated cleanup.
- [ ] Package lock files are committed and CI restore uses locked mode.
- [ ] CI verifies formatting with `dotnet format --verify-no-changes`.
- [ ] `AGENTS.md` verification instructions match the CI quality gates.
- [ ] The complete restore/build/test/format sequence succeeds on Linux.

## Verification

Run from the RepoManager repository root:

```bash
dotnet restore RepoDashboard.slnx --locked-mode
dotnet build RepoDashboard.slnx --configuration Release --no-restore
dotnet test RepoDashboard.slnx --configuration Release --no-build --no-restore
dotnet format RepoDashboard.slnx --verify-no-changes --no-restore
```

Verify that CI executes the equivalent commands on `ubuntu-latest`.

Also inspect the resulting package/project assets to confirm analyzer packages
are analyzer/development assets and are not runtime dependencies of the Avalonia
application.

## Out of scope

- Upgrading Avalonia, Microsoft.Extensions, xUnit, FluentAssertions, or other
  existing packages merely because newer versions exist.
- Adding SonarQube, Qodana, CodeRabbit, or another hosted quality platform.
- Adding every available analyzer or a large subjective clean-code ruleset.
- Reworking RepoManager architecture, MVVM design, Git integration, persistence,
  or UI behavior.
- Changing the autonomous dispatcher/reviewer design.
- Adding Windows-only validation; CI remains Linux-based.
- Bulk refactoring unrelated code solely to satisfy low-value analyzer advice.
